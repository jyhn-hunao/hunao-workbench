> 一个 AI 面板 = 一条独立会话 = 一个岗位。岗位之间不共享上下文，只通过**工单**（派发）与**回执**（结论）交接，

| # | 阶段 | 谁做 | 产物 | 门（谁放行） |

| 3 | 原画 | 原画概念 | `资产\<资产>\ref\`：三视图、气氛图、材质局部稿 + 说明 | **美术指导审**（造型/配色/比例） |

| 5 | 低模/拓扑 | 低模拓扑 | `资产\<资产>\<资产>_lo_v1.blend` + 资产清单（命名/面数/原点/单位） | **技美预检**（命名/面数/负缩放/非流形） |
| 6 | UV/贴图 | UV贴图 | `资产\<资产>\<资产>_uv_v1.blend` + `资产\<资产>\tex\`（≤2K） | **技美预检**（UV 重叠/丢贴图/尺寸） |
| 7 | 材质灯光 | 材质灯光 | `_look_v1.blend` + `资产\<资产>\render\test\960x540_*.png` | **导演审 test 图** |
| 8 | 终渲 | 材质灯光 | `资产\<资产>\render\final\<资产>_<宽>x<高>.png` | 导演验图（构图/曝光/噪点） |
| 9 | 绑定/特效（按需） | 绑定动画 / 特效合成 | `_rig_v1.blend` / `资产\<资产>\render\comp\*` | 需要动画或合成才开单；技美验通道完整性 |
| 10 | 质检导出 | 技美质检 | `资产\<资产>\export\<资产>.glb` + `资产\<资产>\render\qc\<资产>_qc.md` | **QC 通过才交付**；不通过按问题归属退回 |

**参考图入口（2026-11-13）**：用户只丢一张参考图时——导演把它存到 `资产\<资产>\ref\<资产>-ref.png`，把路径与"照这张的造型/配色/比例"写进 brief；
原画岗以该图为第一依据出三视图（**生图默认 Seedream**：`node 工具\生图.mjs gen --ref "<该图>" …`，默认模型 `doubao-seedream-4-5-251128`），美术指导审图时对照它。⛔ 不把聊天里的图当唯一来源（聊天会滚走，文件不会）。

**返工归属**：造型/比例 → 原画或高模；布线/面数/命名 → 低模；UV/贴图 → UV贴图；材质/曝光/构图 → 材质灯光；骨骼权重 → 绑定；导出异常 → 质检自查。

## 三、工单与回执（唯一交接方式）

- 工单：`工作区\创意工坊\工单\G-<YYYYMMDD>-<序号>-<岗位>-<资产>.md`，模板见 `创意工坊\工单模板.md`，状态写文件头（排队/进行中/待验/返工/已交付）。
- 派工（导演）：

```powershell
node 12-源码照搬\工具\派发.mjs --to "创意工坊·高模雕刻" --file "12-源码照搬\工作区\创意工坊\工单\G-20261113-02-高模-木箱.md" --timeout 1800
```

- 回执（收单方干完照抄派发消息里附的命令）：

```powershell

```

- 台账：`12-源码照搬\引擎数据\.dsh\派发\回执日志.md`。

## 四、并发、锁与版本

1. **Blender 单实例**：实时 `exec` 只有一条通道，同一时刻只许一个岗位占用；导演在工单写"占用时段"。
2. **串行链**：同一资产的高模 → 低模 → UV 必须串行（后一环读前一环产物），⛔ 不许并行改同一个 `.blend`。
3. **后台可并行**：`run --background` 可并行（不同资产），但同一 `.blend` 不许两个进程同时写。
4. **版本不覆盖**：`_hi_v1 → _lo_v1 → _uv_v1 → _look_v1`，每次交付新建版本；覆盖同名文件需工单批准。
5. **命名唯一**：`SM_` / `ENV_` / `MAT_` / `TEX_`；跨岗位不许改名。

## 六、交付标准（十岗统一，数值可被工单覆盖）

> 这一节是"工作要求"的量化口径；各岗位卡只写工序，标准以这里为准。工单要放宽/收紧就在工单里写明，⛔ 不许口头放宽。

### 6.1 通用

| 项 | 标准 |
|---|---|
| 单位 / 朝向 | 米制；+Y 向上、-Y 向前（Blender 默认）；导出前 `scale` 应用为 1 |
| 命名 | 对象 `SM_<资产>_<部件>` / `ENV_<资产>_<部件>`；材质 `MAT_`；贴图 `TEX_`；跨岗不许改名 |
| 版本 | `_hi_v1 → _lo_v1 → _uv_v1 → _look_v1 → _rig_v1`，只增不覆盖；覆盖需工单批准 |
| 文件 | 产物只落 `工作区\创意工坊\` 对应子目录；脚本放 `_脚本\`（文件名带日期）；⛔ 盘根/桌面/临时目录 |
| 脚本 | 主流程 `# 1. xxx` 中文编号注释；失败就失败（`--python-exit-code 1`），⛔ 不全吞异常 |

### 6.2 各岗量化阈值

| 岗位 | 量化要求 |
|---|---|
| 美术指导 | `art.md` 必含：主/辅/点缀三色（十六进制）、比例尺、镜头参数、材质区间、参考板 3–5 条；审图结论必须逐项列"通过/偏差"，不许只写"感觉不错" |
| 原画/概念 | 三视图各 ≥1 张（长边 ≥1024 px）、气氛图 1 张、关键材质局部 1–2 张；同一方案先出 2–3 版再定稿 |
| 高模雕刻 | 面数不设上限但必须报；包围盒与 brief 尺寸误差 ≤ 2%；位移/毛发只算雏形，须在回执标注 |
| 低模/拓扑 | 三角面预算：实时/主机 ≤ 5 万，移动端 ≤ 1.5 万，影视/离线 ≤ 20 万；非流形边 = 0；负缩放 = 0；重名对象 = 0；孤立顶点 = 0；N 边形 ≤ 5 个且逐个标注 |
| UV/贴图 | UV 全部在 0–1、重叠面积 = 0（镜像 UV 须在回执标注并说明）；texel density 同资产偏差 ≤ 20%；贴图单张 ≤ 2K（移动端 ≤ 1K）；烘焙 margin ≥ 8 px；丢贴图 = 0 |
| 材质/灯光 | 材质全部 Principled BSDF；测试渲 960×540 / 32 spp；终渲默认 1920×1080 / 64 spp（brief 另有要求以 brief 为准）；必须写明引擎（Cycles / EEVEE）与渲染耗时 |
| 绑定/动画 | 默认 30 fps；循环动作首尾帧姿态一致；极限姿势测试通过（塌陷/穿插 = 0）；骨骼命名 `BONE_<部位>`；**角色/生物类必绑**（交付带 skin 的 GLB），纯道具可豁免但须在 brief 写明「不做可操作资产」；骨架默认用 Rigify 生成（见 6.5） |
| 特效/合成 | 合成需要通道时 AO / Depth / Alpha / ObjectID 齐全；缺任一通道即不通过；特效只做在 `_fx_*` 副本上 |
| 技美/质检 | 通过线：命名全合规、面数 ≤ 预算、非流形 = 0、负缩放 = 0、丢贴图 = 0、UV 重叠 = 0、贴图 ≤ 2K、GLB 回读四项（对象数/三角数/材质数/贴图数）与源一致；任一不过即"不通过" |

### 6.4 建模从基座改，不从零捏（2026-11-13 起）

- **起点顺序**：`工作区\创意工坊\_基座\` 的 base mesh → Blender 官方 Human Base Meshes（CC0）→ 都没有才允许从 blockout 起，且 brief 必须标「无基座，造型品质受限」。
- 岗位动作是**改造**不是造人：对齐比例（拉/压、骨骼对位）、换头/换手、加装备、保持四边面拓扑与对称；⛔ 不推倒重来。
- 回执必须报：基座来源（文件路径 + 许可）、改动清单（比例/部件/删改面数）、面数与包围盒误差（≤2%）。

### 6.5 骨架用 Rigify（2026-11-13 实测可用）

脚本化流程（后台 `run` 通道可跑，不用人点）：

```
bpy.ops.preferences.addon_enable(module="rigify")      # 4.x 自带
bpy.ops.object.armature_human_metarig_add()            # 生成 metarig（159 骨）
bpy.ops.object.mode_set(mode='POSE'); bpy.ops.pose.rigify_generate()
# 网格 + rig → parent_set(type='ARMATURE_AUTO') → 自动权重
bpy.ops.export_scene.gltf(..., export_skins=True, export_def_bones=True)
```

实测数据（4.5.16 LTS 便携版）：metarig 159 骨 → 生成 rig **706 骨 / 160 根 DEF 变形骨**、自动权重 160 个顶点组；GLB `skins=1 / joints=160`；动 IK 手柄（`hand_ik.*`）与 FK 骨（`thigh_fk.L`）后顶点最大位移 **0.34 m**。

- **验收姿势要动 IK 手柄或 FK 骨**：Rigify 手臂/腿默认 IK，转 `upper_arm.*` 这类控制骨网格不动（实测位移 0.00 m），拿它做验收会假通过。
- **导出只导变形骨**：`export_def_bones=True`，控制器骨不进引擎（否则节点数翻倍、引擎里全是没用的骨）。
- **目标引擎是 Unity Humanoid 时**加一步骨名映射：`DEF-spine→Hips`、`DEF-upper_arm.L→LeftUpperArm` 等，映射表写进 `资产\<资产>\qc\bone_map.md`。
- 角色/生物资产**必绑**；纯道具豁免要 brief 写明。

### 6.6 三件验证（不过不算交付；2026-11-13 起）

1. **UV + 贴图**：`bpy.ops.uv.smart_project`（或手工分区）展开 → 烘焙到 `资产\<资产>\tex\` → 材质回写 → 丢贴图检查 = 0；texel 偏差 ≤20%。
2. **QC 脚本**：以 `工作区\创意工坊\_脚本\模板-质检.py` 输出为准，逐项报：非流形边、孤立顶点、负缩放、N 边形、每顶点权重数（≤4）、UV 范围与岛数、贴图尺寸、骨骼数、GLB joints。
3. **端到端**：参考图 → 概念 → 建模 → UV/贴图 → 绑定 → 导出，**至少整条跑过一次并留产物**；跑完 `node 工具\资产.mjs check --name "<资产名>"` 必须是「齐了」。
