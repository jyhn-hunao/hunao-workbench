# 资产规范（创意工坊 · 一次一个资产，一个资产一个包）

> 用户口径（2026-11-13）：**交付的所有材料都放工作目录里，按工程名称管理**——今天要做「木箱」就建一个「木箱」目录，模型/贴图/渲染/导出全放里面；下次做新模型再建新目录。
> 本文是目录与命名的唯一口径；岗位技能只写工序，落哪一层以此为准。

## 一、包结构（固定，不许各建各的）

```
12-源码照搬\工作区\创意工坊\资产\<资产名>\
├─ 资产.json        元信息：name / prefix / created / stage / engine / budget / ref
├─ brief.md         工单：需求、参考图说明、验收清单、进度表
├─ ref\             参考图、三视图、气氛图、材质局部稿（原画岗写）
├─ tex\             贴图 TEX_<前缀>_<部位>.png（≤2K）
├─ render\
│  ├─ test\         测试渲 960×540 / 32spp
│  ├─ final\        终渲 1920×1080 / 64spp
│  └─ qc\           质检用图
├─ export\          *.glb / *.fbx（**可操作资产必须带 skin**）
├─ qc\              质检报告 <资产>_qc.md
├─ scripts\         该资产专用 bpy 脚本（通用脚本仍放 工作区\_脚本）
└─ <前缀>_hi_v001.blend / _lo_ / _uv_ / _rig_    版本只增不覆盖（v002、v003…）
```

`<前缀>` = `SM_` + 资产 id（如 `SM_Box`、`SM_Char`），在 `资产.json` 的 `prefix` 里定，建包时定死，跨岗位不改名。

## 二、一条命令建包（别手搓目录）

```
node 工具\资产.mjs new --name "木箱" --id "Box" --note "倒角木箱 0.8 m，木色 PBR"
node 工具\资产.mjs new --name "角色-铁匠" --id "Smith" --ref "<用户丢的参考图路径>"
node 工具\资产.mjs list                        # 现有资产包：名称 / 阶段 / 最新 .blend / 时间
node 工具\资产.mjs check --name "木箱"          # 缺什么：建模 / UV / 绑定 / 导出 / 参考图 / GLB 有没有 skin
node 工具\资产.mjs stage --name "木箱" --set "绑定"
node 工具\资产.mjs path --name "木箱"           # 打印绝对路径，给脚本/派工引用
```

- `--ref` 给本地图路径：建包时直接拷进 `ref\`，**别让参考图留在剪贴板临时目录**（会被清）。
- 同名包已存在就报错退出：要新版本在同一个包里加 `_v002`，**不要新建同名目录**（否则一个资产两处，谁也说不清哪个是准的）。

## 三、谁写哪一层

| 岗位 | 只写 |
|---|---|
| 原画概念 | `ref\`（三视图/气氛/材质稿 + 说明.md） |
| 建模 / 高模 | 包根 `<前缀>_hi_v*.blend`、`_lo_v*.blend` |
| UV 贴图 | `_uv_v*.blend` + `tex\` |
| 绑定 | `_rig_v*.blend`（**不许动网格顶点**） |
| 质检导出 | `export\` + `qc\` |
| 导演/调度 | `brief.md`、`工单\G-*.md`；⛔ 不进别人的 .blend |

## 四、交付判定（`资产.mjs check` 的口径）

齐包 = 有 `_lo_v*` + `_uv_v*` + `_rig_v*` + `export\*.glb`（**skins ≥ 1**）+ `ref\*.png`。
少一项就报 ✗，退出码 1——**别用嘴说"做完了"，跑 check**。

## 五、旧结构（2026-11-13 之前的扁平目录）

`工程\ 概念\ 贴图\ 输出\ 导出\` 是"按文件类型"分的，多个资产混在一起，已停止新增。
里面现存的文件是历史验证产物，**不删、不搬**（资产包里已复制归档）；以后新资产一律进 `资产\<资产名>\`。
