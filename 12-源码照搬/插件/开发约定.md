# 插件开发约定（12-源码照搬\插件\）

> 目的是**别让后来人（或 AI）乱放**：一个插件一个目录，落点、命名、装法、登记方式都只有一种。
> 判据由机器兜着：`node 12-源码照搬\外壳\scripts\engine-after.mjs` 会核对"装了没 / 登记了没"。

## 1. 目录与文件

```
插件\<中文目录名>\
├─ package.json      必填：name = 引擎认的包名（dsh-xxx），main 指向 index.js
├─ index.js          必填：export const name / export function apply(ctx) …
├─ cordis.patch.yml  可选：本插件自带的登记片段（写法见 §3）
└─ 说明.md / 自检.mjs  可选：人能读的说明；能单测的就写一份自检
```

- 目录名用**中文**（`省token守卫`、`记忆回响`），包名用 `dsh-<英文>`；两者不要互相套。
- 只有说明、没有 `package.json` 的目录（如 `社交通道\`）属于"只读调研"，不算插件——
  `engine-after.mjs` 会以 `!` 提醒，不进 FAIL。
- ⛔ 不要往引擎目录（`12-源码照搬\引擎\`）里放插件；引擎是外部依赖，升级等于整目录替换。

## 2. 装到哪

插件**不装进 `引擎\node_modules`**，而是装进 web profile 的 `node_modules`：

```
引擎数据\.dsh\profiles\web\node_modules\<包名>\
```

装法两种，任选其一并写进插件的 `说明.md`：
1. 有安装工具（如 `工具\记忆回响.mjs --apply`）：工具负责复制 + 登记 + 重启提示；
2. 没有工具：手动复制目录，再按 §3 在 `profiles\web\cordis.patch.yml` 登记。

## 3. 登记写法（最容易踩的一条）

`引擎数据\.dsh\profiles\web\cordis.patch.yml` 里**只能写 `- insert:` 块**：

```yaml
- insert:
    - id: token-guard
      name: dsh-token-guard
```

- ⛔ 顶层裸写 `- id: xxx` 会被引擎判成「找不到这个条目」并**静默丢掉**（2026-11-14 实测三条工具就是这么没挂上的）。
- 写完必须验：`node 引擎\lib\bin.js web --dump-config | Select-String 'not found'` 应为 **0 行**。
- 关掉一个插件 = 从 patch 里删掉它的 name（不是删 `node_modules`）；开关型插件请提供 `--on` / `--off` 工具。

## 4. 自检

- 插件自带 `自检.mjs` 的，写清「跑什么、期望什么」，退出码 0 = 过。
- 整体接线核对：`node 12-源码照搬\外壳\scripts\engine-after.mjs`（✓ 生效 / ! 装了没登记或没装 / ✗ 登记了却没装）。
- 改完插件要**重启整壳**（引擎由壳拉起，⛔ 不在壳外重启引擎）。
