# 记忆回响（dsh-memory-recall）

DSH 引擎插件：**每轮用户发言前**，把本场景的记忆注入成一条上下文，解决「记忆只在换会话时注入一次」的断片问题。

## 注入什么

- `面板交接\<面板id>.md` 的「这次在做」+「下一步 / 卡点」两节（≤0.7 KB；没有这两节才退回文件尾）
- `场景私有记忆.md` 的 §〇 当前交接（≤1.6 KB）
- `_近期.md`（≤0.7 KB）
- `_索引.json` 里与本轮问题关键词命中的 3 条条目（标题 + 日期 + 绝对路径）
- 本场景的「拿不准就进待确认 / 收工」两行规则

总预算 ≤3 KB（字符），超出截断。数据来源全部是场景记忆真源/派生，不新增存储。
换会话默认不再往会话里塞开场消息（2026-11-17）⇒ 交接就是靠这一段每轮注入，用户看到的会话里没有假发言。

## 场景怎么认

用 `agent.sessionId` 去 `外壳/scenarios/*.json` 的 `panels[].sessionId` 反查（唯一真源，缓存 30 秒）。
查不到时会强制重建一次（换会话刚建好的 id 可能还不在缓存里）；仍未绑定任何面板的会话最多 5 秒重建一次，然后跳过，不猜。

## 引擎升级适配

本插件**不改** `12-源码照搬\引擎\`，只装在 profile 的 `node_modules\dsh-memory-recall`；引擎整目录替换不会覆盖它。
升级后确认两件事：

1. `server.log` 里有启动行 `[memory-recall] 已挂载：每轮注入 面板交接 / §〇 / 近期 / 相关条目`；
2. 在任一绑定面板发一条消息，能正常回话；插件异常一律退回 `next()`，不会阻断对话。

如果引擎改了 `agent/pre-step` 的入参（`payload.agent.sessionId` / `downstream.messages` / `kind:'enter'`），按新契约改 `apply()` 即可——`build()` 是纯数据拼装，不依赖引擎版本。
脚本侧（换会话/建会话）依赖 `session/create`、`session/rename`、`session/prompt`、`session/cancel`、`workspace/archiveSession`，升级后按 `AGENTS.md` 的「引擎契约随版本漂移」重跑验证。

## 安装 / 回退

```powershell
node 12-源码照搬\工具\记忆回响.mjs --check          # 只读
node 12-源码照搬\工具\记忆回响.mjs --apply          # 装 + enforce
node 12-源码照搬\工具\记忆回响.mjs --mode shadow    # 只记日志、不注入（先观察）
node 12-源码照搬\工具\记忆回响.mjs --off            # 摘掉
```

⚠ 插件在引擎启动时加载，改完必须**重启整壳**（`12-源码照搬\启动.vbs`），⛔ 不要只重启引擎（token 会失效）。
