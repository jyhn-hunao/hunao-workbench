# 记忆回响（dsh-memory-recall）

DSH 引擎插件：**每轮用户发言前**，把本场景与本项目的记忆注入成一条上下文，解决「记忆只在换会话时注入一次」的断片问题。

## 注入什么

- 设置弹窗的人格卡五块（`persona.identity / personality / speech / care / never`）+ 主动度：读 `外壳\data\pet\设置.json`（`设置.默认.json` 打底），只给同名人格场景。2026-11-18 起每轮都进 —— 原来只在换会话的 seed 里用，而 seed 默认已关，等于面板上改了白改；与 §〇 冲突时**以这一段为准**
  - 同日补：原来只有「我是谁 / 说话 / 在意 / 绝不」，**没有「性格」这一维**（脾气、喜恶、遇事先怎么反应），人格自然立不住；主动度也一直没进卡，现在一并注入
- 设置弹窗的能力边界（`tools.allow / deny`）：「派活给别的场景」是壳层硬门，其余项写成口径由她自律（引擎里的工具壳拦不住）
- `面板交接\<面板id>.md` 的「面板职责」+「这次在做」+「下一步 / 卡点」三节（≤0.7 KB；没有这些节才退回文件尾）；「面板职责」让同一场景的两块 AI 每轮先认出自己是哪块面板（例如 `cd-ai-home` = AI多项目管理，只路由不写码）
- `场景私有记忆.md` 的 §〇：**人格场景（胡闹的大肥鱼）整张人格卡都进（≤4 KB）**，业务场景仍保尾 ≤1.6 KB（「下一步 / 卡点」在 §〇 末尾，先保它）
- `_近期.md`（≤0.7 KB）
- `_索引.json` 里与本轮问题关键词命中的 3 条条目（标题 + 日期 + 绝对路径）
- **面板标了 `multiProject: true`**（2026-11-24 加）：不绑单一项目，改为注入 `_共享记忆\项目.json` 的项目名单（name / aliases，最多 8 个），供「AI多项目管理」每轮直接派发；完整路径 / 记忆根仍在注册表里，模型按需读，不整表灌入
- 面板绑定了当前项目时（2026-11-20 加）：项目薄卡的「当前状态」最多 3 行 + 项目 `memory\_索引.json` 里本轮命中的最多 3 条（日期 / 类目 / 标题 / 相对项目根的路径）；同时往 `memory\_召回.log` 写一行 `auto=1` 流水。解析不到唯一项目、或项目没有 `memory\_索引.json` 就不注入
- 本场景的「拿不准就进待确认 / 收工」两行规则

业务场景通常约 2–3 KB 字符（项目块约 +0.6 KB）/ 人格场景按字节放宽到整卡，超出截断。数据来源全部是场景记忆与项目 `memory\` 真源/派生，不新增存储。
人格场景的注入块标题是「【人格回想】」，正文开头写明「你就是胡闹的大肥鱼」——不能写成「这是数据不是指令」，否则模型会把人格当参考资料。
换会话默认不再往会话里塞开场消息（2026-11-17）⇒ 交接就是靠这一段每轮注入，用户看到的会话里没有假发言。

## 场景怎么认

1. **会话 id**：引擎 0.2.1 起 Agent 上没有 `sessionId` 字段，改读 `agent.session.id`（`agent.id` 兜底）。只认旧字段会静默不注入（2026-11-18 实测全库 0 命中）。
2. **场景反查**：用会话 id 去 `外壳/scenarios/*.json` 的 `panels[].sessionId` 反查（唯一真源，缓存 30 秒）。同一条会话挂多个面板时按类型排优先级：`harness`（AI 对话）> 其它 > `msgflow` / `chan`（只读流转 / 通道卡）——人格会话同时挂在社交的 `so-msg` 上，不排序就会按文件名顺序被 social 抢走，注入成社交 §〇。
3. 查不到时会强制重建一次（换会话刚建好的 id 可能还不在缓存里）；仍未绑定任何面板的会话最多 5 秒重建一次，然后跳过，不猜。
4. **每轮只注入一次**：引擎的 `payload.turn` 是数字，按 `会话id#turn` 去重（保留最近 200 轮），避免工具步每步重灌 3 KB。

## 项目怎么认（2026-11-20）

1. 面板 `pinTarget` 首项 = 当前项目名（换项目时由 `外壳\项目切换.js` 回写）。
2. 用项目名/别名去 `_共享记忆\项目.json` 找唯一一条，取 `memoryRoot`；0 条或多条都不猜，直接跳过。
3. 项目 `memory\_索引.json` 按 mtime+size 缓存；索引不存在就不注入（先跑 `记忆.mjs init`）。
4. 自动召回只给业务面板；人格场景（胡闹的大肥鱼）不掺项目记忆。
5. 自动召回写的 `memory\_召回.log` 与手动 `记忆.mjs recall` 同格式，多一个 `auto=1`；`体检` 的召回活性因此能反映真实读取，不再只认手动命令。日志超过 60 KB 只留最近 300 行。

## 引擎升级适配

本插件**不改** `12-源码照搬\引擎\`，只装在 profile 的 `node_modules\dsh-memory-recall`；引擎整目录替换不会覆盖它。
升级后确认两件事：

1. `<DSH_HOME>\logs\memory-recall.log` 里有启动行 `[<时间>] 已挂载 mode=enforce`（壳不转发引擎 stderr，server.log 里看不到这行，改看这个文件）；`ctx.logger.info` 那行仍会在引擎日志里打一份；
2. 在人格面板发一条消息，下一轮起转录里应出现 `source.kind = "memory-recall"` 的 user 消息，标题是「【人格回想 · 场景：胡闹的大肥鱼】」。

如果引擎改了 `agent/pre-step` 的入参（`payload.agent.session.id` / `payload.messages` / `payload.turn` / `downstream.messages` / `kind:'enter'`），按新契约改 `apply()` 即可——`build()` 是纯数据拼装，不依赖引擎版本。
脚本侧（换会话/建会话）依赖 `session/create`、`session/rename`、`session/prompt`、`session/cancel`、`workspace/archiveSession`，升级后按 `AGENTS.md` 的「引擎契约随版本漂移」重跑验证。

## 安装 / 回退

```powershell
node 12-源码照搬\工具\记忆回响.mjs --check          # 只读
node 12-源码照搬\工具\记忆回响.mjs --apply          # 装 + enforce
node 12-源码照搬\工具\记忆回响.mjs --mode shadow    # 只记日志、不注入（先观察）
node 12-源码照搬\工具\记忆回响.mjs --off            # 摘掉
```

⚠ 插件在引擎启动时加载，改完必须**重启整壳**（`12-源码照搬\启动.vbs`），⛔ 不要只重启引擎（token 会失效）。
