# 社交策略（dsh-social-policy）

P2 的 DSH 侧插件：把「回复语气 / emoji / 表情包频率 / 群聊接话口径」从各通道插件里抽出来，只对**已登记的社交会话**注入。

## 它做什么

1. 读 `外壳\data\社交会话.json`（DSH 镜像 `场景记忆\_共享记忆\社交会话.json`），按 `sessionId` 找当前会话归属。
2. 读 `外壳\data\社交回复.json`（DSH 镜像 `场景记忆\_共享记忆\社交回复.json`），生成一小段【社交回复规范】。
3. 读 `外壳\data\社交关系.json` / `社交情绪.json`（镜像同目录），按当前 `chatId` + 说话人追加一段【关系与情绪 · 内部】：
   - 这个群/这个人的熟悉度、好感、档位、标签、雷点；
   - 她自己当前的心情、强度、原因、多久回平静；
   - 本轮表达联动：文字最多多少字/句、贴纸与语音能不能发、群接话权重（来自 `config.moodEffects`）；
   - 只影响表达（句子长短、主动度、玩笑尺度、称呼、emoji/贴纸、群接话），不改事实与边界。
4. 在 `agent/pre-step` 每轮只追加一次，不刷工具步。
5. 订阅 `dsh-im/session-pre-bind` / `dsh-im/session-unbind`：飞书等 dsh-im 通道绑定会话时自动登记，解绑时只删掉自己写的自动条目，不碰手动登记。
6. 注册 `social_note` 工具：模型只在**确实发生**时记一条关系/情绪事件；外壳限量折算（单次好感 ±1~3、踩雷 -2、严重负向 -10；情绪按标签固定标准：开心 +4 / 兴奋 +8 / 得意 +3 / 低落 -4 / 委屈 -6 / 烦躁 -6 / 疲惫 -4 / 心虚 -3），模型不能直接写分数。
7. 把最近一次注入写到 `场景记忆\_共享记忆\社交策略-状态.json`，并给 `logs\social-policy.jsonl` 每条注入补 `people / mood / relationChars / stage / moodPlan`；设置页「回复风格 → 社交会话登记」和「关系与情绪 → 预览」都能看见。

## 不做什么

- 不改 QQ（`dsh-onebot-channel`）和飞书（`@xmanrui/dsh-im`）的源码。
- 不替代通道的发送、账号选择、@ 触发、群聊窗口/防刷屏；这些仍由各通道原生逻辑执行。
- 不重复注入：微信通道自己的 `_formatPrompt` 已带 `【社交回复规范】`，插件看到标记就跳过。
- 不改微信图库：微信贴纸仍由 `微信通道.js` + 鲸鲸 `native.stickers` 控制。
- 不替通道做硬裁剪：飞书出站不可拦，插件只把联动写进提示词；微信 / QQ 的文字、贴纸、语音由外壳各自执行。
- 不替用户做决定：关系档位不决定「回不回正事」，被 @ / 被直接问仍然必须回；好感再低也不许骂人。

## 情绪联动表（P2.5）

`config.moodEffects` 是唯一参数表，9 个标签 × 6 个字段；2026-11-24 起由 `外壳\社交状态.js` 的 `DEFAULT_CONFIG` 固定成标准，关系与情绪面板只读展示，不提供逐项编辑；CLI `情绪` / `预览` 会打印当前 plan。

| 字段 | 作用 | 0 的含义 |
| --- | --- | --- |
| `maxChars` | 本条正文最多多少字 | 0 = 不额外限制 |
| `maxSentences` | 本条正文最多几句 | 0 = 不额外限制 |
| `emojiFactor` | emoji 概率权重 | 0 = 不发 emoji（微信 / QQ 群 / QQ 普通 @/私聊真删） |
| `stickerFactor` | 贴纸概率权重 | 0 = 不发贴纸 |
| `voiceFactor` | 主动语音概率权重 | 0 = 不发语音 |
| `groupFactor` | QQ 群随机接话概率权重 | 0 = 不接话 |

通道执行：微信 `_reply → filterReply` 收文字、裁贴纸、删 emoji，并临时改 `voice-send.json` 的主动语音概率；QQ 群 `decide / parseReply / enqueueReply` 收文字、删 emoji、贴纸、语音、接话；QQ 普通 @/私聊由 `外发闸门` 收字、删 emoji、`QQ能力.shouldVoiceDirect` 收语音概率；飞书 / DSH 只做提示词注入和 `moodPlan` 元数据。所有通道日志都会写 `mood / maxChars / 贴纸或语音系数`，面板「情绪」页显示当前 plan。语音合成读的是**已经裁剪过的正文**，不会出现「文字很短、语音还在念长文」。

## 安装

```powershell
node 12-源码照搬\工具\社交策略.mjs --check
node 12-源码照搬\工具\社交策略.mjs --apply
node 12-源码照搬\工具\社交策略.mjs --mode shadow   # 只记日志、不注入
node 12-源码照搬\工具\社交策略.mjs --off           # 从 patch 摘掉
```

装完/改完必须**重启整壳**（`启动.vbs`），引擎启动时才会加载插件；不要只重启引擎。

关系数据首次建档：

```powershell
node 12-源码照搬\工具\社交状态.mjs 建档 --all
node 12-源码照搬\工具\社交状态.mjs check
node 12-源码照搬\工具\社交状态.mjs 自检
```

## 验证

- 设置页能看到「DSH 注入」状态；飞书首次绑定后，社交会话登记里出现一条 `source=dsh-im, auto=true` 的条目。
- 社交面板「关系与情绪」能看到每个人的熟悉度/好感、她自己心情、固定标准和下一轮注入预览；分数不再需要手动调。
- 单测：`node 12-源码照搬\插件\社交策略\自检.mjs`；数据面单测：`node 12-源码照搬\工具\社交状态.mjs 自检`。

## 数据

- 策略唯一可编辑源仍是 `外壳\data\社交回复.json`；保存时同步到 DSH 镜像。
- 关系唯一可编辑源是 `外壳\data\社交关系.json`（people + config），情绪是 `外壳\data\社交情绪.json`；保存时同步到 `场景记忆\_共享记忆\`。
- 每次改分 / 每轮注入写 `DSH_HOME\logs\social-state.jsonl`，带来源（auto / model / manual）和证据，面板可审计。
- 自动登记的飞书条目写在 `外壳\data\社交会话.json`，并带 `auto/source` 标记；手动条目不会被 unbind 删掉。
