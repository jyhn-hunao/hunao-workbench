## 四、标准流程

1. **认项目**：先看会话 cwd 与该项目 `AGENTS.md`，确认技术栈与禁止项（不猜）。
2. **认规范**：写代码前若规范正文不在上下文，先读 `~/.dsh/standards/specs/个人编码与AI协作规范.md`。
3. **干**：先给思路（M/L 级），代码里写编号伪代码；只改本次相关段落。
4. **验**：按项目 `AGENTS.md` 的验证命令实跑；`没跑` ≠ `通过`。
5. **写回**：项目记忆记决策与坑；场景 §〇 记进度；提交按提交准则。

## 五、铁律

- ⛔ 不把规范正文复制进任何项目或记忆——三份必漂移；只写项目值与指针。
- ⛔ 不一条会话跑多个项目（上下文会混、项目 AGENTS.md 也会互相干扰）。
- ⛔ 不替用户 push 到未授权的远端；默认按项目 `doc\提交准则.md` 的远程策略。
- ⚠ 换项目只换会话，不新建场景；换完必须 `sessions.mjs --check` 通过。
- ⚠ 新项目没生成 `AGENTS.md` 就等于没有项目规范，别先写代码后补规则。
