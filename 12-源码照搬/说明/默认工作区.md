# 默认工作区（`12-源码搬\工作区`）

> 这份文件是**补上的口径正文**：`05-协作与规矩\二-标准化规范.md:27` 和 `外壳\scripts\sessions.mjs:25`
> 都写着「口径见 `说明\默认工作区.md`」，但直到 2026-11-12 这个文件都不存在（引用悬空）。
> 内容全部照 `二-标准化规范.md` §2.6 落，只补本仓的实际路径。

## 1. 它是干什么的

- **新会话的默认 cwd**：`建会话.mjs:32` 与 `sessions.mjs:31` 的 `DEFAULT_CWD` 都指这个目录，
  引擎侧把它登记成一个工作区（显示名 = 文件夹名 `工作区`）。
- **不属于任何项目的活**都落这里：临时产物、跨场景文档、待判归档。
  有归属项目的活，进项目自己的目录，别往这里堆。
- 它**不是**项目目录、**不是**备份目录，**也不进 git**（根 `.gitignore:9` = `工作区/`），
  所以克隆下来它是空的（git 本来也存不了空目录），需要时由脚本/工作台按需创建。

## 2. 顶层只放这些（白名单制）

| 名称 | 收什么 | 期限 / 归属 |
|---|---|---|
| `_临时\` | 草稿、一次性产物。**必须** `<工作区>\_临时\<会话名或用途>-<YYYYMMDD-HHMM>\` | >7 天归档；谁建的谁收 |
| `截图位置\` | 截屏、演示图 | 长期（只增不删，超期另议） |
| `_webai产物\` | 网页版 AI 生成后落盘的中间稿 | 长期 |
| `_文档\` | 说明文档、技能说明（技能目录里只放真技能） | 归档（只读，别删——老文档/技能还引用着） |
| `_归档\<主题>-<YYYYMMDD>\` | 跨场景文档归档 | 归档（只读） |
| `_存档_<客户 OA>\`、`_修复_<客户 OA>\`、`_审计_<客户 OA>\`、`_oa_tmp\`、`_oa_mt_out\`、`_apkchk\`、`_site\`、`_任务单编制\`、`_项目文件\`、`_更新feed\` | 早期业务桶（本仓没在用，名字留作契约） | 归档（只读） |

入口文件只允许这三个：`README.md`、`_目录地图.md`、`DSH调用逻辑与效率手册.md`。

**要新建一个顶层目录 ⇒ 先登记**：改工具的机器可读白名单（`工具\梳理体检.mjs` 的 `IN_USE` / `ARCHIVE` / `ENTRY_FILES`），
同时在 `<工作区>\_目录地图.md` 的表里加一行（归属谁、放什么、何时能清）。两处都改完才算合规。

## 3. 不许放什么

- ⛔ **关键 / 不可再生的东西**（会话快照、引擎升级历史、行情库旧版、备份）—— 一律放 `<DSH根>\备份\`，**不放这里**。
- ⛔ 盘根（`<盘根>\`）、其它盘根目录、桌面 —— 一律不许在那儿新建东西。
- ⛔ `node_modules\`、`dist\`、`unpackage\`、`__pycache__\`、`.venv`、浏览器 profile 之类的工具缓存。

## 4. 换机 / 克隆注意（本仓特有）

- 根 `.gitignore` 挡着 `工作区/`，所以**仓库里没有这个目录的内容**，克隆后可能是空的、甚至不存在。
- `建会话.mjs` 与 `main.js` 启动时都会 `mkdir -p` 兜一下（2026-11-12 补），保证 cwd 一定存在；
  但**工作区在引擎里的登记**（`引擎数据\.dsh\storages\workspace.json` 的 `tables.workspaces`）是本机数据，
  克隆后不会自动生成 —— 新会话可能落进「未分组」，属正常现象，不是配置坏了。
- 换机器时按 `二-标准化规范.md:20` 的口径整包搬，别只搬 `工作区\`。
