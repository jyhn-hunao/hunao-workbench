# 跨会话派发与回执

> 场景：一个会话（如「AI·工作区」）把活派给另一个会话（如项目会话「luanyujia-workbench」），
> 对方干完后**自动**把结论投回派发方，不再出现「任务做完了、派发方什么也没收到」。

## 一、为什么需要它

引擎的 `session/prompt` 是单向的：把一条消息投进目标会话，目标会话的回答只留在它自己的窗口里。
派发方（发起的人）看不到，也就没法接着往下做事。2026-11-12 的真实故障就是：项目会话把排查做完了、
结论也写进了记忆，但「AI·工作区」这边一条回执都没有，用户只能自己去翻。

## 二、三件套（`12-源码照搬/工具/`）

| 脚本 | 谁调 | 干什么 |
| --- | --- | --- |
| `派发.mjs` | 派发方 | 认会话 → 写派发单 → 投消息（自动附回执命令）→ 起后台等回执 |
| `等回执.mjs` | `派发.mjs` 自动拉起 | 盯目标会话的 transcript，等「我们派的那条消息所在回合」结束 → 把结论投回派发方 |
| `回执.mjs` | 目标会话（也可手动） | 主动回执：把结论投回派发方并把派发单标成 done |
| `看门狗.mjs` | 人 / 计划任务 | 巡检派发单：超时 / 「干完了没回执」就报；默认只读，`--补` 才补投一次回执 |
| `派发-公共.mjs` | 上面三个共用 | 会话索引、transcript 解析、换 cookie、投消息、派发单读写、日志 |

## 三、用法

```powershell
# 1) 派活（一条命令；默认起后台等回执，最多 3600 秒）
node 12-源码照搬\工具\派发.mjs --to "luanyujia-workbench" "排查技能面板为什么是空的"

# 只要派、不要自动回执
node 12-源码照搬\工具\派发.mjs --to "mlw" "任务" --no-watch

# 只核对会话与派发单，不投递
node 12-源码照搬\工具\派发.mjs --to "mlw" "任务" --dry

# 2) 目标会话干完后主动回执（派发消息里会自动附上这条命令）
node 12-源码照搬\工具\回执.mjs --ticket 20261112-111500-cd208a --summary "结论 3~6 行"

# 3) 巡检：哪张单超时、哪张「干完了没回执」（只读；加 --补 才补投）
node 12-源码照搬\工具\看门狗.mjs
```

## 四、派发单（对账用）

落 `12-源码照搬\引擎数据\.dsh\派发\<时间>-<目标尾号>.json`（运行时数据，`.gitignore` 已挡）：

```json
{
  "id": "20261112-111500-cd208a",
  "from": "session-f28099f4-...", "fromTitle": "程序开发·工作区",
  "to":   "session-cd208a77-...", "toTitle": "luanyujia-workbench",
  "text": "任务前 300 字", "turnsBefore": 6,
  "mandate": "本次授权范围（一次一单；不写就是默认只做本条）",
  "parent": "外层派发单号（分层派发才有，普通派发是空串）",
  "rootFrom": "根派发方会话 id（回执自动上浮的终点）", "rootFromTitle": "胡闹的大肥鱼",
  "createdAt": 1794..., "state": "pending", "replyAt": 0, "reply": ""
}
```

`state` 有四种：`pending`（等）/ `done`（已回执）/ `timeout`（超时，也回了一条「没回」）/ `closed`（人工作废，看门狗不再跟踪，`closedWhy` 写原因）。
`回执日志.md` 与单子同目录，一行一条，人肉扫一眼就知道哪张单没回。

## 五、判据（怎么算「我们那轮」）

1. 在目标会话 transcript 里找 `user/message` 正文含**派发单 id** 的那条（一条消息一行 JSON）；
2. 从它往后找第一个 `turn/end`——那就是我们这条派发跑完的回合；
3. 取该回合最后一条 `assistant/message` 的 `text` 段（不含 reasoning），作为回执正文。

不靠「目标会话自觉」：目标忘了调 `回执.mjs`，`等回执.mjs` 也会把结论投回来。

## 六、坑（都是实测记下来的）

| 坑 | 判据 / 绕法 |
| --- | --- |
| 回执投给自己 | `回执.mjs` 在「找不到派发单且没给 `--to`」时直接报错，不猜 |
| transcript 是按 cwd 分目录、目录名被编码过 | 不推导文件名，遍历 `引擎数据\.dsh\sessions\*\` 找 `<sessionId>` 目录 |
| zstd 文件正在写 | 解压或解析失败就当「没写完」，下一拍重试（默认 5 秒） |
| 引擎 token 在 server.log 里且带端口 | 正则按 `DSH_WEB_URL` 的端口过滤，别写死 3080/3083 |
| 目标会话正忙（派发消息排队） | 回执按「消息含单号」定位，不按时间猜，忙时也不会取错轮次 |
| 派发单只增不删 | 单子很小，留着当台账；要清可整体删 `派发\` 目录 |

## 七、授权（Mandate）与巡检（Watchdog）

- **授权一次一单**：派单时 `--mandate "只改 工具\X.mjs，不动引擎、不提交"` 写清这次允许做到哪；不写则用默认「只做本条任务、项目目录内可改、不动引擎和别人的记忆、不提交不推送」，越界即停回问。
- **看门狗判五种状态**：已回执 / 超时未交付 / 消息没进会话 / 在跑 / 已干完·未回执；阈值 `--warn 30 --err 60`（分钟），`--json` 给计划任务和界面，`--strict` 让 warn 也算失败，`--补` 才补投一次回执。
- **为什么必须有无声兜底**：`等回执.mjs` 是派发时拉起的后台进程；壳关了、机器重启、或用了 `--no-watch`，单子就永远 pending —— 看门狗负责发现这种「干完了但没人收尾」。
- **界面入口（不用记命令）**：**总入口**「胡闹的大肥鱼」场景右列的「派发巡检」面板（`type: dispatch-board`，`pet-dog`），每 60 秒自动扫一次，按「在跑 / 没送到 / 干完没回执 / 超时」分类；点「补投回执」才投消息，点「单子」看原始 JSON，点「↻ 立即巡检」马上扫。它属于总入口，不在「记忆」场景——记忆只管记忆。
- **要你点头也不用敲命令**：`confirm` 级的派发会落进 `外壳\data\pet\待批准.json`；**总入口**面板顶部列「待批准 N 条」，点【批准】当场派出、点【忽略】从队列删掉。面板和 `桌宠.mjs` 读的是同一个文件，两边口径不会漂。
- **定时触发（Trigger）**：`外壳\pet\定时.默认.json` 是示例（默认全关），面板里「定时触发」一行一条、点按钮开关（写 `外壳\data\pet\定时.json`）。到点由壳自动调一次 `桌宠.mjs 派`：`read` 级直接派，`confirm` 级照样落进待批准——自动化不越过人，同时也不用人守时间。

## 八、分三层：总入口 → 流程 superAgent → worker

```
你（宿主）
  └ 胡闹的大肥鱼（总入口 · 人格会话，只认人、只路由）
      ├ 程序开发·工作区（开发流程 superAgent）→ 项目会话（mlw 等 worker）
      └ 创意工坊·导演（制作流程 superAgent）→ 十个岗位会话
```

- **总入口只有一个**：人格会话「胡闹的大肥鱼」。她不干活，只把一句话归到能接的场景。
- **怎么认路**：`外壳\data\pet\设置.json` 的 `routes`（关键词 → 会话标题 + 级别 `read`/`confirm`/`never`，按配置顺序当偏好）；认不出就列候选问人，⛔ 不按目录名猜。
- **谁能派**：`tools.allow` 必须含 `dispatch`；`deny`（shell / git_push / http_post）一律不碰 —— 这是硬门，不靠模型自觉。
- **要不要你点头**：`dispatchPolicy` 一处判完 —— 从 QQ / 飞书通道来的话自动升一级；`approval` 的 `write_code` / `outbound` 决定要不要问；`level: never` 直接禁。
- **回执逐级上浮（已代码化，不靠自觉）**：流程 superAgent 派给 worker 时带 `--parent <外层单号>`，子单里就记下 `rootFrom`；worker 跑 `回执.mjs` 结子单后，同一份 cookie 把结论投给根派发方，并把外层单一并标 `done`。忘了上浮会被抓住：看门狗对「子单 done、外层仍 pending」报 `已回执·外层未结` WARN。一次派单一条回执，两层都不许断在半路。
- **记忆场景不是总入口**：它只做系统 / 记忆操作（体检 · 交接 · 归档 · 召回），是大肥鱼可以派下去的一个下游场景。
