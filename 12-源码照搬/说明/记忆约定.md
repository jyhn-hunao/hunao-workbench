# 记忆约定（1 页）

> 这套工作台的记忆是**文件**，不是聊天记录。每个场景一个文件夹，AI 开场先读它。
> 本页只讲"怎么用命令"；字段契约、标签规范、闸门判据、8 个场景的落地矩阵见 `doc\记忆体系规范.md`（v4，2026-11-13）。

## 一、放在哪

```
引擎数据\.dsh\场景记忆\
  命令\场景私有记忆.md       ← 这个场景的骨架（§〇 + 职责 + §一~§五 下标），约 3–8 KB
  命令\决策\<日期>-<标题>.md ← 一条一个文件（§五 拆出来的决策，单篇 ≤2 KB）
  命令\坑\<日期>-<标题>.md   ← 同上，踩过的坑
  命令\通知\<日期>-<标题>.md ← 同上，跨会话通知
  命令\定论\<主题>.md         ← 同主题多篇沉淀出的结论（draft 待 AI 归纳；confirmed 不再覆盖）
  命令\_文件索引.md          ← 这个场景有哪些文件
  命令\归档\               ← 交接/整理/拆分前的原文（只进不改；被定论引用的条目 整理 默认不搬）
  _共享记忆\               ← 多个场景都要用的东西
```

## 二、一份私有记忆的格式

- `## §〇 当前交接`：四小节（上次交接 / 当前项目 / 私有记忆变更 / 下一步·卡点），**≤4 KB**
- `## 核心职责`：≥3 条（负责什么 / 不碰什么 / 一句话）
- `## §一 ~ §四`：职责边界 / 现状接口（**只追加**）
- `## §五 坑与决策`：**只放下标**（规模计数 + 最近 5 条指针），正文一律在 `决策\` / `坑\` 分条文件里

## 三、五条铁律

1. **§〇 ≤4 KB**：只写"下一轮接手要知道的"，细节进分条文件或归档
2. **新条目只走 `写`**：往 §五 直接追加正文 = 巨石复发，`check` 会因为它超 25 KB 直接判红
3. **单篇 ≤2 KB**：超了 `check` 报 ✗（一条记忆只该讲一件事，超 2 KB 说明该拆成两条）
4. **交接才归档**：`node 工具\场景记忆.mjs 交接 --场景 <名字>` 会把旧版挪进 `归档\`
5. **check 不过别换会话**：`node 工具\场景记忆.mjs check --场景 <名字>`

## 四、常用命令

```powershell
node 工具\场景记忆.mjs list                 # 看每个场景缺什么
node 工具\场景记忆.mjs init --场景 命令      # 生成身份卡/画像（首次；同时收敛重复副本）
node 工具\场景记忆.mjs stamp --场景 命令     # 重新生成身份卡/画像
node 工具\场景记忆.mjs 交接 --场景 命令      # 归档旧版 + 补 §〇
node 工具\场景记忆.mjs 读 --场景 命令        # 只打印 §〇（约 2-4 KB，别整读主文件）
node 工具\场景记忆.mjs 写 --场景 命令 --类 决策 --标题 "xxx" --要点 "a|b|c" --证据 "<路径>::<片段>"
node 工具\场景记忆.mjs 写 --场景 命令 --类 决策 --标题 "xxx" --要点 "a|b" --不确定 "要问用户的疑问"   # 进 _待确认.md，不生效
node 工具\场景记忆.mjs 写 --场景 命令 --类 决策 --标题 "xxx" --要点 "a" --取代 程序开发/决策/2026-11-10-xxx.md  # 声明取代旧条目
node 工具\场景记忆.mjs 写 --场景 命令 --类 通知 --标题 "xxx" --要点 "a" --过期 2026-12-31   # 临时约定：到期自动失效（召回/注入跳过）
node 工具\场景记忆.mjs 写 --场景 命令 --类 决策 --标题 "xxx" --要点 "a" --相关 bilibili   # 逻辑多归属：别的场景也适用
node 工具\场景记忆.mjs 待确认 --场景 命令          # 看队列编号
node 工具\场景记忆.mjs 确认  --场景 命令 --序号 1    # 用户点头后转正；否掉加 --放弃
node 工具\场景记忆.mjs 收工  --场景 命令          # 索引 + 近期记忆 + 沉淀定论 + check + 待确认计数（exit 0 才算收工）
node 工具\场景记忆.mjs 索引  --all               # 全量重建 _索引.json + _共享记忆\场景目录.json（神经元据此画场景；少场景时跑这个）
node 工具\场景记忆.mjs 沉淀 --场景 命令 [--dry] [--force]  # 同主题 ≥3 篇 → 定论\<主题>.md 草案（证据=要点原文第一行；源条目写回 consolidated_into 回链）
node 工具\场景记忆.mjs 召回 --场景 命令 --词 "关键词" [--条 5] [--含归档]  # 场景级检索：标题 ×3 / 标签 ×2 / 正文 ×1 + 45 天热度；默认排除归档/过期，--含归档 时 ×0.3 降权
node 工具\记忆回响.mjs --check                # 每轮注入插件装没装（改完/ --apply 后要重启整壳）
node 工具\场景记忆.mjs 拆 --场景 命令 [--dry] # 一次性：§五 存量条目拆成 决策\ 坑\，原文进 归档\
node 工具\场景记忆.mjs 整理 --场景 命令 [--days 180] [--dry] [--强搬]  # 旧条目搬 归档\（默认 180 天；被定论/他条证据引用的不搬，--强搬 例外）
node 工具\场景记忆.mjs check --场景 命令     # 自检（单篇体量/主文件红线/证据复核/索引一致性/定论来源/冲突字段/同证据矛盾/薄卡对账）
node 工具\记忆.mjs 写 --project "<根>" --类 pitfalls --标题 "xxx" --正文 <草稿.md> --证据 "<文件>::<片段>"
node 工具\记忆.mjs 体检 --project "<根>"     # 八项 + 场景层一起验；exit 0 才算收工
node 工具\记忆.mjs 备份 --project "<根>"     # 留最近 10 份，自动进 .gitignore
```

> 读其它节用标题文字匹配：`读 --场景 命令 --节 五、坑与决策`（跑错会列出可用小节）。
> 项目记忆正文用 `工具\记忆.mjs recall`：默认按分数阈值滤低分噪声，每次调用记一行到 `memory\_召回.log`（`--no-log` 可关）。
> `写` 会自动补 frontmatter、落 `memory\<类目>\<日期>-<标题>.md`、重跑 index 再跑 check；check 不过就退出 1，别当"已记录"。
> ⚠ `--dry` 是布尔旗标，工具内部按 `argv.includes` 判断——所以它后面不要再跟取值；出现在命令里任何位置都生效。

## 五、证据字段：让记忆能自证还成不成立

记忆最容易烂的方式不是写错，是**当时对、后来代码改了却没人回头改**。所以正文 frontmatter 可带 `evidence`：

```yaml
evidence:
  - 12-源码照搬/工具/记忆.mjs::function cmdDoctor
```

写法是 `路径::文件里的一句话`。路径先按工作台根（`12-源码照搬\`）解析，找不到再往上找一层，所以 `工具\x.mjs` 和 `12-源码照搬/工具/x.mjs` 两种写法都认（清单里两种都有人写）。`体检` / `check` 会逐条复核：文件不在、或那句话已经找不到 → 报「证据失效」，逼你更新或删掉那条记忆。

**证据是强制的（2026-11-13 起）**：`--类 decisions` 与 `--类 pitfalls` 不带证据会被 `写` 直接拒（退出 1）；确实没有可指向的东西就写 `--无证据 "原因"`，它会落成 `no_evidence: 原因`，体检按「已交代」算——留白才是问题。`体检` 对**近 30 天**的决策/坑缺证据判 ✗，存量只 ⚠ 计数。

`--证据` 可以重复传多条（`--证据 "a::x" --证据 "b::y"`），同一旗标内部也会按 `;` 拆。

## 六、防复发（这四条是 2026-11-12 的教训）

1. **唯一入口**：正文只用 `写` 落盘；复制正文到别处 = 制造第二份真源，迟早不同步。
2. **同轮自检**：写完立刻 index + check，别攒到下次开工才发现索引过期。
3. **闸门有退出码**：`体检` exit 0 才算收工，不靠"我看了一眼没问题"。
4. **配置不许静默降级**：`_词表.json` 空着、备份没做过、召回没人用，体检都会报出来——空配置比没配置更危险。
5. **记忆很久没动也会被提醒**：`体检` 的新鲜度项看「最新记忆文件 mtime」与「之后又有几次提交」——同时满足「>3 天没动」和「之后 ≥3 次提交」才 ⚠。只看时间先后的第一版在「先写记忆、后提交」的正常顺序下就会误报，所以加了提交次数门槛。近似判据，只提醒、不阻断收工。
6. **记忆闸门进了发布流程**：`发布前检查.mjs` 现在会跑 `场景记忆.mjs check --all`，记忆腐化（§五 又攒正文、单篇超 2 KB、证据指空）在出包前就拦住。
7. **换机器自动盖章**：`环境适配.mjs --apply` 末尾会逐场景跑 `stamp`（身份卡/画像在 `.gitignore` 内、不进库，换机必然过期）。
8. **开场不再靠自觉**：`换会话` 建新会话时，开场消息里**直接注入**交接正文——优先 `面板交接\<面板id>.md`（同场景两个 AI 面板各读各的，不串味），没有才回落到场景 §〇；上限 4 KB，超了截断并给全文路径。以前只给一串绝对路径、又明令"这轮别读文件"，等于没注入。
9. **换会话前过项目层体检**：`换会话.mjs` 的强制闸从「场景层 check」扩到「项目层 `记忆.mjs 体检`」。项目根按「面板会话 cwd → `pinTarget[0]` → 场景里唯一 active 项目」三级解析，**解析不到就跳过并写明**（程序开发挂着 3 个项目，不凭目录名猜）；体检 ✗ 才拦，⚠ 只提示。

## 七、跨场景

`node 工具\发消息.mjs --to B站 "帮我看下这个"` —— 纯文件，不发网络请求。对方下一轮读自己的 §〇-通知 就能看到。

## 八、场景记忆分条化：一条记忆一个文件（2026-11-13）

**为什么**：§五 是只追加的，一年就长成一个 25 KB 的巨石；每一轮开工都整份读进上下文，越读越贵、越读越糊，改一条的 diff 也混在几十条里。

**怎么改**：主文件只留骨架 + §五 下标（约 1 KB），每条记忆一个文件：

| 判据 | 门槛 | 谁判 |
| --- | --- | --- |
| 单篇大小 | >2 KB → ✗；>4 KB 说明该拆成两条 | `check` |
| 主文件体量 | >12 KB → ⚠「该拆了」；>25 KB → ✗ | `check` |
| 单个分类目录 | >30 篇 → ⚠（按日期再分年） | `check` |
| 证据 | 每条 `evidence` 逐条复核，失效 → ✗ | `check` |
| §〇 | >4 KB → ✗ | `check` |

**三条命令就是全部入口**：

- `写`：唯一写入口，落 `决策\` / `坑\` / `通知\`，自动 frontmatter + 登记 `_文件索引.md` + 同轮 `check`；同名条目拒写（退出 1）。
- `拆`：一次性把存量 §五 拆成文件，原文整份进 `归档\场景私有记忆-<时间戳>-拆分前.md`，§五 换成下标。会先在 `--dry` 下打印计划与对账，别跳过这一步。
- `整理`：超过 `--days`（默认 180）的条目搬进 `归档\`，§五 下标重算。被 `定论.sources` 或他条 `evidence` 引用的条目**不搬**（一搬就断链），`--强搬` 连它们一起搬、断链由 `check` 报出来。

**拆分前后实测**（本仓 2026-11-13）：程序开发 24,195 B → 主文件 7,432 B（§五 18,298 B → 决策 25 篇 + 坑 7 篇）；自我复盘 13,228 → 5,241 B；本地电脑 2,820 → 2,786 B；命令 3,448 → 3,816 B（小场景拆分后主文件略增，下标块比原 §五 大）。原文日期条目 72 条，拆完缺失 0 条。

**不改的东西**：Markdown 仍是唯一真源，`check` / `git diff` 照样能复核；没有引入数据库，`工具\` 依旧零依赖。体量问题用"拆文件"解决，不用"换存储"解决。

## 九、不确定就不写死（2026-11-13）

记忆最贵的错误是"写错还写死了"。所以 `写` 前面有三道闸：

- **像不像同一条**：同场景标题相似 ≥50% → 拒写（退出 3）。是同一条就改那一篇；确实是两件事 → `--不是同一条 "词：区别"`。
- **拿不准**：`--不确定 "要问用户的那一句"` → 进 `_待确认.md`，**不落正式条目**；当轮就问用户，`确认 --序号 N` 转正、`--放弃` 不留痕。
- **词像但不是一回事**：`--不是同一条` 会写进 `distinct`，联想层不再用那个词连边——不靠算法猜语义，靠作者显式声明。
- **标签**：>12 字或含标点 → 拒写（退出 2）；一条最多 3 个。
- **收工**：`收工 --场景 X`（索引 + 近期记忆 + 沉淀定论 + check + 待确认计数），exit 0 才算收工；`check` 把超过 7 天的待确认标 ⚠。其实 `写` 成功且 check 通过后也会**自动静默沉淀**一次——巩固不再依赖人记得收工。

每个场景的定位卡都有同一段「记忆自主管理」，AI 收工前按它执行；人格场景的 `_近期.md` 仍归 `人格记忆.mjs`。

## 十、冲突、遗忘与审计（2026-11-13 v4 起）

- **取代 / 过期 / 相关**：`写` 加 `--取代 <记忆ID>`、`--过期 <日期>`、`--相关 <场景id,…>` 就会写进 frontmatter。`check` 盯两件事：`supersedes` 指向不存在的 ID → ✗；`expires` 已过 → ⚠，且**召回和每轮注入都跳过**过期条目（临时约定到期自动失效）。
- **遗忘是降权不是删除**：`整理` 搬进 `归档\` 后条目**仍进索引**（kind=归档）。`召回` 默认排除归档；要捞旧经验就加 `--含归档`，命中按 ×0.3 降权并标注"（归档，降权）"。
- **巩固回链**：`沉淀` 的 `evidence` 取源条目要点**原文第一行**（≤60 字，grep 可命中），并给每个源条目写回 `consolidated_into: 定论/<主题>.md`。8 篇存量定论已全量重算（2026-11-13）。
- **check 新增五项审计**：① `_索引.json` 与文件**双向一致**（缺/多都报）；② 定论 `sources` 悬空；③ 定论证据失效；④ 同一条证据被不同条目引用 → ⚠ 提示去 `_共享记忆\冲突.md` 裁决；⑤ 薄卡 ↔ 项目根对账（薄卡在、`项目.json` 有 memoryRoot、索引在）。
- **§〇 截断保尾**：会话开场注入和每轮回想注入超预算时，头部保留约 180 字节 + **末尾"下一步 / 卡点"必保**——把下一步截掉等于白注入。
- 程序记忆仍走显式（核心职责 + runbooks + 收工规则），不上"从反复成功自动抽象"：当前没有可信的成功信号源。未决设计项完整清单见规范 §11。
