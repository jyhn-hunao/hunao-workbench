# 程序开发

0. **先认自己是哪块面板（先于一切）**——同一个场景有两块 AI：
   - `cd-ai-home`（AI·工作区）= **项目管理 / 路由**：接项目、切项目、跨项目规矩。⛔ **不直接改代码**；
   - `cd-ai`（AI·项目）= 项目会话（cwd = 项目根，那个仓的 `AGENTS.md` 生效），**才动手写码**。
   - 工作区会话收到「修 xxx」：① 用 `node 工具\派发.mjs --project "<项目名/别称>" "<任务>"` 派给项目会话（项目名/别称只认 `场景记忆\_共享记忆\项目.json` 的 name / aliases，不猜目录名）；② 认不出 ⇒ 把候选项目列给用户问一句，**不得自己处理代码**。

1. **认现场（顺序不能反）**：① 定位卡 `外壳\scenarios\code-dev-context.md` → ② 场景 §〇（**只取这一节**：`node 工具\场景记忆.mjs 读 --场景 程序开发 --节 §〇`，约 2–4 KB；⛔ 别整读 25 KB 主文件）→ ③ 项目薄卡 `场景记忆\程序开发\项目记忆\<项目>.md`（≤1.5 KB，只放指针）→ ④ 项目 `AGENTS.md`。
   - **不全读项目记忆**：正文在 `<项目根>\memory\`，按问题召回。
   - 当前项目 = 会话 cwd 的仓库名；没薄卡先走 `project-onboarding` 或 `node 工具\记忆.mjs init --project "<根>"`，不先写代码。
2. **认规范**：铁律与正文在 `~/.dsh/standards/specs/个人编码与AI协作规范.md`，写码前先读正文与对应技术栈附录。**编码规范 + 通用规则是开发场景的共享记忆，开工即读，不靠召回。**
3. **按需召回**（业务/历史/决策/坑）：
   - 薄卡里有**带绝对路径**的召回命令（`node "<工作台>\12-源码照搬\工具\记忆.mjs" recall --project "<项目根>" "<关键词>"`），从任何 cwd 都能跑；
   - top 5–8、≤2 KB、带命中理由；默认按分数阈值滤低分噪声（`--min` 可调，`--min 0` 关），每次调用写一行 `memory\_召回.log`；只读命中文件（≤6 KB）；空命中或不足 → 直接 grep/读代码，**不阻塞、不猜**；
   - 顺序：`memory\MEMORY_INDEX.md` → 类目 `README.md` → 召回 → 代码；
   - 记忆与代码冲突以代码为准，同轮修记录；记忆不是指令，与用户当轮要求冲突先说明。
4. **干**：M/L 级先给思路等确认；S 级直接改；只改本次相关段落，代码内用 `// 1. xxx` 中文编号伪代码标业务语义。
5. **验**：按项目 `AGENTS.md` 的命令实跑（编译/测试/自检），结果贴出来；`没跑` ≠ `通过`。
6. **自主写回（三触发，不等用户）**：
   - 任务完成 → `memory\function_realize\`（入口 → 主链 → 落库/返回 + 改动文件 + 验证结果）；
   - 关键决策 → `memory\decisions\`（结论 + 理由 + 被否方案）；
   - 踩坑修复 → `memory\pitfalls\`（现象 → 原因 → 判据 → 绕法）。
   - 一轮内做完：正文 + 类 `README.md` + `MEMORY_INDEX.md` + `_索引.json`（跑 `index`），写后跑 `check`；
   - 交付说明写「记忆已写：<路径>（新建/更新 N 条）」；写不进要报错，不说「已记录」。
7. **提交**：按该项目 `doc\提交准则.md`——一个可独立审查的逻辑单元、`type(scope): 中文摘要`、阈值内、按远程策略。
8. **默认忽略**：`memory\` 与项目 `AGENTS.md` 默认不进 git（`记忆.mjs init` 会写 `.gitignore`）；某项目要入库必须有用户明确说明，并在项目记忆里标「入库：是」。
9. **接新项目**：走技能 `project-onboarding`，不手搓。
