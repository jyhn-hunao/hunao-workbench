# 场景记忆分条化：一条一个文件

## 结论

场景记忆从「一个 25 KB 巨石」改成「一条一个文件」，由工具强制，不靠约定。

## 做法

- `写`：唯一入口，落 `决策\` / `坑\` / `通知\`，自动 frontmatter + 登记 `_文件索引.md` + 同轮跑 `check`。
- `拆`：一次性把 §五 存量条目拆成分条文件，原文整份进 `归档\`，§五 只留下标（约 1 KB）。
- `整理`：>180 天的条目搬 `归档\`，§五 下标重算。
- `check` 硬化：单篇 >2 KB ✗、主文件 >25 KB ✗、>12 KB ⚠、单目录 >30 篇 ⚠、evidence 逐条复核。

## 实测（2026-11-13）

程序开发 24,195 B → 主文件 7,432 B（§五 18,298 B → 决策 25 篇 + 坑 7 篇）；
自我复盘 13,228 → 5,241 B；本地电脑 2,820 → 2,786 B；命令 3,448 → 3,816 B。
4 个场景原文日期条目 72 条，拆分后缺失 0 条；`check --all` 全过。

## 踩到的坑

`--dry` 一开始用 `val('--dry')` 判断——它取的是「--dry 的下一个参数」，永远是空，
于是首次实跑把 自我复盘 真拆了。已用 git 还原、改成 `argv.includes('--dry')` 后重跑。
