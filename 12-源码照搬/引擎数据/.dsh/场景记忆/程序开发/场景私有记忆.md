## 五、坑与决策

- 2026-11-11（决策·跨项目）：**记忆能力改造定稿**——`<项目根>\memory\` 是唯一正文（8 类 + MEMORY_INDEX），工作台侧只留 ≤1.5 KB 薄卡；召回走 `node 工具\记忆.mjs recall --project "<根>" "<词>"`（词法、≤2 KB、带命中理由，空命中直接读代码）；写回三触发（完成/决策/坑）同轮更新类 README + MEMORY_INDEX + `_索引.json`。**不接 mnemon**，语义召回留 `--provider` 可选层。设计：`doc\记忆能力改造设计.md`。
- 2026-11-11（规矩·跨项目）：`memory\` 与项目 `AGENTS.md` **默认不入库**，`记忆.mjs init` 会把 `memory/`、`AGENTS.md` 写进目标仓 `.gitignore`；要入库必须用户明确说明。本仓 `AGENTS.md` 是模板规则，属已声明例外。`_索引.json` 是可再生产物，不手改。

- 2026-11-11（工具坑·跨项目）：`node 工具\场景记忆.mjs check` 的「⚠ 会话文件不在库」在本机是**误报**，不是会话真丢了——`cmdCheck` 里 `SESS = path.join(MEMROOT, '..', '.dsh', 'sessions')`，而 `MEMROOT` 本身已含 `.dsh`，拼出来是 `引擎数据\.dsh\.dsh\sessions`（不存在）⇒ 恒为 false。真实目录是 `引擎数据\.dsh\sessions\<工作区>\<sessionId>\session.v4.jsonl.zstd`。判会话在不在，直接去看这个目录，别信这条告警；要修工具就把那行改成 `path.join(MEMROOT, '..', 'sessions')`。

- 2026-11-11（交付判据·跨项目）：凡实现写法参考了仓内某个现有文件/类（Redis 覆盖、批量写入、缺失补齐等），在实际参考到的分支/方法处标 `// [REF-<文件缩写>#<方法名>] 说明`，缩写↔文件映射随交付说明给出，便于按关键词检索全部使用点；只标真正参考到的写法，不复制参考代码的注释原文。旧记忆引擎里这条是常驻记忆，工作台改文件记忆后落这里。
- 2026-11-11（迁移判据·跨项目）：旧记忆引擎（`.mnemon`）迁进工作台文件记忆的分工——常驻记忆里跨项目的进本节 §五，项目专属的进 `项目记忆\<项目>.md`，分域长知识整篇归档 `归档\<项目>-mnemon-<日期>.md`（只进不改）供回查，项目记忆只留提炼结论；旧引擎的「记忆落点分层」规则随引擎一起作废，别再沿用。

- 2026-11-10（决策）：删除「工作台定制」场景，其职责并入本场景的**当前项目**（见 §〇 第 2 小节）。理由：两个场景在同一仓库里做同一件事，同一仓两条会话容易串台，且场景应按职责分、不按项目分。原记忆已并入该项目的项目记忆，快照在 `归档\工作台定制-场景私有记忆-2026-11-10.md`。

- 2026-11-10（决策）：**一个场景多项目、一个项目一条会话**。理由：规范按会话 cwd 生效，混用会让几套项目规则互相干扰；项目数会持续增长，若一项目一场景则顶栏与维护成本都会爆。
- 2026-11-10（决策）：规范分三处放——铁律/方法在 `~/.dsh/standards`（唯一真源）、项目值在各仓 `AGENTS.md`、场景层（本文件与技能）只放"怎么干活"。
- 2026-11-10（坑）：`建会话.mjs` 等脚本原先写死 3080 端口取 token，本机 3083 全废；已修（提交 7c4a386）。新增脚本一律按 `DSH_GUI_BASE` 的端口过滤 token。
- 2026-11-11（工具坑·跨项目）：改**混合行尾**的大文件时，用编辑工具整文件替换会把某一段 CRLF 统一成 LF，diff 从 3 行膨胀到 484 行（本机 `renderers.js` 就踩了）。规避：改完先 `git diff --numstat` 看行数，再 `git diff --ignore-cr-at-eol` 看真实改动；噪声大就 `git checkout <rev> -- <file>` 还原，然后用 .NET `ReadAllText` / `Replace` / `WriteAllText(UTF8Encoding($false))` **按字节只替换目标行**（保留原行尾与无 BOM）。
- 2026-11-11（判据·跨项目）：排「卡在加载页」先比日志顺序，别先怀疑网络——凡是「A 就绪」与「B 拿到资质」分两步的，先确认 B 是否晚于 A 广播。
- 2026-11-11（决策）：**换项目改成面板标题栏「项目」下拉**（用户当面反馈「程序开发里无法切换项目」）。之前只有 `接入项目.mjs` 一条路：每次都 `session/create` 新建会话、只回写 AI 面板，而面板里把引擎侧栏藏了 ⇒ 界面上没有任何切换入口，切回旧项目还会多一条孤儿会话。现在：下拉列「已登记项目 + 当前项目父目录下有工程标志的同级目录」，选已接入的 = 复用原会话（按 cwd/标题精确匹配，不新建），选未接入的 = 先跑既有接入脚本再切；切的同时把 Git 面板 `repo`、定位卡两行、场景索引一行一起回写。规则：**没会话不硬切、非 git 仓不动 Git 面板**，两者都进 warnings 由界面显示。后端 `外壳\项目切换.js`（纯函数 + 注入 fs，可单测），自检 `node 外壳\scripts\项目切换自检.mjs`（40 项）。下拉只列「登记项目 + 当前项目父目录下有工程标志的同级目录」——**DSH 的工作区不单独成项**（本机那个「工作区」里躺着别的场景的会话，列进去会钉错人）；没有标题的会话也不能当钉子（`sessions.mjs --check` 会失败）。

- 2026-11-11（决策·方向）：**项目记忆从"单文件全量载入"改成"薄卡 + 按问题召回"**。用户明确：开发场景的项目记忆要自主写回（不靠手动触发）、优先只读编码规范与通用规则、其余按问题检索；每场景常驻只留工具/技能/人格/跨场景必知；记忆神经元要能画出项目私有记忆（现在渲染器不读 `项目.json` 的 `memory`，且 `索引.json` 缺程序开发区域、owner 名对不上面板 id）。正文落项目仓库、工作台只留薄卡与索引；5 个待拍板项见 `doc\handoffs\2026-11-11-记忆能力改造-handoff.md` §5。**未定稿前不动实现。**
