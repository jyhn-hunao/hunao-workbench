## 五、坑与决策

- 2026-11-10（决策）：面板组合只用本仓已注册的类型（`view` / `file` / `harness`），不造新渲染器——先能看能聊，等真被使用逼出需求再补。
- 2026-11-10（坑）：`外壳\scripts\建会话.mjs:57`、`sessions.mjs` 的 token 正则写死 `127.0.0.1:3080`，而本机引擎在 3083（`启动.vbs:11`），所以这两个脚本在本机拿不到 cookie；本次建会话是走同一套 RPC 手工完成的。
- 2026-11-10（决策）：换外观走「末尾皮肤段 + 设计令牌」，不重写 `styles.css`（4900 行里混着布局与 JS 依赖的尺寸）；组件规则一律带 `html[data-theme]` 前缀，靠「同特异性 + 文件末尾」压过历史覆盖，能不写 `!important` 就不写。
- 2026-11-10（坑）：`styles.css` 有 78 行 `!important`（70% 在启动页）；`#scenebar` 的背景/边框是 `!important`，皮肤段里也必须 `!important` 才压得住；启动页的 `position:fixed / z-index:30000 / flex 居中` 三处同理，别想着改成 static。
- 2026-11-10（坑）：`.view-ta` 是 `<textarea>`，会被全局 `textarea` 输入框阴影环命中 ⇒ 必须显式 `box-shadow:none`，否则预览区会凭空多一圈"边框"（白底上最显眼）。
- 2026-11-10（决策）：默认主题 dark → light，键改 `guiTheme.v2` 并做一次性迁移（light/system 保留、dark 落回浅色）——旧 `dark` 只是当时的默认值，不代表用户偏好。
- 2026-11-10（坑）：改 `renderer.js`（主题默认、preload 之外的启动逻辑）热更新不生效，只有整页重载才会重新执行；`刷新面板.mjs` 只重拉 `styles.css` 与 `renderers.js`。要整页重载：先 `(Get-Item 外壳\renderer\topbar-status.js).LastWriteTime = Get-Date`，再跑 `刷新面板.mjs all` —— 主进程有它的 mtime 哨兵，会 `reloadIgnoringCache()` 主窗口。
- 2026-11-10（坑）：`check-gui.mjs` 第 10 项报 3 个 FAIL（`外壳\.idea`、`pnpm-lock.yaml`、`pnpm-workspace.yaml` 不属于目录契约），这三个是本次之前就有的，别当成自己改坏的。
- 2026-11-10（坑）：**深色画布类面板不能跟主题令牌**。「命令」的记忆神经元画布是 3D 星空、节点配色写死在 `renderers.neuron` 的 `COLOR` 表里；HUD 原来用 `var(--text)`，默认主题切浅色后近黑字糊在深底上（统计/按钮/详情卡标题全不可读），搜索框还被全局 input 规则刷成白条。修法：皮肤段 §⑫ 让这块 HUD 走「深色玻璃 + 固定浅色字」，并把 `.kneu-search` 从全局 input 的 `:not` 链里排除（那条链特异性 (0,4,2)，普通类规则压不过）。以后遇到 canvas / video / 终端类面板，先判断"底色是不是自绘的深色"，是就别用令牌。
- 2026-11-10（改判）：上一条的判断被宿主否掉——**他要的就是整块浅色**，不是"深色舞台 + 深色玻璃"。做法改成：画布颜色从绘制代码里抽出来，集中到 `renderers.neuron` 的 `KNEU_LIGHT` / `KNEU_DARK` + `COLOR` / `COLOR_LIGHT`；浅色画在白纸上（不铺深色背景、不压暗角、星点退成纸面尘埃、标签白底深字、连线按类型走石板/青/蓝），深色维持原星空；HUD 在 §⑫ 里给两套玻璃；图例点由 `paintLegend()` 跟主题重刷。**判据更新**：不是"深色画布就保持深色"，而是"自绘画布也必须能换皮"——颜色一律集中成常量表，绘制代码里不留 hex。这次返工就是因为颜色散落在 30 处 `rgba(...)` 里。
