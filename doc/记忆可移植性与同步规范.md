# 记忆可移植性与同步规范（v1 · 2026-11-13）

> 本文件回答一个问题：**记忆数据怎么"丢不了、换得了"**。
> 上位规范 `doc/记忆体系规范.md` 定层级与字段，本文件定**分发**——迁移 / 同步 / 兜底 / 换引擎四种场景的最小闭环。
> 工具：`工具/记忆打包.mjs`（零依赖，Node 内置模块）。

## 0. 一条总原则

**换机器丢不丢，取决于同步策略，不取决于存储格式。** 换 SQLite / 向量库，新机器上的 `.db` 同样不存在。本体系的选择：

- **git 管"机制与公开记忆"**：场景记忆真源 md 入库，新机 `git clone` 即回。
- **记忆包管"兜底与换机"**：`记忆打包.mjs` 打全量快照，**连 gitignore 掉的归档\、项目.json、身份卡画像都包进来**——git 救不回的它救。
- **派生可重建（I2）**：索引 / 近期 / 身份卡画像 / 定论草案，删了都能一条命令重算，不做备份重点。

## 1. 四种场景与 SOP

| 场景 | 例子 | SOP |
|---|---|---|
| **迁移**（一次性换主力机） | 旧电脑 → 新电脑 | ① 旧机 `记忆打包.mjs 打包`（或直接 git clone）② 新机 `恢复 --包`（或 clone + 拷贝）③ `环境适配 --apply` ④ `索引 --all` + `check --all` ⑤ 逐面板 `换会话 --go`（sessionId 是机器凭证，不搬） |
| **同步**（双机并行） | 公司机 + 家里机都写记忆 | git 为主：开工 `pull`、收工 `push`；**同一场景同一时段只在一台写**；冲突让 git 按行 merge（md 的优势，二进制库做不到）；记忆包每周打一次兜底 |
| **兜底**（git 也丢了） | 硬盘坏 / gitee 号出问题 | 靠记忆包：离线存 U 盘 / 网盘。`核对 --包` 定期查"备份过期了吗" |
| **换引擎**（DSH 升级/换实例） | 引擎 0.2.x 升级，home 布局变 | 不搬 `.dsh` 目录，走记忆包 恢复 + 环境适配；引擎本体整目录替换，与记忆无关 |

## 2. 命令手册

```powershell
node 工具\记忆打包.mjs 打包 [--到 <目录>]      # 全量快照 → <工作台根>\记忆包\记忆包-<时间戳>\（含清单.json + 恢复说明.md）
node 工具\记忆打包.mjs 核对 --包 <目录>         # 包 vs 当前：一致/变了/缺失/新增；「缺失」exit 1（变了/新增只报告）
node 工具\记忆打包.mjs 恢复 --包 <目录>         # 先自动把当前快照到 记忆包\恢复前备份-<时间戳>\，再覆盖（可回滚）
node 工具\记忆打包.mjs 升版                    # 落地/更新 _共享记忆\schema.json（数据契约版本，幂等）
```

- 打包范围：`场景记忆\` 全量（含归档、_共享记忆）+ 每个已登记项目的 `memory\`；跳过没登记 `memoryRoot` 的项目并在说明里写明。
- **界面入口（2026-11-13）**：顶栏「记忆包」胶囊（文件夹右边）——打包 / 核对 / 恢复 / 升版 / 打开目录；恢复需 6 秒内二次确认，且工具会先自动快照当前。命令行走 `外壳\main.js` 的 `topbar:mem-*` IPC，同样落到本工具。
- 核对口径：只按 sha256 比"存在性与内容"；「缺失」= 当前比包少（可能误删）→ exit 1，可脚本化拦截；「变了」= 正常演进，不判错。
- 恢复口径：包先自校验（坏包拒绝恢复）；当前数据必先自动快照；项目记忆按**本机** `项目.json` 的路径落位（包里的旧机绝对路径不直接用）。

## 3. 数据契约版本（schema.json）

- 位置：`场景记忆\_共享记忆\schema.json`，字段 `schemaVersion`（当前 **2**）。
- 规则：**加字段/改结构时版本 +1**，工具向前兼容读；`check --all` 每次校验并 ⚠ 提醒（老数据撞新工具是"换机后莫名其妙"的第一来源）。
- 恢复时包版本 > 本工具版本 → 拒绝恢复并提示换新工具；打包永远写当前工具版本。
- 首次落地：`记忆打包.mjs 升版`（2026-11-13 已执行，v2）。

## 4. 双机同步纪律（git 为主）

1. 开工先 `git pull origin main`，收工先 `git push`；记忆 md 是文本，冲突按行 merge。
2. **同一场景同一时段只在一台机器写**——两台同时写同一场景，check/索引会在两边各自通过但内容分叉，只能人工合。
3. 派生文件（`_索引.json`/`_近期.md`/定论草案）**不入同步决策**：谁跑 `索引 --all` 谁重算，冲突直接覆盖。
4. `项目.json` / `记忆地图.json` / `面板交接\` 是本机登记（盘符绝对路径），gitignore 掉了——双机各有各的，靠 `环境适配 --apply` + 接入项目重建，**不要互相拷贝**。
5. 每周 `记忆打包.mjs 打包` 一次 + `核对 --包` 上一次的包，确认备份没断代。

## 5. 已知边界（不做的与为什么）

- **不做自动定时备份**：记忆体量小（当前 285 个文件），收工前顺手打一次包即可；定时任务等双机并行成为常态再上。
- **不做 zip/加密**：零依赖优先；包要离线存放时由用户自己压缩/加密。
- **恢复=整体覆盖**：按文件 sha 覆盖，包里有而当前多的（新增）不动；"恢复到某个时间点"请用 git（文本天然支持）。
- **不搬 sessionId**：会话绑定是机器凭证（AGENTS.md 已知风险），换机必须逐面板 `换会话 --go` 重建，搬 id 无效。
