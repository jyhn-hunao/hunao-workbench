# 分层设计理念 —— 大脑 / 手 / 性格 / 人

> 这份文件只回答一件事：**新功能该写在哪一层、写成什么样**。写错层的功能，代码再干净也是 bug。
> 机制怎么连通（台账 / 注入 / 回流）见 [`00-核心机制/三-场景体系.md`](../00-核心机制/三-场景体系.md) 第 7.5 节，本文件不重复。

## 1. 四层各是什么

| 层 | 是谁 | 唯一职责 | 真源 |
|---|---|---|---|
| **大脑** | 人格场景「胡闹的大肥鱼」 | **决定**：看什么、学什么、派谁做、要不要办 | `外壳\data\pet\设置.json` 的 persona + routes；人格场景记忆 |
| **手** | 各业务场景（生活 / 社交 / 程序开发 / 本地电脑 / 记忆 / 控制台） | **执行**：只提供工具与通道，取数据、跑脚本、发消息 | `外壳\scenarios\*.json` + 各场景 SKILL + `工具\` |
| **性格** | 人格卡 | **定味**：语气、称呼、边界 | `设置.json` 的 persona（每轮由记忆回响注入） |
| **人** | 用户（胡闹） | **拍板**：多个候选、动钱动账号、不可逆 | 会话回执等人点头 |

一句话：**大脑想，手做，性格定味，人拍板。**

## 2. 新功能落在哪层（判据）

| 你要加的东西 | 落哪 | 不该落在哪 |
|---|---|---|
| 「要不要 / 该不该 / 先做哪件」这类判断 | 大脑（人格规则、路由、派发） | ⛔ 不许写进业务场景脚本 |
| 「能不能做 / 怎么调接口 / 走哪个通道 / 走哪条命令」 | 手（对应场景的工具或 SKILL） | ⛔ 不许写进人格卡 |
| 「说话语气 / 称呼 / 口头禅 / 主动度」 | 性格：只在人格卡 | ⛔ 别的场景不许写第二份 |
| 「拿不准时怎么办」 | 人：回执到会话等人点头（`发消息.mjs --to 胡闹的大肥鱼`，脚本 `exit 3`） | ⛔ 不许自主决策、不许默认选一个 |
| 「这双手会什么」的说明 | 手的能力表：`外壳\场景能力.js` 的 `MECHANISMS` | ⛔ 不许只写在 SKILL 里不登记 |

## 3. 四条反例（出现就是偏了）

1. **手越位**：生活场景里写「我看这条不错就学这条」「我挑了 3 条里最好的」→ 应改成取回候选、标必刷，投给大脑定看哪条。
2. **大脑甩锅**：人格回「B 站的事归生活管，我下不了手」→ 应改成当场派给生活、拿回执再说结果。⛔「这不归我管」在任何场景都是错话。
3. **大脑看不见手**：只加了脚本、没写 `MECHANISMS` → 注入里没有它，大脑永远不知道这双手会干这个，功能等于不存在。
4. **性格分叉**：在通道里另写一套情绪数字 / 语气规则，或让别的场景改人格卡 → 同一个人在两处说话不一样。

## 4. 开发完必答三问

1. 这个功能是**决定**还是**执行**？决定归大脑，执行归手——写错层就是越位。
2. **大脑怎么知道这双手会这个？** 进没进 `MECHANISMS`，跑没跑过 `场景能力.mjs 生成`？
3. **拿不准时它会把问题交回给人吗？** 有没有 `exit 3` / 回执路径，而不是自己选一个？

三问有一个答不上，先别提交。

这几条**不是靠自觉**：`node 12-源码照搬\外壳\scripts\测试.mjs --only layers` 会扫所有场景 SKILL，出现「我挑了 / 我决定了 / 这不归我管 / 你去那个场景」这类句式直接红灯；`doc\分层设计理念.md` 或 `AGENTS.md` 的入口被删也会报 ✗。

## 5. 两个容易搞反的边界（已定，不许翻案）

- **社交场景只做通道与消息**：好友关系、情绪曲线由代码固定、面板只读；人格设置归人格场景。
- **生活场景只做取素材与通平台**：看什么、学什么由大脑定；学习笔记落人格层 `记忆\学习\`，来源（系列 / UP / mid / BV / 日期）写进首行。

|---|---|

| 手 / 这双手 | 任一业务场景的 AI 会话 + 它的脚本与通道 |
