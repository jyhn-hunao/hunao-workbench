# 本仓提交准则（项目层落地）

> 上位文件：《附录-提交准则》`~/.dsh/standards/specs/附录-提交准则.md`（v1.0）。
> 本文件只写**本仓的值与差异**，不复制通用正文；没写到的按上位文件执行。
> 冲突裁决：用户当轮指令 > 铁律层 > 本文件 > 个人偏好层。

## 1. 一个提交放什么（本仓场景）

| 场景 | 一个提交放什么 | 不要放什么 |
| --- | --- | --- |
| 文档板块修订 | 一个板块（或一个主题贯穿多个板块）的说明 + 对应配图 | 顺手改代码、顺手改 `README` 排序 |
| 场景配置调整 | 一个场景的 JSON + 它的定位卡 + `_场景身份索引.md` 对应行 | 多个场景一起改（除非是同一批新增） |
| 外壳改动 | `main.js` / `preload.js` / `renderer/` 里同一行为变化 | 整文件格式化、无关段落重排 |
| 工具脚本 | 一个脚本的一次行为变化 + 用法注释 | 顺手改另一个脚本 |
| 规则改动 | `AGENTS.md`、`doc/` 下的规则调整 | 混入业务/壳代码 |
| 依赖与锁文件 | 依赖版本或锁文件 | 与功能改动混提交 |

判断口诀：**只回滚这一个提交，界面还能启动、场景还能对上会话吗？** 不能就是没切好。

## 2. 粒度阈值（沿用通用，收紧一条）

| 维度 | 本仓值 | 说明 |
| --- | --- | --- |
| 文件数 | 理想 ≤ 8，硬上限 12 | 超了先拆，拆不动在正文写「为何不可拆」 |
| 变更行 | 理想 50–300，硬上限 400 | 纯文档按同一口径 |
| 额外收紧 | `12-源码照搬/外壳/main.js`（单文件 260 KB）单次 diff > 200 行必须拆 | 先提交「定位 + 结构说明」，再提交行为变化；否则没人能审 |

## 3. `type` 词表（小写）

`feat` 新功能 / `fix` 缺陷修复 / `refactor` 行为不变的重构 / `perf` 性能 / `test` 测试 / `docs` 文档 / `style` 纯格式 / `build` 构建与依赖 / `chore` 杂项 / `revert` 回滚。

## 4. `scope` 词表（本仓专用，不另造）

| scope | 覆盖范围 |
| --- | --- |
| `docs` | `00-核心机制/` 至 `13-公开情报/`、`总纲.md`、`README.md`、`新手必读.md`、`_索引.md`、`模板/`、`配图/` |
| `shell` | `12-源码照搬/外壳/` 主进程、预加载、渲染器 |
| `scenario` | `12-源码照搬/外壳/scenarios/` 场景 JSON 与定位卡 |
| `scripts` | `12-源码照搬/外壳/scripts/` |
| `tools` | `12-源码照搬/工具/` |
| `plugin` | `12-源码照搬/插件/` |
| `engine-conf` | `12-源码照搬/引擎数据/.dsh/` 里入库的配置与场景记忆 Markdown |
| `rules` | `AGENTS.md`、`doc/`、`.env.example` |
| `repo` | `.gitignore`、`LICENSE`、远程与分支约定 |

新增 scope 须先改本表再使用；一次提交涉及多个 scope 时，先考虑是不是该拆。

## 5. 消息格式

> **适用范围**：本节只约束 **AI 产出/代办的提交**。用户在 git 工具里手写的提交信息属于个人自由，不合格式也不算违规；任何界面、hook、脚本都不得以格式为由校验、改写或拦截（2026-11-12 用户明确；外壳 git 面板的格式拦截已按此移除）。
```
type(scope): 中文摘要（≤50 字符，动宾结构，不加句号）

为什么：
改了什么：
影响面：
验证：
风险/回滚：
```

- 变更 > 50 行、跨 `shell`/`scenario` 两层、改启动链路或改规则时，正文五段必写。
- 反例：`1`、`update`、`fix bug`、`优化。`、`同步一下`。
- 正例：`fix(shell): 修正面板刷新后会话标题丢失`、`docs(rules): 落地项目层提交准则`。

## 6. 提交前 gate（本仓可执行）

- [ ] `git status` 干净以外的改动都属本次意图；**不 `git add -A`**，按文件或 `git add -p` 暂存。
- [ ] 改了场景 JSON：`node 12-源码照搬\外壳\scripts\sessions.mjs --check` 通过（没跑就写明原因）。
- [ ] 改了外壳或脚本：`node 12-源码照搬\外壳\scripts\自检.mjs` 跑过并把结果贴进正文。
- [ ] 改了发布相关：`node 12-源码照搬\工具\发布前检查.mjs` 通过。
- [ ] 没有 `server.log`、`引擎数据/.dsh` 运行时文件、密钥、`node_modules` 混进暂存区。
- [ ] `git diff --cached --stat` 未超第 2 节阈值。

## 7. 远程策略

- `origin` 只指向 gitee `https://gitee.com/ydcy_studio/hunao-workbench.git`。
- 原仓 `mashanglinyu/luanyujia-workbench` 保留为 `upstream`，push URL 置为 `DISABLED`，**不向其推送**（用户 2026-11-10 明确要求）。
- 本仓获常驻 push 授权：AI 可自主 `git push origin main`；不 force push、不推 `custom-local`、不推 tag，除非当轮明确要求。
- 推送失败先 `git fetch origin` 看远端，用 rebase 前移后重推，不改写已推送历史。

## 8. 禁止项

| 禁止 | 原因 |
| --- | --- |
| 每次工具动作/每个文件一提交 | 碎提交不可回溯 |
| WIP、临时备份、`fixup!` 进主线 | 污染历史，未推送前用 `--amend` 收敛 |
| 向原仓 `mashanglinyu/luanyujia-workbench` 推送 | 本仓是个人分支，只落 gitee 的 `hunao-workbench` |
| 提交 `12-源码照搬/引擎/`（外部引擎整目录） | 500 MB 级外部依赖，已在忽略范围外人工把关 |
| 提交 `.env`、token、真实会话数据 | 泄密；`server.log` 里就含 token |

## 9. 拆分示例（本仓真实场景）

- 反例：一次提交同时改 `AGENTS.md`、`scenarios/command.json`、`main.js` 的面板刷新逻辑——三层三意图，回滚任何一层都会让另两层不自洽。
- 正例：① `docs(rules): 落地项目层 AGENTS 与提交准则`（只加规则文件）；② `fix(shell): 面板刷新后重读场景 JSON`（只动 `main.js`）；③ `chore(scenario): 更新命令场景的会话绑定`（只动 `scenarios/command.json` 与索引表一行）。
