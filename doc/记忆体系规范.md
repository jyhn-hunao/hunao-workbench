# 记忆体系规范（v4 · 2026-11-13）

> 本文件是记忆体系的**规范性**（normative）文件：定层级、定字段、定闸门、定迁移。
> 上位原理见 `00-核心机制/二-记忆机制.md`（为什么必须分层）；日常怎么用见 `12-源码照搬/说明/记忆约定.md`；
> 历史设计见 `doc/记忆能力改造设计.md`（2026-11-11 定稿，其中 P1/P3 已完成）。
> 冲突裁决：**壳与工具的实际行为 > 本规范 > 历史文档**；改了行为必须同批改本规范，不许"代码一套、文档一套"。
> v4 增补（2026-11-13，对"四个难点"体检的落地）：依赖感知归档、遗忘分级（归档降权≠删除）、冲突字段（取代/过期/相关）落地、真实证据 + 巩固回链、五项新审计、§〇 截断保尾、写后自动沉淀。

## 0. 四条不变式

任何改动先过这四条，不过就不合规范：

| # | 不变式 | 判据 | 违反的典型 |
|---|---|---|---|
| I1 | **单一真源** | 一个事实只有一处正文（`.md`）；别处只能放指针 | 同一条结论既写 §五 又写决策文件；记忆与台账各写一份数字 |
| I2 | **派生可重建** | 删掉所有派生文件，一条命令能全量重建且内容等价 | 手改 `_索引.json`、手编 `_近期.md`、把登记表当数据 |
| I3 | **每层有预算** | 见 §2 表格；超预算必须搬 `归档\`，不是"下次注意" | §〇 写成周报；主文件 25 KB 还在追加 |
| I4 | **结论可自证** | 近 30 天的决策/坑必须带 `evidence` 或 `no_evidence` | 只写"已修好"，三个月后无人能判还成不成立 |

## 1. 分层模型（L0–L7，含 L3.5 巩固层）

| 层 | 文件 | 回答什么问题 | 谁写 | 谁读 | 预算 | 生命周期 | 性质 |
|---|---|---|---|---|---|---|---|
| **L0 身份** | `<场景>\身份卡.md`、`场景画像.md` | 我是谁 / 边界 / 接口 | `场景记忆.mjs init/stamp` | 开场、神经元 | ≤2 KB | 场景变更时重盖章 | 派生（可重建） |
| **L1 交接** | `<场景>\场景私有记忆.md` 的 `§〇` | 干到哪 / 下一步 / 卡点 | 人（`交接` 命令） | 每轮开场必读 | **≤4 KB** | 每次交接**覆盖** | 真源 |
| **L2 骨架** | 同文件 `核心职责` + `§一~§四` | 职责边界 / 接口 / 历史约定 | 人，**只追加** | 按需 | 主文件 ≤12 KB（>25 KB ✗） | 季度复核 | 真源 |
| **L3 情景** | `<场景>\决策\`、`坑\`、`通知\<日期>-<slug>.md` | 一条结论 + 证据 | **只走 `写`** | 按需 / 近期 / 下钻 | 单篇 **≤2 KB**，每类 ≤30 篇 | 180 天搬 `归档\`（被 `定论.sources` / 他条 `evidence` 引用的**不搬**，`--强搬` 例外） | 真源 |
| **L3.5 定论（巩固层，2026-11-13）** | `<场景>\定论\<主题>.md` | 从多篇同主题情景抽象出的**一条结论/规律** | `沉淀` 出草案，AI 归纳后把 `status` 改 `confirmed` | 下钻 / 召回 / 每轮注入 | 单篇 ≤2 KB | `confirmed` 不被 `--force` 覆盖 | 草案派生 + 结论真源 |
| **L4 近期** | `<场景>\_近期.md` | 最近发生了什么（压缩摘要） | `近期记忆.mjs 生成` | 开场注入 | ≤2 KB（7 天 / 8 条） | 每次生成覆盖 | 派生 |
| **L5 项目** | `<场景>\项目记忆\<项目>.md`（薄卡）+ `<项目根>\memory\<8类>` + `_索引.json` + `_词表.json` | 项目级长时记忆 | `记忆.mjs 写/init` | `recall` / 下钻 | 卡 ≤1.5 KB，篇 ≤2 KB | 类目内归档 | 真源 + 派生索引 |
| **L6 共享** | `_共享记忆\` 的 `areas\*.md`、`索引.json`、`项目.json`、`记忆地图.json`、`_待办.md`、`_跨场景通知.md`、`冲突.md`、`提交链\` | 跨场景事实与路由 | 工具优先，登记表手工 | 按需 | 单文件 ≤4 KB | 持续 | 登记表（半派生） |
| **L7 索引/关联** | `<场景>\_索引.json`、主题节点 | 机器可读清单 + 联想 | `场景记忆.mjs 索引` / 渲染派生 | 神经元 / 巡检 | 单场景 ≤100 KB | **每次写后** | 派生 |

> L7 索引**含归档条目**（`kind: "归档"`）：归档 ≠ 从索引消失，只是召回默认排除（`--含归档` 时 ×0.3 降权并标注）。

**分层判据**（沿用二-记忆机制）：`这东西谁会读、多久读一次？`
每轮都读 ⇒ 注入层（必须短）· 每场开场读 ⇒ L1/L4 · 需要才查 ⇒ L2/L3/L5 · 机器读 ⇒ L7。
同主题 ≥3 篇 ⇒ 先 `沉淀` 成 L3.5 草案，再让 AI/人写一句 `## 结论`（`confirmed` 后才算"学会了"）。

## 3. 命名与标识

| 对象 | 权威来源 | 规则 | 例 |
|---|---|---|---|
| 场景目录 | `scenarios/<id>.json` 的 `name` | 中文场景名，目录名 == 场景名 | `程序开发` |
| 场景 id | 同上 `id` | 小写英文/短横线 | `code-dev` |
| 面板 id | 同上 `panels[].id` | 只用于绑定，不写进记忆正文 | `cd-ai` |
| 记忆 ID | 文件路径 | `<场景>/<类>/<YYYY-MM-DD>-<slug>` | `程序开发/决策/2026-11-13-场景记忆分条化.md` |
| slug | 工具生成（`slugOf`） | ≤32 字，中文优先，去标点，`-` 分词，截断落在词边界 | `场景记忆分条化-一条一个文件` |

## 4. 字段契约（frontmatter）

### 4.1 场景分条（决策 / 坑 / 通知）

```yaml
---
title: <一句话结论，≤40 字，不写过程>
date: YYYY-MM-DD
tags: [决策, <主题词 0–2 个>]
evidence:                      # 二选一：证据 或 明确交代
  - 12-源码照搬/工具/记忆.mjs::function cmdDoctor
# no_evidence: <为什么这条不需要证据>
# relate: [bilibili, command]  # 逻辑多归属（见 §6）；目标场景不存在时 check 会报
# supersedes: 程序开发/决策/2026-11-10-xxx.md   # 取代旧条目；指向不存在的 ID 时 check 会报 ✗
# expires: YYYY-MM-DD          # 只对"临时约定"有效；过了日期召回/注入自动跳过，check 报 ⚠
---
```

| 字段 | 必填 | 约束 | 谁校验 |
|---|---|---|---|
| `title` | ✅ | ≤40 字；与既有条目不重名（同名拒写） | `写` |
| `date` | ✅ | `YYYY-MM-DD`；缺省取当天 | `写` |
| `tags` | ✅ | 第 1 个必须是类标签（决策/坑/通知）；其余为主题词 | `写` + `check` |
| `evidence` | ✅/`no_evidence` | `路径::片段`，片段 ≥8 字符 | `check` / `体检` |
| `relate` | 选填 | 场景 id 列表，目标必须存在 | `写 --相关` + `check` |
| `supersedes` | 选填 | 指向存在的记忆 ID | `写 --取代` + `check`（悬空 ✗） |
| `expires` | 选填 | 未来日期 | `写 --过期` + `check`（已过 ⚠）+ 召回/注入过滤 |

### 4.2 项目记忆

`category` 由目录决定，固定 8 类：`architecture`、`interfaces`、`runbooks`、`pitfalls`、`decisions`、`function_realize`、`sql-log`、`handoffs`（另有 `archive`）。
必填同 4.1；另加 `description`（≤240 字，召回打分用）与 `tags`（来自 `_词表.json`）。

### 4.3 标签规范（当前最大质量债）

现在 114 条分条（85 在册 + 29 归档）里，多数只有类标签，仍有若干条标签是**整句描述**（如 `[决策, 场景记忆 + 项目记忆的体检、交接、归档、…]`）。这会让联想边糊成一团，必须收敛：

| 类型 | 来源 | 数量 | 约束 |
|---|---|---|---|
| 类标签 | 目录（决策/坑/通知） | 固定 1 个 | 手写不了 |
| 主题标签 | `_词表.json` / 场景 `_主题词.md`（P0 建，≤50 词） | ≤2 个 | 必须是词表里的词 |
| 自由词 | 人写 | ≤1 个 | ≤8 字，禁标点、禁整句 |

校验（P0）：`写` 时若某个 tag 长度 >12 或含 `，。、+` → 拒写并提示改用主题词；`check` 报"标签合法率"（目标 ≥90%）。

### 4.4 写入闸门：不确定就问（2026-11-13 新增）

记忆最贵的错误不是写少了，是**写错还写死了**：听来的一句、推断的一段、和旧条目一字之差却是另一件事。所以写入前过三道闸，全部由 `场景记忆.mjs 写` 执行：

| 闸 | 触发 | 行为 | 退出码 |
|---|---|---|---|
| **相似闸** | 同场景已有条目与新标题的二元词 Dice 重合 **≥0.5** | 拒写，列出最像的 3 条；确认是同一条 → 直接改那一篇；确实是两件事 → 加 `--不是同一条 "词：区别"` | 3 |
| **标签闸** | 任一标签 >12 字、含 `，。、；：！？+`、或超过 3 个 | 拒写，要求改成词表里的主题词 | 2 |
| **证据闸** | 决策/坑没有 `--证据` | 允许写，但打 ⚠；`体检` 对近 30 天缺证据判 ✗ | — |

**待确认队列**（拿不准的唯一合法去处）：

```powershell
# 不确定 ⇒ 不落正式条目，进 <场景>\_待确认.md，当轮就问用户
node 工具\场景记忆.mjs 写 --场景 程序开发 --类 决策 --标题 "…" --要点 "…" --证据 "…" \
     --不确定 "这句是用户口头说的，还是要写进规范？"

node 工具\场景记忆.mjs 待确认 --场景 程序开发            # 看队列（编号）
node 工具\场景记忆.mjs 确认   --场景 程序开发 --序号 1   # 用户点头 → 转正（自动索引 + check）
node 工具\场景记忆.mjs 确认   --场景 程序开发 --序号 1 --放弃   # 用户否掉 → 不留痕
```

**同名不同物（词像义不同）**：`--不是同一条 "工作区：这里指文件区，不是会话工作区"` 会写进 frontmatter `distinct: [工作区]` 和正文 `## 消歧`。联想层计算主题时**丢弃这个词及其二元词**——不靠算法猜语义，靠作者显式声明。一条最多 12 个消歧词，超了说明该拆条。

**收工**：`node 工具\场景记忆.mjs 收工 --场景 X` = 重建索引 + 重算 `_近期.md` + `check` + 报待确认条数；**exit 0 才算收工**。每个场景定位卡已写入同一段"记忆自主管理"（2026-11-13）。

### 4.5 定论（L3.5）：从情景抽象出规律（2026-11-13 新增）

`沉淀 --场景 X` 用"主题种子"聚类（不是两两相似并查集，避免 40 条连成一个巨簇）：取标题/标签里中等频次的词（≥3 且 ≤8 条），每个词收一组、组内 ≤8 条、组间不重叠；主题名取组内 2–5 字高频短语（`df × 长度²`），凑不出明确主题就**跳过，不硬造词**。

产物 `<场景>\定论\<主题>.md`：

| frontmatter | 含义 | 谁维护 |
|---|---|---|
| `kind: 定论` | 层标识 | 工具 |
| `topic` / `sources` / `evidence` / `date` / `generated_by` | 主题、来源条目、证据 | 工具 |
| `status: draft\|confirmed` | 草案 / 已确认 | AI 归纳后手改 |

正文：`## 摘要` 每条来源一句（标题 + 首条 description/要点 + 相对路径，方便一页看完全貌）；`## 结论` 只放**被 ≥2 条来源重复提到**的共识原句，没有就写"待归纳：各说各的，需要一句共同结论；不硬凑"。

**证据与回链（2026-11-13 起）**：`evidence` 取源条目要点**原文第一行**（≤60 字，可直接在源文件里 grep 命中，不再是标题前 8 字的形同虚设）；同时给每个源条目写回 `consolidated_into: 定论/<主题>.md`，`check` 校验回链指向的定论存在。

**确认**：AI/用户把一句真正的结论写进 `## 结论`，并把 `status` 改成 `confirmed`。`沉淀` 对已存在文件默认跳过；`--force` 也只重算 `draft`，**`confirmed` 永不覆盖**。⛔ `sources/topic` 由工具维护，别手改。

**自动触发**：`写`（写成功且 check 通过后，静默只报新增篇数）与 `收工 --场景 X` 都会顺带跑一次 `沉淀`，所以每个场景干完活就自动多出该有的定论草案；`沉淀` 失败不影响主命令退出码。

## 5. 生命周期与 TTL

```
新建 → 生效（索引） → 近期（7 天） → 常备（被引用/召回） → 归档（180 天） → 只读
        │              │                │                    │
        └ check 0      └ 注入开场        └ 主题/关联           └ 只进不改
```

| 动作 | 触发 | 命令 | 失败后果 |
|---|---|---|---|
| 写一条 | 有新结论（≤10 行 / 2 KB） | `写`（自动 index + check） | check ≠0 ⇒ 不算记录完成 |
| 刷新近期 | 每次写入后 / 每日开工前 | `近期记忆.mjs 生成 --all` | 开场注入的"近期"是旧的 |
| 刷新索引 | 每次写入后（已自动） | `场景记忆.mjs 索引` | 神经元看不到今天的内容 |
| 召回 | 需要历史细节 | `记忆.mjs recall --project "<根>" "<关键词>"` | 只能靠猜 |
| 归档 | 180 天 / 单类 >30 篇 | `整理 --days 180`（先 `--dry`；被引用不搬，`--强搬` 例外） | 目录越攒越厚，check 只告警 |

**遗忘分级（2026-11-13 起，分段近似，不上指数曲线）**：180 天硬截止 + `归档\` 只进不改 → 归档条目**仍进索引**（kind=归档），召回默认排除、`--含归档` 时 ×0.3 降权并标注"（归档，降权）"。即：**降权 ≠ 删除**，`expires` 已过的临时约定连 `--含归档` 也不出（真正失效）。
| 交接 | 换会话前 | `交接 --场景 X` | §〇 停在上一轮，新会话接不上 |
| 体检 | 每周 / 换会话前 / 发布前 | `记忆.mjs 体检`、`check --all` | 腐化在出包后才暴露 |

**不该写的**：过程流水、搜索结果、报错原文（只写"症状→根因"）、一次性约束、聊天记录。

## 6. 关联与多归属（v3 新增）

### 6.1 两个维度分开

| 维度 | 规则 | 存在哪 |
|---|---|---|
| **物理归属** | 唯一：文件在哪个场景目录就属于哪个场景 | 目录 |
| **逻辑归属** | 多：`relate: [场景id…]` 表示"这条也适用于 B站/命令"，**不复制文件** | frontmatter |
| **主题** | 派生：跨场景条目按 IDF 强命中 + 共享二元词聚类，标签取最长公共子串 | 运行时，不落盘 |

一条记忆因此可以：属于 1 个场景、被 N 个场景引用、挂在 M 个主题上 —— 这才是"一对多 / 多对一 / 多对多"，而不是把两个场景压成一条线。

### 6.2 权重（越用越亮）

| 信号 | 现状 | 取值 |
|---|---|---|
| 新鲜度 | ✅ | 45 天线性衰减 |
| 主题强度 | ✅ | 簇内 IDF 分合计，映射到线宽 0.7–1.7 |
| 被引用次数 | ⏳ P2 | `relate` 被指向次数 |
| 被召回次数 | ⏳ P3 | `memory\_召回.log` 统计；**≥50 次命中且覆盖 ≥3 场景**才回写边权，否则是无数据支撑的权重 |

### 6.3 什么时候才升级到 C（多归属落库）

不因为"想更像大脑"就上 C。触发条件三条同时满足：① `relate` 在 10 条以上记忆中使用；② 召回日志 ≥50 次；③ 出现"同一条记忆被 3 个场景反复要"。否则保持"目录唯一 + 逻辑引用"。

## 7. 检索协议（读序与预算）

**开场自动注入三段，总 ≤10 KB**：面板交接（`面板交接\<面板id>.md`，≤4 KB）→ 场景 `§〇`（≤4 KB）→ `_近期.md`（≤2 KB）。超预算截断并给全文路径；`§〇` 截断**保尾**——头部保留约 180 字节，末尾"下一步 / 卡点"小节必保（把下一步截掉等于白注入）。

**每轮强制回想（2026-11-13，引擎插件 `记忆回响`）**：挂 `agent/pre-step`，每次用户发言前按 `agent.sessionId → 外壳/scenarios/*.json panels[].sessionId` 反查场景，注入 `§〇`（≤1.6 KB，截断保尾）+ `_近期.md`（≤0.7 KB）+ 本轮关键词命中的 3 条条目路径（**排除归档与 `expires` 已过条目**）+ 本场景收工规则，总 ≤3 KB。同一轮只注入一次；查不到场景或任何异常 ⇒ 退回原结果，不阻断对话。装/退：`工具\记忆回响.mjs --apply/--off`，改完重启整壳。

**按需读序（不许跳步）**：

1. 要交接 → `读 --节 §〇`（已被注入就别再读）
2. 要"有哪些条" → `读 --节 五、坑与决策`（只拿下标）
3. 要具体结论 → 打开对应 `决策/坑\<日期>-<slug>.md`（单篇 ≤2 KB）
4. 要项目细节 → `recall --project`（按分数阈值，来了就记日志）
5. 跨场景协作 → `发消息.mjs` / `派发.mjs`（⛔ 不直接改别人记忆）
6. 只记得关键词、不知道是哪条 → `场景记忆.mjs 召回 --场景 X|--all --词 "<关键词>" [--条 5] [--含归档]`（标题 ×3 / 标签 ×2 / 正文 ×1 命中 + 45 天热度，按分排序给路径；默认排除归档与 `expires` 已过条目，`--含归档` 时归档 ×0.3 降权并标注；每次调用记 `_召回.log`）

**禁止**：整读主文件（>4 KB 就是浪费）、把 `_索引.json` 塞进上下文（那是给渲染器/巡检的）、`grep` 整个记忆目录当检索、把聊天正文抄进记忆。
