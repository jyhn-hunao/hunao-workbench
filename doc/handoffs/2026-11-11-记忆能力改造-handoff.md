## 1. 用户需求（原话要点，改义即错）

1. **主场景是开发**：每个项目有独立的记忆——业务知识、代码记录等。
2. **其他场景的记忆能力要保留**，用户未来会使用（B站 / 命令 / 自我复盘 / 本地电脑）。
3. 现在工作台的记忆能力与方式**不符合需求**：
   - 开发场景的项目记忆必须**自主记忆**：做完功能不能靠用户手动触发写回。
   - 开发场景**必须优先读**：编码规范 + 通用规则；其余记忆**按功能/问题检索**，不能把整个项目记忆塞进一个文档全量载入。
   - **记忆神经元**：场景记忆那部分（每场景独立）是对的；但**项目私有记忆没有画出来**；加载方式蠢（全量载入）大量消耗 token。
   - 建议形态：**每个场景只常驻"必须知道"的记忆**（工具、技能、人格/身份、别的场景必须知道的信息）；**具体记忆按用户的问题检索**。
4. 本对话已不干净 → 新会话接手，做需求设计 + 交接。

## 3. 设计约束（已定，不要再问）

1. **不改引擎**：全部落工作台的文件 / 脚本 / 技能 / 面板。
2. **每项目独立**：业务知识只属于该项目；场景私有记忆只放跨项目规矩（现有铁律不能破）。
3. **常驻层要小**：每场景常驻只含「工具 / 技能 / 人格与身份 / 其他场景必须知道的信息」。
4. **召回要按需、可解释**：命中理由（标题/标签/小标题/正文）要能说清；一次召回输出 ≤2 KB，只读命中文件。
5. **自主记忆**：任务完成、关键决策、踩坑时**自动写回**，不靠用户手动触发；写入必须同轮更新索引。
6. **新老项目都要能用**：新项目没有 mnemon 也要有记忆；老项目的 mnemon 可迁移。
7. **兼容现有结构**：`_共享记忆\索引.json / 项目.json / 记忆地图.json`、神经元面板、`project-onboarding` 流程。
8. **上次白屏事故后的硬纪律**（`自我复盘` §五 第 10–18 条）：改 `renderers.js` 必须 `node --check` + 假 DOM 加载自检 + 临时文件原子改名 + 整页重载后验证；不许在用户在用的时候连续热替换。

## 4. 设计草案（**待用户拍板**，不要直接实施）

### 4.1 三层

| 层 | 放什么 | 预算 |
|---|---|---|
| **L0 每轮常驻** | 工具/技能/人格/跨场景必知 + **检索入口一句话** | ≤2 KB |
| **L1 开工一次** | 定位卡（瘦身）+ 场景 §〇 交接 + **项目薄卡** | ≤5 KB |
| **L2 按需召回** | 项目记忆正文（项目仓库）+ 场景规则正文 | 召回 ≤2 KB；单篇 ≤6 KB |

### 4.2 项目记忆正文放项目仓库（记忆根可配置）

- 新项目：`<项目根>\docs\`（附录-文档记忆体系的骨架：MEMORY_INDEX.md + 8 类目录 + 各级 README）。
- `mlw` 这类已有 `doc\` 的项目：`<项目根>\doc\memory\`，避免两个 `docs/` 打架。
- 工作台侧只留：
  - `项目记忆\<项目>.md` = **薄卡 ≤1.5 KB**：项目根、记忆系统类型（docs / mnemon 历史）、索引路径、当前状态 3 行、最近 5 条记忆的**指针**（路径 + 一行标题）、召回命令。
  - `场景记忆\_索引\<项目>.json` = 紧凑索引（标题/标签/小标题/source），供召回用。

### 4.3 召回工具（建议 `工具\记忆.mjs`，零依赖）

```bash
node 工具\记忆.mjs index  --project <根>            # 扫记忆根 → 更新 _索引\<项目>.json
node 工具\记忆.mjs recall --project <根> "关键词"    # 输出 top 5-8：路径+标题+命中行（≤2KB）
node 工具\记忆.mjs write  --project <根> --type pitfall --title "…"   # 建文件+更新 README+索引
node 工具\记忆.mjs migrate --project <根> [--dry]    # mnemon → 记忆根（含分类建议清单）
```

- 召回算法：标题/描述/标签/小标题打分（BM25 或加权关键词）+ 正文 grep 兜底；输出带"命中理由"。
- 命中为空 → 直接读代码，不阻塞（附录 §7 纪律）。

### 4.4 自主记忆的触发点（待拍板）

- 候选：任务完成时（交付后自动写一条「功能流转/决策/坑」）、关键决策确认时、踩坑修复后、每 N 轮汇总一次。
- 写入必须过附录 §2「一眼判定」选目录；同轮更新 README + 索引。

### 4.5 神经元改造（与 4.2 联动）

- 短期：`索引.json` 补 `code-dev` 区域；项目节点按 `pr.memory` 生成「项目记忆」节点 + `project → memory` 边；owner 按场景名/面板 id 双匹配。
- 长期：改为画「项目 docs 索引 + 召回入口」，而不是引擎侧旧文件。
