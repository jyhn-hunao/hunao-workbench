# 机制可移植性规范（2026-11-12 立）

> 一条判据：**换一台机器 clone 下来，除了「只能重建、不能搬」的三样（会话 id、模型凭据、引擎与依赖），其余必须能一条命令回到可用。**
> 本文约束「以后新加的机制与工具」，不追认历史；历史问题见 `doc/跨机器移植兼容清单-2026-11-12.md`。

## 一、本机值只许出现在三处

| # | 允许的存放位置 | 例子 |
|---|---|---|
| 1 | **不入库**的运行时数据 | `引擎数据/.dsh/机器配置.json`、`sessions/`、`storages/`、`外壳/data/` |
| 2 | **可由环境变量覆盖的默认值**（默认值只许出现在一处） | `process.env.DSH_PORT \|\| 3083`，默认值只在 `启动.vbs` / `main.js` / `工具\环境.mjs` 各出现一次 |
| 3 | **可由自身位置推导的相对路径** | `path.dirname(fileURLToPath(import.meta.url))` |

除这三处，任何 `C:\`、`D:\`、盘符、用户名、绝对路径都不许写进入库文件。

**唯一例外**：`scenarios/*.json` 与 `_共享记忆/项目.json`。GUI 直接读它们，所以必须存真值；
但它们的真值由 `外壳\scripts\环境适配.mjs --apply` 在新机器上重算，**不是**靠人手工改。

## 二、六条硬契约

| # | 契约 | 违规判据 | 反例（本仓真实踩过） |
|---|---|---|---|
| 1 | 路径只从自身位置推 + `DSH_*` 覆盖，不用盘符字面量 | 入库代码出现 `[A-Z]:\\` | `发布前检查.mjs` 曾写死 `C:\Program Files\Git\...`；`sessions.mjs` 曾按 `HARNESS_DIR\.dsh` 找技能 |
| 2 | 端口只经 `工具\环境.mjs` 取，默认值只在一处 | 脚本里出现 `3083` / `31238` 字面量 | `自检.mjs` 曾写死 `[3083, 31238, 9876]`，改了 `DSH_PORT` 它仍探旧端口 |
| 3 | 入库配置只放逻辑名，或放真值但**必须**配自愈逻辑 | 存了绝对路径却没有对应的重算分支 | `项目.json` 两个项目全是 `D:\...`，且落在发布前检查白名单里，无人提醒 |
| 4 | 私有依赖必须可重建：源码放 `12-源码照搬\插件\` 并落位，或在 `说明\` 写明安装命令 + 版本 pin | 只存在于 `node_modules` | `dsh-token-guard` 源码在 `插件\省token守卫\`，但没有任何步骤把它链到 `profiles\web\node_modules` |
| 5 | 平台假设显式化：Windows 专属脚本集中放，入口显式判平台并给替代路径 | 无 `process.platform` 判断、无替代说明 | `启动.vbs` 是 WSH + UTF-16LE；`main.js` 依赖 `%APPDATA%\...\Recent`、`Program Files\nodejs` |
| 6 | 新工具必须三条：`--check`/`--dry` 只读模式、幂等可重复跑、一条接进 `自检.mjs` 的检查项；并登记 `_索引.md` | 无只读模式、重复跑会改数据、无自检项 | —（本轮新工具按此写：`环境适配.mjs` 三模式） |

## 三、加一个机制/工具时的 10 项自检

1. 路径：`import.meta.url` 推导 + `DSH_*` 覆盖，推导失败抛错（⛔ 不静默兜底）。
2. 端口：走 `工具\环境.mjs` 的 `port(name)`，不新写字面量。
3. 本机值：需要盘符/项目根/用户名时，读 `机器配置.json`，不写进代码。
4. 只读模式：`--check` 或 `--dry`，退出码能区分「通过 / 有缺口」。
5. 幂等：连续跑两次结果相同，第二次不产生多余备份。
6. 平台：Windows 专属就显式判 `process.platform === 'win32'`。
7. 依赖：新包若私有，源码进 `插件\`，并在 `说明\` 写安装与落位命令。
8. 自检：在 `自检.mjs` 加一条 check()，能让移植缺口一跑就现形。
9. 文档：`_索引.md` + `工具与技能目录.md` 登记（名字与用途一行）。
10. 验收：在真机上跑 `环境适配.mjs --check`，必须全绿；再造一次错（临时改坏一个路径）确认它真能报出来。

## 四、三条命令（换机器只记这三条）

```powershell
# 体检（只读，有缺口退出码 1）
node 12-源码照搬\外壳\scripts\环境适配.mjs
# 自愈（重算本机路径 + 私有插件落位 + 写 机器配置.json；幂等）
node 12-源码照搬\外壳\scripts\环境适配.mjs --apply
# 换机后重建 6 条会话（⚠ 会归档旧会话，确认旧会话不要了再用）
node 12-源码照搬\外壳\scripts\环境适配.mjs --rotate
```

## 五、为什么会话 id 搬不了（唯一必须重建的部分）

会话实体在 `引擎数据/.dsh/sessions/<cwd编码>/<会话id>/`，`cwd` 是本机绝对路径的编码形式；
把 id 搬到新机器，引擎里既没有那条会话、cwd 也对不上 ⇒ 面板必然空白。
只能在目标机重建，并回写三处（场景 json / 定位卡 / 名册）。`换会话.mjs <面板id> --go` 已经一条命令做完这四件事，
`环境适配.mjs --rotate` 负责批量。

## 六、界面入口（2026-11-12 新增）

配置属于**整台工作台**，所以入口在顶栏，不在任何业务场景里：

- 位置：顶栏最右 `⋯ 更多` → 「环境适配」折叠项。
- 内容：6 项状态（机器配置 / 路径对齐 / 插件落位 / bundle / 会话 / 端口）+ 「开始体检」「一键自愈」两个按钮。
- 数据：`main.js` 的 `topbar:env-check` / `topbar:env-apply` → `环境适配.mjs --json`；前端只负责渲染，不自己算路径。
- 边界：**界面不给 `--rotate`**。它会归档现有会话，只能由用户在命令行显式跑。
- 加新检查项时：只要在 `环境适配.mjs` 里 `add(名称, level, 明细)`，界面自动多一行 —— ⛔ 不要在 `topbar-status.js` 里再写一份判断逻辑（那就成了第二份真相）。
