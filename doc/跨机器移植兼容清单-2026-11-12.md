# 跨机器移植兼容清单 · 2026-11-12

> 问题：这台机器上的工作台，如果换一台机器 clone 下来（或在另一台机器上改完再 push），会出什么不兼容/报错？新加的机制与工具怎么保证在别的机器按环境生效？
> 结论：**git push 本身没问题；问题全在「另一台机器 pull 下来之后」**——引擎整目录、私有插件、6 条会话、所有项目绝对路径都不随仓库走。现有机制（`工具/*.mjs` 的相对推导 + `DSH_*` 环境变量覆盖）骨架是对的，缺的是「机器层配置 + 启动前自愈 + 契约 + 闸门」四层。
> 判定口径：把「能不能用」拆成三级——**起得来**（进程/引擎能启动）、**面板活**（6 个 AI 面板能钉到会话）、**机制生效**（记忆/派发/换会话/省 token 真能跑）。多数问题卡在第二、三级。

## 四、另一台机器「直接 push」的额外风险：验证盲区

如果指的是「在另一台机器改代码再 push」，除了上面 15 条，还有一个更麻烦的问题：**那台机器没有本机状态，四条验收命令里有三条跑不了或不作数**。

| 命令 | 在无状态的机器上 |
|---|---|
| `sessions.mjs --check` | 没有会话 → 恒红或恒空，**无法判断你的改动是否破坏了会话绑定** |
| `场景记忆.mjs check --场景 X` | 没身份卡/画像 → 恒红，无法发现真问题 |
| `自检.mjs` | 缺引擎时会走「复用 3083 外部实例」分支（`自检.mjs:42`），把别人的引擎当成自己的，**假绿** |
| `发布前检查.mjs` | 依赖 `git ls-files` 与 `os.homedir()`，能跑，但路径红线按那台机器的根算，结论与本机不可比 |

⇒ 跨机器提交的代码，等于「没有回归验证就进主线」。这是比配置错位更值得警惕的一条。

## 五、怎么让新加的机制与工具在别的机器按环境生效

核心判断：你的资产分两类——**代码**（跟着 git 走，天然可移植）与**状态**（会话 id、绝对路径、凭据、私有插件、profile 依赖，不跟 git 走）。可移植性 = 让状态在目标机器**可重建** + 让代码只依赖**逻辑名**、不依赖**本机值**。

现有骨架已经对了一半：`工具/*.mjs` 基本都做了 `path.dirname(fileURLToPath(import.meta.url))` + `process.env.DSH_*` 覆盖（如 `_共用-场景记忆.mjs:15-17`、`发布前检查.mjs:21-22`）。缺的是下面四层。

### L1 · 机器层配置（本机值只有一个出口）

- 新增 `12-源码照搬/引擎数据/.dsh/machine.json`（**不入库**，在 `.gitignore` 加一条），只放本机值：
  `workbenchRoot`、`driveRoots`、`ports{dsh,site,preview,webAi}`、`nodeExe`、`browserExe`、`engineVersion`、`projects{逻辑名→绝对路径}`。
- 新增 `12-源码照搬/工具/环境.mjs` 作为唯一读取口：`root(逻辑名)` / `port('dsh')` / `nodeExe()`。
  优先级固定为 **env > machine.json > 相对推导 > 抛错**。**不允许第四档静默兜底**（AGENTS.md §5「不静默兜底」）。
- 所有新工具禁止直接读盘符或 `os.homedir()` 拼路径，一律经这个模块。

### L2 · 启动前探测与自愈（把「本机值」在目标机器上就地重算）

新增 `12-源码照搬/外壳/scripts/环境适配.mjs`，分两个模式：`--check`（只读，退出码非 0 即不通过）、`--apply`（幂等改写）。它做四件事，正对上面 P1 的 5/6/7：

1. **路径对齐**：比对 `machine.json.workbenchRoot` 与仓库真实位置，不一致则重写 `scenarios/*.json` 的 `homeFolders`/`repo`/`drives`，以及 `项目.json` 的 `paths`/`memory`/`memoryRoot`/`memoryIndex`。
2. **会话重建**：调 `sessions.mjs --check` 拿到钉空的面板清单，逐个走 `换会话.mjs <面板id> --go`（它已经是一条命令做完四件事）。**会话 id 属于环境，只能重建，不能搬**——这是整套机制里唯一无法「搬」的部分。
3. **依赖可解析性**：读 `引擎/package.json` 对齐 `engineVersion`；遍历 `profiles/web/package.json` 的 `bundles`，逐个 `require.resolve` 校验（专门覆盖 `dsh-token-guard` 这类私有包），缺了就明确报出「装哪个、从哪装」。
4. **端口仲裁**：用 `machine.json.ports` 逐个探活，占用就**报错停下**，不自动顺延（自动换端口最容易连到别人的引擎）。

建议把 `--check` 挂进 `启动.vbs`：不通过就 `MsgBox` 退出，不带病启动。

### L3 · 契约（约束以后新加的一切）

写进 `AGENTS.md §4` 或单独一份 `doc/机制可移植性规范.md`，6 条硬规则：

1. **不写盘符字面量**：路径一律 `fileURLToPath(import.meta.url)` 推导 + `DSH_*` 覆盖；推导失败要抛错。
2. **不写死端口**：一律 `process.env.DSH_PORT || 默认`，默认值只允许出现在 `启动.vbs` / `main.js` / `.env.example` 三处；自检也必须读同一来源（现在 `自检.mjs:16` 是反例）。
3. **入库配置只放逻辑名**：`项目.json` 只存 `name`/`aliases`，物理路径交给 L1/L2 解析；必须落绝对路径的，只能进 machine.json。
4. **私有依赖必须可重建**：像 `dsh-token-guard` 这样的私有包，要么放进 `12-源码照搬/插件/`（AGENTS.md §2 已规定插件落这里）随仓库走，要么在 `说明/` 写清安装命令 + 版本 pin。**不允许只存在于 node_modules**。
5. **跨平台声明**：Windows 专属脚本集中到 `scripts/win/`，入口显式 `if (process.platform !== 'win32') die('...')`，并给出非 Windows 的替代路径（至少 `npm start`）。
6. **每个新工具自带三条**：`--dry`/`--check` 只读模式、幂等（可重复跑）、一条接入 `自检.mjs` 的检查项；并登记到 `_索引.md` 与 `工具与技能目录.md`。

### L4 · 闸门（发布前与移植后各跑一次）

- **给 `发布前检查.mjs` 加一条「可移植性」规则**：扫 `git ls-files` 里的 `scenarios/*.json` 与 `_共享记忆/项目.json`，出现 `[A-Z]:\\` 盘符字面量就报错。现在这两个文件在**白名单里**，等于主动放行——这是当前闸门最大的洞。
- **新增 `12-源码照搬/外壳/scripts/移植自检.mjs`**：按「只有 git 内容」的假设逐项判 P0/P1 的 10 条（引擎、版本、私有包、锁文件、6 条会话、json 路径、项目.json、凭据、Node、端口）。它应该在新机器上**必然失败若干条**——这就是移植待办清单。
- **移植完成的验收口径（4 条全绿）**：
  `自检.mjs` 5 项全通过 / `sessions.mjs --check` 6 个面板全命中 / 每个场景 `场景记忆.mjs check --场景 X` 通过 / `发布前检查.mjs` 0 命中。

## 六、新机器移植 SOP（8 步，按顺序）

1. `git clone`（只拿到方法与壳，**不含**引擎、会话、依赖、凭据）
2. 装 Node **24.x（>=24.9）**
3. 把引擎 **0.2.1-rc.3** 放到与 `外壳/` 同级的 `引擎/`（同级推导见 `main.js:28-32`，换盘符不用改代码）
4. `cd 12-源码照搬\外壳 && npm install`
5. `cd ..\引擎数据\.dsh\profiles\web && pnpm install`，并单独装回私有包 `dsh-token-guard`
6. `node 外壳\scripts\环境适配.mjs --apply`（重算本机路径、写 machine.json）
7. 双击 `启动.vbs`，等引擎起来后再逐面板 `node 外壳\scripts\换会话.mjs <面板id> --go` 重建 6 条会话
8. 跑上面 4 条验收命令；全绿再开始用

### 9.3 仍然「不能搬」的三样（设计如此）

1. **会话 id** —— 实体在 `sessions\<cwd编码>\<id>\`，cwd 是本机路径的编码形式；只能在新机器重建（`--rotate` 或逐面板 `换会话.mjs --go`）。
2. **模型凭据**（`.credentials.yaml` / `.anonymous-user-id`）—— 新机器重新登录。
3. **引擎本体 + profile 依赖** —— 新机器自行安装，版本对齐 `0.2.1-rc.3`。

### 9.4 未验证

- 没有第二台机器做端到端演练（只做了假树 + 真机，没有真跑 GUI）。
- **顶栏界面未实跑**：只做了 `node --check` 与 `--json` 结构核对（6 行、level 齐全）。菜单项要**重启工作台**才出现——IPC 在 `main.js`/`preload.js`，热更新只覆盖 renderer；未重启时 `TB.envCheck` 不存在，整项自动不显示，不会报错。
- `--rotate` 未实跑：它会归档现有 6 条会话，不在无人值守时动。

### 9.5 最易误用点

1. 把「可移植性」提示升成红线 —— 新机器 clone 完必然全红，这个检查会被直接关掉。
2. 以为 `--apply` 会重建会话 —— 不会；重建要显式 `--rotate`，且它**会归档旧会话**。
3. 以为 `机器配置.json` 该入库 —— 入了就等于把本机盘符与项目路径重新带回公开仓。
4. 手工改 `scenarios/*.json` 而不跑 `--apply` —— 会漏项目登记表与定位卡，面板仍指向旧路径。
