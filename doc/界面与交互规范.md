# 界面与交互规范（工作台落地）

> 上级通用规范：`12-源码照搬/引擎数据/.dsh/standards/specs/附录-界面与交互设计.md`；主规范 §14 是入口。
> 本文件只写**工作台的项目值、差异和反例库**，不复制通用正文；换项目时通用条款仍然生效。
> 适用：所有场景面板、顶栏弹层、弹窗、右键菜单，以及 Git / 文件 / 预览 / 会话等跨面板交互。

---

## 1. 六条不可放宽的底线

1. **入口可见**：核心操作必须有常驻文字入口，不能只藏在图标、右键或长弹层里。
2. **默认安全**：默认不选中、不提交、不删除；查看类默认先给源内容，派生视图作为显式选项。
3. **一次一件事**：变更单管理、不参与提交、移动分组、提交各自独立，不塞进同一个长弹层。
4. **状态可见**：空、加载、成功、失败、禁用、无权限、部分成功都有文案和下一步。
5. **可退出、可恢复**：弹层可关闭、流程可取消；删除变更单不碰磁盘文件；危险操作两步确认。
6. **反馈明确**：操作结果走 `window.__tbsToast(msg, bad, ms)`；错误 ≥8 秒，关键结果不能只放在会消失的小字里。

## 2. 工作台具体判据

| 项 | 本仓判据 | 反例 |
| --- | --- | --- |
| 核心入口 | 「变更」页签顶部常驻 scope 栏；变更单、不提交、查看模式必须有文字入口，不能只藏在 `⋯` / 右键 / 长弹层 | 工具栏只留一个 `◧` 图标，点开才知道有什么 |
| 默认值 | 变更列表默认不勾选任何文件；Git 双击默认看文件内容；默认动作不得提交 / 删除 / 覆盖 | 打开就全选，双击直接弹 diff |
| 一次一件事 | 变更单管理、不参与提交、移动分组各自独立卡片；提交区 sticky 底部 | 一个长弹层同时塞分组、排除、提交 |
| 单击 / 双击 | 单击只选中；双击按当前模式执行；双击功能必须另有右键或按钮的单次入口 | 单击直接弹 diff，双击时先触发两次 click |
| 刷新 / 状态 | 自动刷新保留勾选、提交草稿、选中提交、滚动位置；跨面板定位失败必须 toast | 刷新一次清空输入和勾选 |
| 危险操作 | 删除变更单不删文件；删除变更单两步确认并写清范围；移出只改归属，不碰磁盘 | 一键删组，文件跟着没了 |
| 跨面板联动 | Git 双击内容模式 → 预览面板 `show({ path, title, kind })` + 文件面板 `locate(full)`；目标面板不存在时提示 | 点了没反应，也不报错 |
| 视觉 | 颜色走 `--bg` / `--bg-panel` / `--border` / `--text` / `--text-dim` / `--accent` / `--ok` / `--warn` / `--err` / `--sh-*`；按钮用组件类；正文 ≥12px、次要文字对比度 ≥4.5:1 | 内联写死深色 hex、裸 `<button>`、浅色下白字白底 |
| 弹层 | `var(--bg-panel)` 底 + `var(--border)` 边 + `var(--sh-2)` 影 + 圆角；内容超高时底栏 sticky | 只有底色没有阴影；按钮被卷出可视区 |

## 3. 跨面板联动的固定契约

### 3.1 Git 变更 → 预览 / 文件面板

- 双击模式由 `localStorage["app.git.openMode"]` 保存；默认 `file`，可选 `diff`。
- `file` 模式：`openWorkFile` 把 `repo + rel` 转成绝对路径，送 `renderers.view` 的 `show({ path, title, kind })`；代码 / 文本强制 `kind:'text'`，图片 / PDF / Office 交给预览面板按类型处理。
- 同时 `locateInFiles` 调 `window.__kunFiles[meta.filesPanel].locate(full)`，让文件面板翻到父目录、选中并滚动到该文件。
- 目标文件已被工作区删除（`stLetter(c.code)==='D'`）时，自动退回删除 diff。
- 场景 JSON 的 `cd-git` 必须带 `filesPanel:"cd-files"`；新增类似联动时，先确认目标面板 id 已登记。
- `openDiff` / `openCommitFile` 必须允许不传行 DOM（右键菜单场景），不能假设调用方一定有行元素。

### 3.2 通用联动

- 任何「这边点了，那边要变化」的交互，都必须在方案里写清：谁触发、传什么、目标怎么定位、失败怎么提示。
- 目标面板不存在、目标行找不到、目标文件已删除时，必须有可见兜底；不能静默失败。
- 跨面板定位完成后，焦点要落在目标上，不能把用户留在原面板。

## 4. 自动刷新与状态保持

- Git 面板自动刷新沿用「指纹 2s + 全量 20s」：指纹不变不启动 git 进程；变了才 `pullPanel()`，内容签名不变不重画 DOM。
- 重画必须保留：勾选、提交信息草稿、选中提交、滚动位置。
- 打开弹层（`curModal`）或正在拖拽（`draggingPath`）时跳过自动刷新，操作结束后再补拍。
- `focus` / `visibilitychange` 回前台要补拍；但不能因此抢焦点或清空输入。
- 工作区变化与 `.git` 变化分开判断：`.git` 指纹只负责分支 / 提交更新，工作区文件改动走全量读兜底。

## 5. 视觉与主题（补充 `外观皮肤与设计令牌.md`）

- 新组件必须同时过两关：**颜色令牌 / 组件类** 和 **入口 / 默认 / 状态 / 退出**；只过视觉不算完成。
- 皮肤段按组件名改，**新组件可能落在皮肤段之后**，天生不在覆盖范围；新增 Git、选股、抠图等组件时要单独过令牌扫描。
- 本机默认主题是浅色；「深色下看着没问题」不等于浅色下没问题。浅 / 深两套都要检查。
- 不用颜色单独表达状态；涨跌、成功 / 失败、选中 / 禁用都要有文字或图标。
- 弹窗、菜单、右键菜单必须统一 `g-mask + g-modal` / 组件类，不写裸原生控件。

## 6. 交付检查（工作台版）

界面 / 交互改动交付时，除通用八项外必须附：

| # | 检查 | 本仓做法 |
| --- | --- | --- |
| 1 | 入口 | 不看代码，能否在「变更」页签顶部找到变更单 / 不提交 / 双击模式 |
| 2 | 默认 | 新文件是否默认不勾选；双击是否默认看内容；默认是否不会提交 / 删除 |
| 3 | 状态 | 空组、空变更、加载失败、无文件面板、已删除文件是否都有提示 |
| 4 | 输入冲突 | 单击只选中；双击按模式执行；右键可单次指定「看文件内容 / 看改动 diff」 |
| 5 | 刷新 | 自动刷新后勾选、草稿、选中提交、滚动是否还在 |
| 6 | 危险操作 | 删除变更单是否两步确认；是否明确不删文件；移出是否只改归属 |
| 7 | 视觉 | 浅色 / 深色、窄宽、长文本、图片缩略图、禁用行是否可读 |
| 8 | 验证标注 | `node --check` / `测试.mjs` / `渲染自检.mjs` 实际结果；未实跑要写「未实跑」 |

## 7. 反例库（2026-11-17）

### 7.1 Git 面板旧版：功能都有，但全是黑盒

| 旧版 | 问题 | 现在 |
| --- | --- | --- |
| 工具栏 `◧` 按钮下挂长弹层 | 变更单、不参与提交、提交混在一个入口；不点开不知道有什么 | 「变更」页签顶部常驻 scope 栏：`变更单 [当前组 ▾] ＋新建　⊘ 不提交 n　查看全部` |
| 行右键平铺组名 | 分组入口只在右键，发现成本高 | 变更列表按变更单分组成树；组头有组级复选框、折叠、组名、文件数、`提交`、`⋯` |
| 行尾挂组名徽标 | 只能看，不能拖，不能改 | 文件可拖到组头 / 组体归组；拖到「未归组」= 从变更单移出 |
| 提交区不吸底 | 文件一多，提交按钮被卷出屏幕 | 提交区 sticky 底部，标题「提交 · 组名」+「已勾选 n / m」+ 跨组提示 |
| 双击默认弹 diff | 用户想看文件内容，却先看到变化视图 | 摘要行 `双击看 [内容] [改动]`，默认「内容」；右键可单次指定 |

**教训**：功能全不等于可用。入口、默认、状态、退出四项不过，功能越多越像黑盒。

### 7.2 省 token 面板（2026-11-11）

- 反例：节点内联 `color:#e6edf3` / `#8b949e`，浅色主题下正文近白、次要文字只有 2.9:1；底栏两个裸 `<button>` 渲染成系统灰按钮。
- 纠正：颜色全走令牌；按钮用 `.upop-btn` 等组件类；底栏右对齐，主操作 `is-primary`、次操作 ghost；浅 / 深两版实测截图。

### 7.3 皮肤段覆盖盲区（2026-11-12）

- 反例：以为「皮肤段改过了」= 整站改过了；实际皮肤段只覆盖 226 个选择器，新加的 Git / 选股 / 抠图组件落在皮肤段之后，天生不在覆盖范围。
- 纠正：新增组件单独过令牌扫描；判据是「底色 / 文字是否走令牌」和「浅色主题下是否还有深底深字」，不是「类名在皮肤段里出现过」。
