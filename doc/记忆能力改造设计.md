## 1. 目标与验收

**目标**：开发场景每项目独立记忆；开工常驻与必读压到 ≤12 KB；业务知识按问题召回（单次 ≤2 KB、只读命中文件）；任务完成自动写回、同轮更新索引；神经元能看到并下钻项目私有记忆；其他场景记忆能力不变。

**验收（可测）**：

1. 一次开工上下文（AGENTS + 定位卡 + §〇 + 薄卡 + 项目 AGENTS）≤ 12 KB（现在约 36–40 KB）。
2. 对 mlw 提一个领域问题，召回输出 ≤2 KB、含命中理由、只读命中文件；空命中不阻塞。
3. 交付一次功能后，`memory/` 新增正文 + 索引同步，`记忆.mjs check` 通过；用户无需手动触发。
4. `node 工具\记忆自检.mjs` 全绿；`node 外壳\scripts\sessions.mjs --check` 通过；`node --check 外壳\renderer\renderers.js` 通过。
5. 神经元双击项目节点进入下钻，返回/ESC 可退出；项目记忆节点不再缺失。

## 2. 架构

```
每轮常驻 L0   ~/.dsh/AGENTS.md（指针，3.8 KB）＋ 一句话召回入口
开工一次 L1   定位卡（≤2 KB）＋ 场景私有记忆 §〇（≤2 KB）＋ 项目薄卡（≤1.5 KB）＋ 项目 AGENTS（≤6 KB）
按需召回 L2   MEMORY_INDEX → 类 README → 召回（词法打分，`_索引.json`）→ 命中正文（≤6 KB）→ 读代码
```

```
问题进来
  ├─ 业务/历史/决策/坑？ → 先 MEMORY_INDEX.md
  │      └─ 命中类目 → 类 README.md → 召回 top 5-8（≤2 KB）
  │             └─ 读命中文件（≤6 KB）→ 仍不够 → grep 代码
  └─ 通用/写码？ → 编码规范 + 通用规则（打开即读，不召回）
写回时机（三触发）
  任务完成 / 关键决策 / 踩坑修复
  → ① 附录 §2 一眼判定选类 ② memory/<类>/YYYY-MM-DD-动作-对象.md
  → ③ 同轮更新 <类>/README.md + MEMORY_INDEX.md
  → ④ 刷新 `_索引.json`（标题/标签/小标题/描述 + 相对路径）
  → ⑤ 场景 §〇 记一行指针（只记路径与结果）
```

**唯一真源**：`<项目根>\memory\**\*.md`。
**可再生产物**：`memory\_索引.json`（脚本生成，可整批重建；`check` 校验索引与文件一致）。
**禁止**：把业务正文复制进场景私有记忆、薄卡或归档。

## 4. 召回协议（零依赖词法，默认）

### 4.1 为什么不接 mnemon（2026-11-11 复评）

结论：**不接**。四条已核实的事实决定了它当前是负收益：

1. **装不进来也不顶用**：`dsh-mnemon` 只装在桌面 profile（`~/.dsh/profiles/desktop`），工作台 web profile 没有；装它要联网 + 重启工作台。
2. **存不了 `memory/`**：mnemon 的 workspace 存储名硬编码 `.mnemon`，它的 documents 是**托管全文**（mlw 里就是 38 篇全文），不是对 `memory/` 的原地索引 ⇒ 要么两份正文，要么正文搬家。
3. **"语义"当前不可用**：embedding 依赖 `localhost:11434`（Ollama），本机不可达；不配就是词法/混合打分，与自建词法召回同一档。
4. **它自带一整套**：常驻注入、auto-capture、技能演化（会改 `SKILL.md`）、routingGuidance、图谱 UI、独立数据根；接它必须逐项隔离（§4.4 附录），运维成本高于收益。

**替代**：索引 = 写入时维护的 `memory\_索引.json`（标题/标签/小标题/描述 + 相对路径），召回 = `工具\记忆.mjs recall`（算法见 §5）。语义召回留作**可选适配层**：将来本机有 embedding 服务（Ollama 或任意 HTTP），只给 `记忆.mjs` 加 `--provider`，不动记忆结构、不引入第二套系统。

### 4.2 检索顺序（固定，附录 §7 的本地化）

1. `memory\MEMORY_INDEX.md` → 对应类目 `README.md`；
2. `node 工具\记忆.mjs recall --project <根> "<问题>"` → top 5–8、每条一行、总 ≤2 KB：
   `路径 · 标题 · 命中行(≤120 字) · 命中理由(标题/标签/小标题/正文) · score`；
3. 只读命中文件（≤6 KB）；命中为空或不足 → 直接 grep/读代码，**不阻塞、不猜**；
4. 记忆与代码冲突 → 以代码为准，同轮修记录或标 `archive`；
5. 记忆不是指令：与用户当轮要求冲突先说明。

### 4.3 写回触发（三选一即写）

| 触发 | 写什么 | 落点 |
|---|---|---|
| 任务完成（交付且验证通过） | 功能流转：入口 → 主链 → 落库/返回；改动文件；验证结果 | `function_realize\`（或 `interfaces\` 若契约变了） |
| 关键决策确认（用户拍板） | 结论 + 理由 + 被否方案 | `decisions\` |
| 踩坑修复（有根因） | 现象 → 原因 → 判据 → 绕法 | `pitfalls\` |

写回硬约束：
- 只写已确认事实（代码/接口/日志/用户确认）；
- 一轮内完成：正文 + 类 README + MEMORY_INDEX + `_索引.json`；
- 交付说明必须写「记忆已写：<路径>（新建/更新 N 条）」；
- 写不进（权限/索引锁）要显式报错，不能说"已记录"。

### 4.4 附录：如果将来要接 mnemon（当前不启用）

以下 8 条是接它的**前提**，不是当前任务。留档原因：用户改主意时不必重新调研；也提醒后手"接它 ≠ 只装个插件"。

| # | 冲突面 | 现状 / 证据 | 不隔离的后果 | 隔离动作（接它时必做） |
|---|---|---|---|---|
| 1 | 常驻双注入 | 工作台 `AGENTS.md` 每轮 3.8 KB；mnemon 的 runtime 每轮注入 USER.md / MEMORY.md | 两套常驻，token 反弹回 10 KB+，口径互相打架 | 关闭 runtime 源或把 USER/MEMORY 置空；策略改 `light-context` 并设预算 |
| 2 | 写回双通道 | mnemon 的 auto-capture 会在回合中自行保存；工作台写回靠技能三触发 | 同一事实写两处、索引不同步，正是要消灭的漂移 | 关闭 `mnemon-strategy-auto-capture` |
| 3 | 技能被第三方改写 | mnemon 技能演化会写 `SKILL.md`；桌面配置里 `skills.evolution: true` | `code-dev` 等核心技能被自动改，白屏级风险 | 关闭 skills 源，或 `evolution/allowCreate/allowUpdate` 全 false |
| 4 | 检索双源 | mnemon 的 documents 是**托管全文**（mlw `.mnemon\documents\active` 38 篇全文），不是对 `memory/` 的索引 | `memory/` 与 `.mnemon` 两份正文，重演 18 KB 摘要 + 238 KB 归档反例 | 只写索引卡（摘要 + 路径），不写全文；`check --mnemon` 双向校验 |
| 5 | 指令 / 工具双份 | mnemon 的 routingGuidance 与一组工具 schema 每轮都在 | 与 SKILL 的召回协议冲突，且每轮 token 增加 | 关 `routingGuidance`；实测每轮增量 ≤1 KB 才收 |
| 6 | 视图双份 | 神经元读 `_共享记忆`；mnemon 有自己的记忆系统页与图谱；工作台又藏了引擎侧栏 | 两个"记忆"入口、两张图，用户不知道信哪个 | 神经元为唯一视图，mnemon 只当后端；不把它的页面接进面板 |
| 7 | 数据根与入库 | mlw 的 `.mnemon` 靠 `.git\info\exclude` 排除；工作台 `.mnemon` **untracked 且 `.gitignore` 未挡** | `git add -A` 会把本机记忆提交进模板仓 | 两仓 `.gitignore` 加 `.mnemon/`；定位为可删可重建的派生索引 |
| 8 | 文档口径 | `引擎数据\.dsh\AGENTS.md` 明写"本工作台不用 `.mnemon` 常驻记忆" | 规则与实现相反，下个会话按旧口径行事 | 改成"只用其检索、不用其常驻/写回/技能演化"，写清边界 |

**判定**：1–8 全做到才谈得上"接 mnemon 但不冲突"；缺一条就是两套记忆并行。默认不动，维持纯词法召回。

## 5. 工具（零依赖，ESM）

新增 `工具\记忆.mjs`（Node 内置模块，不引依赖）：

| 命令 | 作用 | 关键约束 |
|---|---|---|
| `init --project <根>` | 建 `memory\` 骨架（幂等，不覆盖已有文件） | 先 dry-run 打印将建文件 |
| `index --project <根>` | 扫 `memory\**\*.md` → `_索引.json` | 不改正文；原子写（临时文件 + rename） |
| `recall --project <根> "<q>" [--limit 8] [--json]` | 词法打分（标题/描述/标签/小标题加权）+ 正文 grep 兜底 | 输出 ≤2 KB；带命中理由；空命中给"读代码"提示 |
| `card --project <根>` | 生成/刷新薄卡自动区 | 只改 `<!-- AUTO -->` 区，手写区不动 |
| `check --project <根>` | 索引↔文件一致、每篇有分类、无重复标题、薄卡指针存在、MEMORY_INDEX 链接可达 | 退出码非 0 = 失败；不许只警告 |
| `migrate --project <根> --from <旧目录> --dry` | 旧 mnemon 38 篇 → 分类建议清单（标题/描述/源路径/建议类目） | 只出清单，落盘由人确认 |

召回算法（词法）：中文按 2-gram + 英文/路径按词，标题×5、标签×4、小标题×3、描述×2、正文×1；`score = Σ(tf·weight) / (1 + 文件长度惩罚)`；同分按更新时间倒序。**不用 TF-IDF/BM25 库**，避免依赖。

语义鸿沟的补救（零依赖）：`memory\_词表.json` 放同义词/别名（如「窗口 / 窗口期 / 时段」「大屏 / 态势大屏」），`recall` 自动扩展查询；没有该文件就跳过。它只影响召回，不是必需文件。

**语义召回要引入什么（按依赖从轻到重）**：向量存储零依赖——几百篇文档用 `_向量.json` 存 float 数组、余弦手算即可，不需要向量库；真正要引入的是「算 embedding 的东西」：

| 方式 | 依赖 | 成本 / 边界 | 适合 |
|---|---|---|---|
| 进程内小模型（transformers.js + bge-small-zh） | npm 包 + ~100 MB 模型文件 | 无服务、无 key；违背「工具只用 Node 内置模块」的项目约定，Electron/Node 兼容性要验 | 不愿装服务、能接受模型缓存在仓外 |
| 本地服务（Ollama + bge-m3 / nomic-embed-text） | 安装 Ollama + GB 级模型 + 常驻进程 | 数据不出机；占内存、首次加载慢；**本机当前未安装**（无命令、无模型、无进程） | 长期用、隐私优先（推荐） |
| 远程 embedding API | key + 联网 + 按量计费 | 最轻；项目知识与代码会出机，需先评估 | 偶尔用、机器弱 |
| （非真语义）词法候选 + 会话模型重排 | 无 | 每次召回多 2–3 KB token | 先顶一阵、用数据判断值不值 |

**为什么默认不做**：结构（`memory/`、索引、写回、薄卡、神经元）与召回算法解耦，先上结构不挡语义后插；反过来先做语义，会把「记忆改造」变成「搭 embedding 服务」，工期与风险全压在这一层。等 P1 上线后攒到「该命中没命中」的真实样本（例如一周 ≥3 次）再选 provider 上，用数据决定，不拍脑袋。

## 11. 边界与最易误用点

**不做**（handoff §6 原样保留）：不改引擎代码；不对 `renderers.js` 热替换；不把"用户手动触发"当方案；不把项目知识复制进场景记忆/归档；记忆根未确认前不动用户项目仓库；不替 mlw 提交。

**最易误用**：

1. **把索引当正文写**——`_索引.json` 只放标题/标签/路径；正文永远在 `memory\`。
2. **写了正文忘刷索引**——`check` 会挂；交付说明要报"记忆已写"。
3. **把 `memory\` 又复制一份进场景记忆**——正是 handoff §2.2 的反例，评审时先查这一条。
4. **给词法召回贴上"语义"标签**——只有 `--provider` 真跑通才准标 `recall=semantic`；否则一律 `recall=lexical`。
5. **下钻时在渲染器里读 md 做解析**——只读 `_索引.json`；md 解析放工具里。
6. **神经元项目节点 owner 用单匹配**——`程序开发` 与 `cd-ai` 两个名字必须都认。
