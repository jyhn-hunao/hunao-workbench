## 三、这轮加的东西（界面 + 配置怎么落）

### 1. 入口：场景 `console`「工作台控制台」

| 面板 | 类型 | 管什么 |
| --- | --- | --- |
| 功能台 | `feature-board`（`group: "all"`） | 全部 28 项装同一块：顶部统计带（28 项 / 63 动作 / 5 组 / 日常 6 / 低频 10）+ 「每组多少项」小计 + 跨组搜索 + 5 个组内小节（各组卡片、平时折叠低频）+ 底部 6 条症状带 |
| 配置与记录 | `feature-config` | 界面偏好（二次确认 / 展开说明）/ 接管范围计数 / 最近 10 条操作（成败 · 原因 · 点击数）/ 历史日志目录与最近 8 份 / 清空上次结果与计数 |

两块都不绑会话 —— 看点按钮不该为它占一条 AI 会话（`_场景身份索引.md` 已登记为「非 AI 面板」）。
“找功能 / 最近操作 / 症状表”不再是独立面板：全局搜索与症状带并进「功能台」底部与顶部，最近操作并进「配置与记录」（见 1h）。

### 1b. 怎么管 100 项：三层认知（2026-11-14 第三轮）

功能一多，靠记名字必输。所以界面按**「什么时候会用」**而不是按代码目录排：

| 层 | 怎么体现 | 数据在哪 |
| --- | --- | --- |
| **频率** | 每块功能板内 `daily` 在前、`weekly` 居中、`rare` 折叠成「低频 N 项」；卡片上「日常」小标 | `功能台.js` 的 `FREQ` 表（`daily 6 / weekly 12 / rare 10`） |
| **组内搜索** | 每块板顶部一个搜索框，功能名 / 用途 / 脚本名 / 按钮名都能搜；输入时自动展开折叠项 | 渲染器前端过滤，不重排、不重建卡片（不会弄丢已跑出来的输出） |
| **全局搜索** | 底部「找功能」一块：一个框搜全部 28 项，结果显示「功能名 · 在哪组 · 几个动作」，点「去这张卡」跳过去；空框先给日常 6 项 | `feature:list` 全量下发，前端拍平；跳转靠卡片 `data-fid` |
| **症状** | 底部「出什么事点什么」：6 条症状 → 卡；点「去这张卡」滚过去高亮 | `功能台.js` 的 `TRIAGE` 表 |

两张表（`FREQ` / `TRIAGE`）+ 一份登记表，就是全部维护成本：**加功能只加登记项，调顺序改 `FREQ`，加排障路径改 `TRIAGE`**；界面不猜、不硬编码。

### 1c. 危险动作分级（2026-11-14 第三轮）

原来所有写操作都是"连点两次"，风险不分级 = 没有分级。现在分两档：

| 档 | 谁在这个档 | 界面怎么拦 |
| --- | --- | --- |
| `write` | 开关 --on/--off、对齐引用、发消息、改名、生图、收工 | 6 秒内连点两次 |
| `destructive` | **出包**、**连引擎一起打（≈5GB）**、**拆成分条**、**整理归档**、**沉淀定论** | 按钮红框，且必须**手打「确认」**两字才解锁执行（不靠连点） |

判定原则：**会覆盖或搬运真实文件 / 会写掉几 GB 的，一律 destructive**；只改一行配置或追加一条的，留 write。共 5 个动作在这一档。

### 1d. 运行态：点了之后能看见、能停、能查（2026-11-14 第四轮）

前三轮解决的是「怎么找、怎么防误触」，这一轮补「跑起来之后」：

| 能力 | 做法 | 实测 |
| --- | --- | --- |
| **停** | `功能台.kill(id)` → IPC `feature:kill` → 卡片上「停」；只杀这条动作的子进程 | 跑 `shell-test` 0.8 秒后停：`ok=false killed=true msg=已停（你按的「停」）`，872ms 返回 |
| **失败原因上提** | `tailReason()` 取输出最后 3 行（每行 ≤110 字）写进标题行，不再只说「原因见输出」 | `asset-check` 传不存在的资产名 → 标题行直接是「✗ 没有这个资产包：…」 |
| **全文落盘** | 每次跑完写 `外壳\data\历史\<功能>.<时间>.log`，每功能留 20 份；卡片上「打开完整日志」 | `usage-ledger all` → 落盘 4.0KB，界面只显示前 6000 字 |
| **上次结果带动作名** | `last[id].action` 反查按钮名 → 「上次 ✓ 全部会话 · 时间」；一张卡多按钮不再分不清 | 标签结构改了，无歧义 |
| **最近操作** | `list().recent` 由 `last` 按 `at` 倒序取 10 条，新面板 `feature-recent` 渲染 | 真跑 2 次后 `recent=2`（用量、停掉的那次都在） |
| **点击计数与审计** | 每次跑 `hits[id]+1`；`node 功能台.js --audit 90` 列 90 天没点过的卡 | `--audit 30` 输出「6 / 28 项用过，22 项没动」 |
| **接着做** | `NEXT` 表（12 条工序链，如 体检→索引→收工→沉淀）→ 成功后给按钮跳卡 | `next` 指向不存在的功能已被第 9 项门禁拦（`n.ok=false`） |
| **别处也有入口** | `ALSO` 表标注顶栏/命令行同类入口（用量、体检、静态测试、用量自检） | 卡片上「别处也有：顶栏「用量」面板…」 |
| **状态新鲜度** | 底部写明「开关状态查于 X 分钟前（60 秒缓存，↻ 重查）」 | `status().at` 是毫秒，界面按毫秒换算 |

### 1e. 第五轮：修缺陷（不是加功能）

| 问题 | 真是什么 | 怎么修 | 验证 |
| --- | --- | --- | --- |
| 长输出把失败原因切掉 | `push` 超 4 万字时 `slice(0,40000)` 砍的是**尾巴**，而 `tailReason` 取最后 3 行 ⇒ 封装/发布前检查这类长日志，失败时原因取自中间 | 只砍中间：留头 2000 + 尾 37000，插「…（中间省略约 N 字）…」 | 单测 100 段 × 600 字：末行=段100，原因取到 段98/99/100 |
| 改完开关还显示旧状态 | `status()` 60 秒缓存，`run()` 成功后不清 ⇒ 刚切 on，卡片上仍写「未装」 | `finish` 里：`ok && danger!=='read'` ⇒ `STATUS_CACHE = {at:0,data:null}` | 代码层静态确认（没真跑改开关的动作，怕动真实配置） |
| 同时跑好几条抢 CPU | 只挡「同一条重复点」，可以同时开 5 条 node | 全局上限 2，第三条直接拒（不排队） | 实测：第三条 `ok=false 已经在跑 2 条…`；停完再点 186ms 通过 |
| ~~并发写覆盖 / 写坏配置~~ | **上一轮的这条判断是错的**：`finish()` 里 read→改→write 全是同步 IO，单线程不会交错；`writeCfg` 本来就是 `.tmp` + `rename` 原子替换 | 不需要改 | 读代码确认，撤回该结论 |

### 1f. 第六轮：再修四处（都实测过）

| 问题 | 证据 | 修法 | 验证 |
| --- | --- | --- | --- |
| 同一秒两次跑，日志互相覆盖 | 两次 `usage-ledger all` 的 `logPath` 完全相同，目录里只剩 1 份 5628 字节（第一次静默覆盖） | 时间戳加毫秒：`.replace(/[:T.]/g,'-').slice(0,23)` | 同秒连跑两次 → `不同文件=true`，两份都在 |
| 历史目录 / 重置没有入口 | 界面只能看「最后一份」，`data\历史\` 打不开，`last`/`hits` 清不掉 | 配置面板加「打开历史目录」「清空上次结果与点击计数」（后者两次确认，不碰真实开关、不删日志） | `configSet({reset:true})` 后 `recent=0`、`hits=0` |
| 表单「执行」按钮不随忙态置灰 | `btnBusy` 只禁卡片按钮区，弹开的表单按钮仍可点，会撞「同时 2 条」 | `busyRefresh` 登记刷新函数，表单按钮一起置忙；破坏性闸门与忙态叠加判断 | 代码层 + 渲染自检通过（未真点验证） |
| 「停」是整功能粒度 | 同功能两个动作同跑时点一次「停」会全杀 | `kill(id, actionId)`：给了 actionId 只停那一条；不给则兼容旧行为（IPC/preload 同步透传） | 实测同跑 `render-selftest` + `shell-test`，停后者 → 后者 killed(781ms)，前者跑完（12.7s ok）；错 actionId 返回「没在跑」 |

### 1g. 第七轮：把「展示」和「审计证据」分开

上一轮验证「清空」时把 `last` 清了，`--audit` 立刻失真（说 2/28 用过）—— 因为审计拿展示字段算“多久没点过”。这是设计没分层，不是按钮出错。

| 改动 | 做法 | 验证 |
| --- | --- | --- |
| 使用痕迹独立存 | 新增 `cfg.seen[id] = 时间戳`，每次跑都写；`reset` **只清 `last`/`hits`，不清 `seen`**；`audit()` 改读 `seen` | 跑 1 次 → `seen={session-bind:…}`；`reset` 后 `last=[] hits={}` 但 `seen` 仍在；`audit` 仍报「1/28 用过」 |
| 最近日志列表 | `list().logs`（读 `data\历史\*.log` 的元信息，倒序 8 条）；配置面板在「历史日志目录」下逐条列：文件名 · 大小 · 打开 | `logs=8`，首条 `session-bind.2026-11-14-09-11-15-074.log` |

> 口径：「上次 ✓」是给人看的（可清）；「什么时候用过」是审计证据（不可清）。两件事从这一轮起分开存。

### 2. 后端：`外壳\功能台.js`（28 功能 / 63 动作 / 5 组）

三条硬约定（写在文件头上，也就这么实现的）：

1. **只跑白名单**：脚本路径写死在登记表里；界面只能传 `feature id + action id + 声明过的输入项`，多传的键直接丢。
2. **不进 shell**：`spawn(process.execPath, [脚本, ...argv])`，参数逐项进 argv（`发消息` 的正文、`生图` 的提示词都不会被当成命令解释）。
3. **不猜状态**：三个插件开关的"装没装 / 什么模式"一律跑脚本 `--status` / `--check`（`feature:status`，60 秒内复用），界面不另存影子状态。
4. **登记表有机器门禁**：`scripts\测试.mjs` 第 9 项（`--only features`）会拦「缺 name / plain 太短 / 没动作 / 动作 id 重复 / `danger` 非法 / `input.kind` 不认识 / 脚本不在 `工具\` 或 `外壳\scripts\` / 症状表指向空卡」——加功能忘了写说明，测试直接红。

IPC：`feature:list` · `feature:run` · `feature:status` · `feature:config:get` · `feature:config:set`（`main.js` 里挂在 `tools:catalog` 后面，`preload.js` 暴露 `window.app.feature`）。

## 七、遗漏检查（第二轮，2026-11-14）

用户「检查是否有遗漏」之后，按四条机械判据重查，**不许自我保证**：

1. **面板类型对账**：扫 `renderers.js` 的注册名 vs 9 个场景 json 的 `panels[].type` 求差集。
2. **「仅命令行」重算**：把 `工具\*.mjs`、`scripts\*.mjs` 的文件名在壳内代码里做包含匹配，**去掉注释行、并排除 `功能台.js` 自身**（否则"我刚接的"会被算成"原来就有"）。
3. **动作 ↔ 子命令核对**：把功能台每个动作拼出来的 argv 逐条对回脚本头部的用法行（`--dry` / `--天` / `--size` / `--with-engine` 这类参数有没有真的被实现）。
4. **IPC 有接口没界面**：`preload.js` 的命名空间在渲染层有没有调用点。
