# 安装包化清单（参考实现 → 可安装分发）

> 定位已改：本仓目标形态是**可安装的桌面应用**，不再是「只读的参考模板」。`12-源码照搬/` 是当前可跑的外壳，安装器仍在施工。
> 本文只写差距与排期；做完一项改一项状态，⛔ 不提前在 README 写「装完即用」。
>
> **2026-11-21 进度**：阶段 A 已收口（`build` + NSIS 配置、首启下载 / 本地选包 → sha256 → 解包 → 替换 → 起引擎，并已用真实引擎包验收）；阶段 B 地基已落地（数据外置、首启目录 / 机器配置 / skills、面板会话自愈、Electron 43.0.0 固定，见 2.2）；`插件\` 与「种子 profile」已随包，安装版首启即装好记忆回响 / 社交策略 / 聊天档案（见 2.3）。**引擎下载源 url 仍未填**，干净机主路径仍是「本地选包」。

## 0. 做到什么才算「安装包」

1. 一个安装器（Windows `.exe`）：双击装，不装 Node、不装 npm、不手动放引擎。
2. 首次启动向导：机器配置 7 组（`workbenchRoot` / `repoRoot` / `codeRoot` / `ports` / `nodeExe` / `engineVersion` / `projects`）+ 端口 + 项目登记，全部落 `机器配置.json`。
3. 装完能跑：至少默认场景 + 1 个 AI 面板能切到会话（`sessionId` 自动建、自动回写，用户不碰）。
4. 数据与程序分离：数据目录可在向导里选，默认用户目录；卸载时可选保留。
5. 可升级 / 可回退：接现有 `引擎更新.mjs`（prepare / apply / rollback）。
6. 卸载干净：进程、端口、计划任务、开机项都清；数据按用户选择。
7. 签名：未签名安装器会被 SmartScreen 拦，内测可自签、对外需证书。

## 2.1 已落地（2026-11-21）

**首启下载链路**（`外壳\引擎引导.js`，只用 Node 内置模块，**不依赖 pnpm / 本机 node**）

- 检测两套布局（`lib/bin.js` / `apps/cli/lib/bin.js`）；打包版缺 `node_modules` 判「半截产物」，不当已就位。
- 下载源优先级：`env`（`DSH_ENGINE_URL` / `DSH_ENGINE_SHA256`）> `机器配置.json` 的 `engine.source` > `外壳\引擎源.json`；sha256 不是 64 位十六进制**直接拒装**。
- 下载支持 http/https（302 最多 5 跳）、`file://` 与本机路径；边下边算 sha256；进度经 `boot:progress` 回启动页。
- 解包到同级 `staging` → 验入口 → 旧引擎改名 `.bak-<时间>` → 新目录 rename → 写 `.engine.json` → 删备份；任一步失败回滚。
- 启动页：缺引擎时只留「⬇ 下载引擎（约 500 MB）」一个主动作，旁边「📂 选择本地引擎包」做离线兜底；下载中隐藏「立即进入」，失败把原因写到 detail 行并可重下。
- 本地包走同一条链路：选中 `.tar.gz` 后先算一份 sha256 当完整性基线（防拷坏，不证明来源），再解包 / 替换 / 起引擎。
- 发版侧：`工具\打包引擎.mjs` 产出 `引擎-<版本>-win-x64.tar.gz` + `.sha256`，并打印 `engine.source` 段；托管后把 url 填进 `机器配置.json` 或 `外壳\引擎源.json` 即可。**打包源必须是 hoisted 布局**（`pnpm install --prod --node-linker=hoisted`）：pnpm 默认的 `.pnpm` 隔离布局会在 `node_modules` 里留几千个符号链接，Windows 上打不进 tar、客户机也解不回来，工具检测到链接直接 exit 3 拒打。

## 2.2 阶段 B 地基（2026-11-21）

目标：装完不配也能进到「面板有会话」的状态。四块：

- **数据与引擎分家**：安装版 `DSH_HOME` 默认 `%LOCALAPPDATA%\胡闹的工作台\engine-data\.dsh`，electron profile / 工作区 / server.log 也在同一数据根下；⛔ 不再用 `resources\引擎\.dsh`（引擎升级整目录替换会把会话和记忆一起换掉）。源码版行为不变（仍由 `启动.vbs` 指 `引擎数据\.dsh`）。
- **首启准备**：`外壳\首启数据.js` 建目录 + **不覆盖地**写 `机器配置.json`（workbenchRoot 按安装位置推导、nodeExe 留空、不写 ports 以免多一份端口真源）+ 把随包 `种子数据\.dsh\skills` 种进去；已存在的配置与记忆一律不动。
- **Node 不随包**：引擎在 Electron 里的运行指纹有白名单（`node-addon-native-custom-loader` 只认 43.0.0 / 44.0.0 / 44.7.0 / 45.0.0-alpha.6），**43.4.0 会被拒**（实测报 `unsupported Electron runtime fingerprint`）。所以安装包固定 `build.electronVersion = 43.0.0`；它自带 Node 24.18.1，满足 `engines.node >=24.9`。安装版 `resolveNodeExe()` 直接返回空 ⇒ 引擎与工具脚本都用 Electron 跑，不再扫 PATH（避免命中旧 22.x）。开发机仍可用 43.4.0 + 系统 Node 跑源码版。
- **面板会话自愈**：`工具\首启绑定.mjs` 扫所有带会话的面板，按「会话文件是否真存在」判缺失；同一条旧 id / 同一个 `sessionTitle` 归一组（`so-msg` / `ch-hub` / `pet-msg` / `pet-ai` 共用一条），一组只建一条再批量回写。壳在引擎就绪 2s 后自动跑一次（`--go`），失败只写日志、下次再试。`建会话.mjs` 新增 `--scene/--panel`（可逗号多面板）直接回写场景 json + 定位卡 + 身份索引，用户不用再手抄 sessionId。
- **打包补件**：`extraResources` 把 `工具\` 与 `引擎数据\.dsh\skills` 带进安装包（`resources\工具`、`resources\种子数据`）；脚本里 `../../工具` 的相对推导在安装版正好落到 `resources\工具`。

## 2.3 插件随包与首启种子（2026-11-21）

目标：安装版不只要「会话都在」，还要「引擎插件首启就在」，不让用户再手跑 `--apply` + 重启整壳。

- **插件全量随包**：`package.json` 的 `extraResources` 增加 `../插件 → 插件`，安装版落到 `resources\插件`。`main.js` 的 `PLUGINS_DIR` 改为「源码同级 `插件` 优先，没有才取 `resources\插件`」，手机导入图等路径一并改走它；微信通道的「换脑插件源文件」因此不再是缺失状态。
- **首启种子 profile**：`种子数据\.dsh\profiles\web\cordis.patch.yml` 只写三条 `insert`（`dsh-memory-recall` / `dsh-social-policy` / `dsh-chat-archive`，`mode: enforce`），**不拷开发机整份 patch**（避免把模型 provider、界面偏好带进产品）。三个插件目录由 `extraResources` 直接落到 `种子数据\.dsh\profiles\web\node_modules\<包名>`；`首启数据.js` 的种子清单增加 `profiles`，仍然只补缺、不覆盖。
- **三个安装工具路径推导**：`工具\记忆回响.mjs` / `社交策略.mjs` / `聊天档案.mjs` 统一按 `DSH_HOME`（env 优先）算 profile 与日志 / 档案库，插件源按 `工具\..\插件`（安装版即 `resources\插件`）；`聊天档案.mjs` 的壳模块改用 `DSH_SHELL_DIR` → `外壳` / `app` 推导，不再拼源码布局。

## 2.4 外壳 `data` 外置（2026-11-21）

- **数据根提前算**：`main.js` 在加载本地模块之前算出 `PACKAGED / DATA_HOME / DSH_HOME / SHELL_DATA_DIR`，并写回 `DSH_DATA_HOME` / `DSH_SHELL_DATA` / `DSH_SHELL_DIR` / `DSH_HOME`；安装版 `SHELL_DATA_DIR = %LOCALAPPDATA%\胡闹的工作台\data`，源码版仍是 `外壳\data`。

- **首启建目录**：`首启数据.js` 的目录清单加 `dataHome\data`，首次启动即可写；不迁旧 `resources\app\data`（当前尚无正式用户，后续需要再补迁移）。

## 3. 推荐路线（三步，不追求一次到位）

**阶段 A：能装**
- electron-builder + NSIS，per-user 安装；先**不随引擎**。
- 首启检测引擎：没有就引导下载官方包，校验 sha256 后落到 `引擎\`；两套布局都认（`lib/bin.js` / `apps/cli/lib/bin.js`）。

**阶段 B：装完能跑**
- 向导收 7 组 → 写 `机器配置.json` → 跑 `环境适配 --apply`。
- 自动为默认场景建会话并回写 `sessionId` → 打开默认场景。
- 验收：干净 Windows 上，从双击到 AI 面板回第一句话，≤10 分钟。

**阶段 C：可维护**
- 接引擎更新 / 回退；卸载保留数据；签名；自动更新。
- 验收：升级不丢数据，回退能回上一版引擎。

**不做（明确排除）**
- MSI（NSIS 足够）；内置两套 Node；把源码版引擎（数 GB）塞进安装包；安装器里生成 `sessionId`。

## 4. 验收（Definition of Done）

1. **干净机**：无 Node / 无 npm / 无引擎，双击安装 → 默认场景 AI 面板能对话。
2. **卸载**：进程、端口、计划任务、开机项清空；数据按选择保留或删除。
3. **升级**：旧数据不丢；引擎可回退；`sessions.mjs --check` 仍全过。
4. **自检**：安装后布局下 `自检.mjs` exit 0（`nodeExe` 指随包 node、引擎两布局识别、端口无冲突）。

## 5. 与现有硬规则的关系

- 端口：仍 `env > 机器配置.json > 默认`；⛔ 安装器不改脚本里的端口字面量。
- 会话：`sessionId` 仍只由 `建会话` / `换会话` 回写；⛔ 向导、配置字典、模板渲染都不生成。
- 文档：安装器交付前，README / 新手必读保留「当前源码版」用法；交付后再删掉「照抄必失败」的警告，改成「装完即用 + 高级配置」。
