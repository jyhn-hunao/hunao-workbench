# 功能台重设计（2026-11-18）

> 触发：用户原话「现在工作台控制台的交互设计和UI太反人类了，重新设计一下」。
> 范围：`工作台控制台` 的两块面板 —— `con-desk`（功能台，§1–§7）与 `con-config`（配置与记录，§8）。
> 数据与执行没动：`外壳\功能台.js` 的登记表仍是单一真源。
> **2026-11-18 晚补（配置位）**：登记表做实为 **32 项 / 80 个动作**（原 34/86 为旧计数）；每项新增 `cfg` 声明，分 `plugin 3 / machine 1 / external 2 / none 26` 四类；右栏 `con-config` 由「偏好 / 最近 / 日志」改为「配置 / 最近 / 日志」管理总览。本文中的 34/86 与旧右栏描述属当时状态，现以 `node 12-源码照搬\外壳\功能台.js --json` 与 `console-context.md` 为准。

## 1. 旧版到底难在哪（诊断）

| 症状 | 具体表现 | 后果 |
| --- | --- | --- |
| 卡片墙 | 34 张功能卡 + 86 个按钮竖排成一条很长的滚动流，顶部还压统计带 / chip 行 / 5 个分组小节 / 低频折叠 / 底部症状带 | 找一个功能要滚很久；滚动条越长，越不知道自己在哪一组 |
| 结果和操作分离 | 输出写回卡片底部，卡片本身又很高 | 点完按钮要回头翻才能看到结果；切到别的功能就找不回来了 |
| 字号过小 | 大量 10.5–11px 的标签与说明，低于「正文 ≥12px」 | 看得见字、读不进去，密集恐惧 |
| 一次全铺开 | 所有功能的参数表单、开关状态都挂在同一屏 | 页面噪声大，真正要用的那一项反而不突出 |

## 2. 新版信息架构

**左「功能目录」+ 右「详情」，一次只展开一个功能。**

- 左栏（252px，永远可见，自己滚）：
  - 搜索框：跨全部组，功能名 / 用途 / 脚本名 / 按钮名都能搜；
  - 分组 chips：全部 + 5 组，带项数（插件开关 3 / 记忆维护 10 / 自检与发布 14 / 协作与通道 4 / 创意与资产 3）；
  - 条目：状态点（绿 = 脚本在、红 = 脚本不在）、功能名、组名、「日常 / 低频」标、上次 ✓/✗ + 多久前；
  - 左下症状带：可折叠的「出什么事点什么（6）」，点开 6 条症状 → 只选中功能，**不代跑**。
- 右栏（详情，自己滚）：标题（名称 + 日常/低频/重启/脚本不在标签）→ 组 · 脚本路径 → 说明 → `别处也有` → `背景：为什么以前只给命令行`（`<details>` 折叠，受配置里 `showWhy` 控制）→ 当前开关状态（后补）→ 动作按钮（上次跑过的那条带 ✓/✗）→ 参数表单（一次只开一条，收起再开不丢已填值）→ 输出区（跑着有「停」；跑完结论 + 耗时 + `pre` 输出 + 打开完整日志）→ 成功后「接着做」。
- 选中项写 `sessionStorage('fb.sel')`：刷新、关面板再开都停在上次那一项；找不到才退回第一条「日常」。

**为什么是两栏而不是页签**：34 项分 5 组，页签只能省掉「切组」这一下，仍要在组内找；目录把所有组压成一列可视清单，配合搜索与状态点，找东西从「滚」变成「扫」。详情独占右栏，才有足够宽度放参数、输出与下一步。

## 3. 交互与安全（沿用旧口径，不放松）

1. 默认安全：列表不预选任何动作；`confirmAgain`（默认开）时写操作第一次点只提醒，6 秒内再点才执行。
2. 破坏性动作（出包 / 连引擎 / 拆分 / 整理归档 / 沉淀定论）不看二次确认，必须**手打「确认」**才解锁执行。
3. 同时最多跑 2 条（主进程全局闸）；「停」走 `feature:kill(id, actionId)`，只停这一条。
4. 输出超 6000 字界面截断，全文落 `外壳\data\历史\<功能>.<时间>.log`，详情里「打开完整日志」直达。
5. 开关真实状态不猜：`feature:status` 起子进程探，60 秒缓存；**清单与配置先画，状态后补**，面板不再整块「读取中」。
6. ⛔ 不启停引擎；开关改完只提示「重启整壳生效」。

## 6. 验收用例

- 正常：重启整壳 → 打开「工作台控制台」→ 左栏应立刻出 34 项（不等开关状态），标题行先「读取中…」再变「34 项 / 86 个动作 · 开关状态查于 刚刚」；点「插件开关」组 → 右栏出 3 个开关的状态与动作。
- 边界：搜索「发布」→ 左栏只剩相关项、组标题带命中数；点「自检与发布」chip 后再搜，只在组内筛；关掉面板再开，仍停在刚才那一项。
- 异常：找一个 `danger=destructive` 动作（如打发布包）→ 直接点只出表单且「执行」灰着；不输入「确认」点不动，输入后才可执行；跑起来后点「停」应即时落「已手动停掉」，并出现完整日志入口。

## 8. 配置与记录重设计（同日第二轮）

> 触发：用户「配置与记录的面板也同样反人类」。这块是 w2 窄栏，和左边宽栏不是同一种病。

### 8.1 旧版症状

- 偏好 / 接管范围 / 统计段落 / 最近 10 条 / 配置文件 / 日志目录 / 8 份日志 / 清空，**8 段全堆在一条滚动流里**，找一条失败记录要滚到底；
- 正文压到 10.5px，坏原因和正常时间混在同一行，扫不出来；
- checkbox 贴在标题行里，不像开关；「接管范围」只是一堆统计数，却占了正文位置；
- 页签、分组都没有，窄栏里全靠滚。

### 8.2 新版

**顶部三页签，每页只做一件事：**

| 页 | 内容 |
| --- | --- |
| 偏好 | 两个开关（危险动作二次确认 / 显示背景说明）→ 数据在哪（配置文件路径 + 打开）→ 清理（清空上次结果与计数，两步确认）→ 页脚统计（34 项 / 86 动作 / 5 组 / 日常 6·低频 10） |
| 最近 | 10 条操作倒序：✓/✗ + 功能 · 动作 +「多久前 · 点过几次」+ 失败原因（红字）；空态给一句怎么产生记录 |
| 日志 | 打开历史目录 + 最近 8 份（文件名 + 大小，点一行直接开全文）；空态说明 |

- 默认页：有记录落「最近」，没记录落「偏好」；手动切过就记在 `sessionStorage('fc.tab')`，下次回来还在那一页。
- 开关改成 36×20 的滑动开关（`role=switch`），点击先变后落盘；失败退回原状态并报错，不假装成功。
- 字号 12–12.5px，行距 1.45–1.55；所有颜色走设计令牌。

- 正常：重启整壳 → 右栏应出现「偏好 / 最近 N / 日志 N」三页签；有历史记录时默认在「最近」，点开一条失败记录能一眼看到红色原因。
