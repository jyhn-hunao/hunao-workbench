# 外发安全闸门（2026-11-18）

> 一句话：胡闹的大肥鱼通过 QQ / 微信回话时，所有正文先过本机判定；IP、本机路径、主机名/用户名、token/密钥、手机号/身份证/邮箱/账号一律拦或打码。**不是提示词，是会失败的代码检查。**

## 1. 为什么不能只写提示词

提示词只能降低概率，不能给出「这条消息到底发没发出去」的确定答案；模型一轮走偏、换个写法（全角 IP、空格拆 IP、零宽字符、文件附件）就能绕过去。这里把出口收成一个函数：

- 判定只有一处：`12-源码照搬/外壳/外发闸门.js` 的 `checkText()`。
- QQ 不直连协议端：插件 `onebotHttp` 指到本机 `3100`，代理逐条检查后再转发 `3000`。
- 微信不直接发正文：`微信通道.js` 的 `_reply()` 在调用适配器前过闸。
- 判定库自己跑用例：`工具/外发闸门.mjs --自检` 有 27 条规则用例 + 6 条代理用例；有一条不通过就退出码 1。

## 3. 判定与动作

七类：`ip` / `path` / `host` / `user` / `secret` / `account` / `attachment`。默认动作：

- `ip/path/host/user/secret/attachment` → **阻断**（整条不发）。
- `account`（手机号、身份证、邮箱、QQ/微信账号、open_id 等）→ **打码后发**。
- 未识别为正常发送的 OneBot 动作 → 默认阻断（`unknownAction: block`）。

模式：

- `enforce`：命中就按上表拦 / 打码。
- `shadow`：照常发，但审计里记 `would`（用于观察，不建议长期开）。

`replyFallback`（默认「这个我在这儿不方便说～」）是阻断时替换的整句；不要写「已屏蔽」「系统提示」这类暴露机制的话。

## 4. 配置界面

入口：**社交 → 通道**面板标题行常驻「安全闸门」按钮 + 状态胶囊（`闸门 开/关·只记·QQ待接管·今日拦 N`）。按钮打开弹窗，四个页签：

| 页签 | 能改什么 |
| --- | --- |
| 总览 | 总开关（关要二次确认）、模式、微信/QQ/飞书渠道开关、被拦后的安全回话 |
| 规则 | 七类动作逐项选「阻断 / 打码后发 / 放行」、白名单短语、被拦原文是否存本机 |
| 审计 | 最近 40 条非放行记录（时间/渠道/结论/规则码），刷新、打开目录 |
| 高级 | QQ 代理开关、监听端口、上游地址、立即接管 / 恢复直连、刷新资产、跑自检、试审一条、只读文件位置 |

数据面 IPC（`preload.js` 的 `window.app.outbound`）：

`outbound:get / set / status / audit / assets-refresh / qq-apply / qq-restore / selfcheck / test / open-dir`

保存即生效：QQ 走插件的 `POST /api/qq-bridge/save`（同时改内存与文件，下一轮投递生效）；换不到引擎 cookie 时直接写 `~/.dsh/qq-bridge.config.json`，返回 `restartRequired: true`，不假装已生效。

## 7. 已知边界（必须说清）

1. **shell 主动绕过**：模型若自己 `curl 127.0.0.1:3000` 发 `send_private_msg`，代理拦不到。这属于「它主动绕开外壳」，不是通道漏洞；后续在桌宠 confirm 级规则里拦「命令行含 3000/3100/31241 或 `send_*`」，尚未落地。
2. **飞书未接**：见第 2 节。
3. **附件默认阻断**：图片/文件不走文本判定，默认整条拦；以后要放行得先做图片 OCR 与文件类型白名单，不能直接改 `attachment: pass`。
4. **只保护本机外发**：引擎/插件若在别的机器上跑，闸门不覆盖。
5. **换 WiFi / VPN 后**：点「刷新资产」，否则新 IP 不在指纹里，仍靠 IPv4 正则兜底。
