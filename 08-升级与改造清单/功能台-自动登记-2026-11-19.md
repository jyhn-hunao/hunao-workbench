# 功能台自动登记（2026-11-19）

> 状态：已落地 · 单测通过（38 项 / 94 动作 · `--verify` 94/94 · 收进/移出实测通过）
> 起因：用户反馈「控制台「全部」一直是 32，应该有新的才对」「为什么不会自动加入，我不能每次都来手动维护」。

## 1. 问题

- 控制台左栏「全部」的数字 = `功能台.js` 里 `FEATURES`（后改名 `BASE_FEATURES`）的条数，`list().stats.features` 由登记表长度算出，**不是写死**，但**来源只有一张手写表**。
- 于是新脚本只要没人手工补一条，界面就永远看不见：不是数字错了，是机制缺一层。
- 2026-11-19 首轮补了 5 个漏登记（聊天档案 / 社交策略 / 未定义检查 / 外发闸门 / 自动巡检），32 → 37 项。但同类问题会再发生，所以补机制而不是补数字。

## 2. 结论：三层登记，手写不是必须的

| 层 | 入口 | 能表达什么 | 落点 |
| --- | --- | --- | --- |
| 手写 | `功能台.js` 的 `BASE_FEATURES` | 多动作、参数表单、危险等级、状态探针、症状表、策略数值 | 仓内代码（可审、可 diff） |
| 脚本自声明 | 脚本头部一行 `// @功能台 {json}` | name / id / group / freq / plain / why / label / timeout / statusArgs | 仓内代码（跟着脚本走） |
| 一键收进 | 管理总览「未登记脚本 → 收进」 | 只读一条「跑一遍」，无参数 | 本机 `外壳\data\功能台自动.json`（不入库） |

组装顺序（`reloadFeatures()`）：`BASE_FEATURES`（手写）→ 扫描到声明 → 扫收到的收进；同 id / 同脚本都去重，**手写优先**。

## 3. 实现

文件：`12-源码照搬\外壳\功能台.js`

| 片段 | 作用 |
| --- | --- |
| `BASE_FEATURES` | 原 `FEATURES`，手写真源 |
| `AUTO_TAG` | 只认 `// @功能台 {…}` 一行（前 60 行内），JSON 解析失败在未登记里报原因 |
| `AUTO_DIRS` | 只扫 `工具\` 与 `外壳\scripts\` 两处 `.mjs`，`_` 开头跳过 |
| `scanFiles` / `declaredOf` / `autoFeature` | 扫目录、读声明、生成条目（id `auto-<slug>`，group 默认 `guard`，freq 默认 `rare`，danger 固定 `read`，timeout 夹在 10s–900s） |
| `INTERNAL` | 壳维护 / 面板按钮 / 调试 / 后台定时 / 要 key 会写文件：不算漏登记，不给「收进」按钮 |
| `ADOPT_FILE` | `外壳\data\功能台自动.json`（本机、`.gitignore` 挡；写盘 tmp + rename） |
| `readAdopted` / `writeAdopted` | 收进清单读写；条目 `{script, name, at}` |
| `reloadFeatures()` | 每次 `list / run / status / audit / verify / configSet` 前重建 `FEATURES`，改声明不用重启壳 |
| `unregistered()` | 扫到却没进目录的：`{script, name, reason, internal, at, size}`，internal 排最后 |
| `configSnap` / `configSet` | 配置快照统一带上 `unregistered / adopted / adoptFile`；`{adopt}` / `{drop}` 走白名单目录 + 文件存在校验，只改本机 json |

## 4. 为什么不做「扫到就全部上架」

脚本的**参数、危险等级、必填输入、okCodes、超时**无法从目录名推断。全量上架会把：

- 内部模块（`派发-公共.mjs` 之类）变成按钮；
- 壳维护（`建会话 / 换会话 / 环境适配`）在已有面板里出现第二份入口；
- 需要 key、会写文件的脚本（`表情包生成.mjs`）变成一键按钮，跑一次就报错或悄悄写文件。

所以默认「只读一条、要参数请手写」：安全，但解决「界面里根本不存在」这个真正的痛点。

## 5. 运维

**加一个新功能（只读）**

1. 脚本头部写一行：

```js
// @功能台 {"name":"内置规范检查","group":"guard","freq":"weekly","plain":"核 引擎数据\\.dsh\\standards\\ 里的规范是否齐全。","why":"规范随仓走，换机器后没人核。","label":"核一遍"}
```

2. 跑 `node 12-源码照搬\外壳\功能台.js --json`，看 `groups` 里出现 `auto-…`；
3. 跑 `node 12-源码照搬\外壳\scripts\测试.mjs`（「未登记脚本」应为 ok）。

**加一个复杂功能（要参数 / 要写 / 要状态灯）**

- 在 `BASE_FEATURES` 手写一条（动作、inputs、danger、okCodes、cfg、statusArgs、也写进 `CFG` / `FREQ` / `ALSO` / `NEXT` 需要的那份）。
- 同一脚本写了声明也不会重复：手写优先。

**临时先接出界面**

- 管理总览 →「未登记脚本」→「收进」：写进 `功能台自动.json`，出现在「自检与发布」组、低频；
- 「移出」只删这条登记，脚本文件不删；删 `功能台自动.json` 等价于全移出。

**门禁**

- `scripts\测试.mjs`：未声明未手写的非内部脚本 → warning（列脚本名与原因）；内部的不算，仅计数；
- `功能台.js --verify`：自动条目也逐条体检（只读，跑一次看退出码）。

## 7. 遗留

- 已收进项统一「低频 + 只读一条」：想给它们加参数/分组，仍要在 `BASE_FEATURES` 手写。
- 自动条目没有 `okCodes` 以外的判定：脚本若默认退出码 0 但输出 FAIL（如部分自检脚本），状态灯会显示 ✓。要精确判定就手写。
- 声明写在 60 行之后不认（防误伤正文里的示例字符串）；写错了会在「未登记」里给出解析错误原因。
- 生效范围：后端改动随下次调用立刻生效；**前端新增区块要重启整壳**（`12-源码照搬\启动.vbs`），只重启引擎不够。
