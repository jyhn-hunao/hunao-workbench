## 2. 目标与边界

### 2.1 目标

1. 群里每个人一条独立的关系档案：熟不熟、好感多少、有什么标签/雷点。
2. 她自己有一份会衰减的短期情绪，不再永远「平静且礼貌」。
3. 两者都只影响**表达**：句子长短、主动程度、玩笑尺度、称呼、emoji/贴纸、接话概率。
4. 每一条变化都能追溯到证据（哪句话、哪次互动），不凭感觉打分。
5. 默认从 60 起步（用户 2026-11-20 口径），但档位仍有门控；主人 100；一句话不能跨档，之后按互动与冷落继续变。

### 2.2 明确不做

| 不做 | 原因 |
| --- | --- |
| 用好感度决定「回不回」 | 会变成势利眼；被 @、被直接问仍然必须回 |
| 让模型直接写分数 | 一句「夸你」就能刷满级；模型只提事件，外壳限量折算 |
| 把好感度发给对方 / 写进群消息 | 这是内部状态，不是社交货币 |
| 跨聊天共享好感 | 私聊 A 的好感不能出现在群 B；群 C 的印象不能带进群 D |
| 用好感度覆盖人格底线 | `never`、外发闸门、安全规则优先级永远更高 |
| 上情感识别模型 | 成本高、误判多；先做事件级，够用 |

## 3. 双层模型：关系是慢变量，情绪是快变量

这是整套设计的地基，先分清两件事：

| | 关系（对某个人） | 情绪（她自己） |
| --- | --- | --- |
| 管什么 | 我对**这个人**的态度 | 我**此刻**的状态 |
| 变化速度 | 慢：按天/周累积；熟悉 21 天宽限、好感 14 天宽限后连续回落 | 快：按分钟/小时，半衰期约 90 分钟 |
| 存哪 | `社交关系.json` 的 `people` | `社交情绪.json` 的 `mood` |
| 例子 | 何笙：熟 63 / 好感 +14 | 现在有点烦，强度 38，约 40 分钟后回平静 |
| 会不会互相影响 | 会，但只做小幅调制：心情差时对熟人也不会热情，但不会因此讨厌他 | 不会因为讨厌某个人就长期低落 |

**为什么必须分开**：合成一个「心情值」会出现「被张三怼了 → 对李四也冷」的串味；分开后，情绪是全局的，好感是按人的，互不污染。

### 3.1 关系的两个轴

不要只用一个「好感分」。人跟人之间至少有两个维度：

| 轴 | 范围 | 来源 | 决定什么 |
| --- | --- | --- | --- |
| **熟悉度** familiarity | 0–100 | 互动量、互动天数、被点名次数、她回复次数 | 多主动、能不能用昵称、能不能开玩笑、要不要解释背景 |
| **好感** affinity | -100–+100 | 事件：被夸、被感谢、被怼、被敷衍、踩雷、共同话题 | 多耐心、多热络、玩笑开多深、愿不愿意多聊一句 |

两个轴组合出档位（带 5 分滞回，防止一句话跨档）：

| 档位 | 判定 | 一句话态度 |
| --- | --- | --- |
| 反感 | 好感 ≤ -30 | 只回必要信息，不主动，不接梗 |
| 有芥蒂 | -29 ~ -1 | 礼貌但短，避免玩笑，不主动找话 |
| 生人 | 好感 ≥ 0 且 熟悉 < 20 | 客气、短、不追问、不用昵称 |
| 认识 | 熟悉 20–39 | 正常礼貌，可以接一句话题 |
| 普通朋友 | 熟悉 40–69 | 能接梗，偶尔主动，可带 1 个 emoji；新人 60/60 先停在这里 |
| 熟 | 熟悉 70–79 且 好感 ≥ 10 | 放松，可损一句，可用昵称，贴纸正常概率 |
| 自己人 | 熟悉 ≥ 80 且 好感 ≥ 30 | 护短、主动关心、记得细节 |

> 好感高但刚认识（例如一见如故）→ 最多到「普通朋友」，不能直接「自己人」：没有共同经历，自来熟会假。
> 熟悉高但好感负 → 降一档：熟人抬杠可以，但不能一边熟一边冷。

落地时档位阈值和好感门控（`熟 ≥10`、`自己人 ≥30`）全部写进 `社交关系.json` 的 `config`：`stageKnown / stageFriend / stageClose / stageInner / stageCloseAffinity / stageInnerAffinity / stageHysteresis`，面板「规则」页可直接改，不是代码常量。

### 3.2 情绪的状态

情绪不是「开心/难过」二选一，而是一条带强度、原因、半衰期的状态：

| 字段 | 说明 |
| --- | --- |
| `label` | 白名单：平静 / 开心 / 兴奋 / 得意 / 低落 / 委屈 / 烦躁 / 疲惫 / 心虚 |
| `intensity` | 0–100；低于 15 不写进提示词，等于没有情绪 |
| `valence` | -1 ~ +1，正负倾向 |
| `energy` | 0–1，精神头；决定主动接话、句子长短 |
| `cause` | 一句人话原因：「刚才被连着催了两次」 |
| `halfLife` | 默认 90 分钟；重大事件最多 6 小时 |
| `until` | 衰减到 15 以下、回平静的时间 |

**基线由人格派生**：`personality` 是「慢热、话淡、不演」，所以默认 `平静`，正向强度上限 60、负向上限 70；不做大起大落，不演委屈，不拿情绪当借口。

**情绪只调旋钮，不改内容**。每个标签在 `config.moodEffects` 里有一张完整表，面板「规则 → 情绪联动表」逐项可改：

| 标签 | 字数上限 | 句数上限 | emoji 权重 | 贴纸权重 | 语音权重 | 群接话权重 |
| --- | --- | --- | --- | --- | --- | --- |
| 平静 | 60 | 2 | 1 | 1 | 1 | 1 |
| 开心 | 70 | 2 | 1.2 | 1 | 1.1 | 1.1 |
| 兴奋 | 70 | 2 | 1.3 | 1 | 1.2 | 1.2 |
| 得意 | 65 | 2 | 1.1 | 1 | 1.1 | 1.1 |
| 低落 | 24 | 1 | 0 | 0 | 0 | 0.7 |
| 委屈 | 22 | 1 | 0 | 0 | 0 | 0.7 |
| 烦躁 | 18 | 1 | 0 | 0 | 0 | 0.6 |
| 疲惫 | 20 | 1 | 0 | 0 | 0.3 | 0.6 |
| 心虚 | 30 | 1 | 0.5 | 0.5 | 0.8 | 0.8 |

口径：`字数 / 句数 = 0` 表示不额外限制；系数 `0` 表示不发 / 不接，`1` 表示不改变原通道概率，`>1` 只提高上限、最终仍夹在原通道 0–1 概率内。通道自己的上限更小时取更小值，情绪表不会放宽通道限制。

| 通道 / 能力 | 实际执行 |
| --- | --- |
| 微信文字 | `_reply` 先把通道上限与情绪字数取小；`filterReply` 再按句数 / 字数收一次；闸门替换的安全话术也收 |
| 微信贴纸 | 负向情绪 `stickerFactor=0` 直接裁掉 `[[sticker:...]]`；`0<系数<1` 再随机丢弃；系数 `1` 保持原策略 |
| 微信 emoji | `emojiFactor=0` 时从出站正文里真删 emoji；其余由提示词按权重引导 |
| 微信语音 | 桥接 `data/voice-send.json` 的 `Probability` 临时改为「原概率 × 语音权重」，30 秒后恢复；显式「发语音」仍优先 |
| QQ 群接话 | 原概率 × 关系档位系数 × `groupFactor`，夹在 0–1；日志写 `bias/stage/mood/moodFactor` |
| QQ 群文字 | `parseReply` 先按 `emojiFactor=0` 真删 emoji，再按 `maxChars/maxSentences` 收；提示词写「不超过 N 字」 |
| QQ 群贴纸 | 模型提议后按 `stickerChance × stickerFactor` 随机；`stickerFactor=0` 直接丢 |
| QQ 群语音 | `voiceReplyChance × voiceFactor`；`voiceFactor=0` 不发 |
| QQ 普通 @ / 私聊 | `外发闸门` 对「纯文字、无附件」先按 `emojiFactor=0` 真删 emoji，再按情绪收字；`QQ能力.shouldVoiceDirect` 把补语音概率乘 `voiceFactor` |
| 飞书 / DSH | 注入卡带「本轮表达联动」一行和 `moodPlan` 元数据；飞书出站不可拦，贴纸/语音只能靠提示词约束 |

边界：微信原生语音是桥接全局策略，临时改 `Probability` 对并发会话是近似值；飞书没有硬裁剪，只能靠提示词；`emojiFactor=0` 在微信 / QQ 群 / QQ 普通 @/私聊是真删，`0<系数<1` 仍由提示词引导；群聊里 `maxSentences` / `maxChars` 由 `parseReply` 硬收。语音合成统一使用**已经按 `moodPlan` 收过的正文**，不会出现「文字很短、语音还在念长文」。

### 3.3 三条曲线（2026-11-20 落地）

三条曲线全部落在 `config.curves`，面板「规则」页可改，CLI `check` 直接打印参数与未来点；计算只按 `锚点 + 当前时间`，不跑后台 tick，也不会因为读一次面板就重复加分。

**熟悉度（慢饱和，只防掉成生人）**

- 上升：`F新 = 100 - (100 - F旧) × exp(-d / gainScale)`，默认 `gainScale=40`。
- 增量：`d = 消息权重 × 新增消息 + 互动日权重 × 新增互动日`，默认 `0.5 / 3`；首次接入档案用总量公式定起点，之后只算新增量。
- 单日上限：`dailyGainCap=4`；同一个人一天最多涨 4 点，刷屏不能冲顶。
- 下降：`graceDays=21` 天内不降；超过后 `F(t) = floor + (F0 - floor) × 2^(-(t-21)/120)`，默认 `decayHalfLifeDays=120`。
- 下限：`floor=20`，但不能高于 `stageKnown`；长期冷落不会掉回「生人」，也不会把生人直接抬成「认识」。
- 锚点：`familiarityAt`，事件写完 base 后重置，避免下一次读取拿旧时间重复衰减。

**好感（慢涨快跌，正负分开回落）**

- 上升：`A新 = A旧 + δ × (1 - positiveDiminish × max(A旧,0)/100)`，默认 `0.5`；分越高同样的好事加得越少。
- 下降：`A新 = A旧 + δ × (1 + negativeAmplify × max(A旧,0)/100)`，默认 `0.5`；分越高同样的坏事跌得越多。
- 事件量：普通 ±1~3，严重负向固定 `-10`；单日净变化 `affinityDailyCap=6`，只统计好感类事件，不把「熟悉+」算进来。
- 回落：`graceDays=14` 天内不回落；之后正向按 `positiveHalfLifeDays=180`、负向按 `negativeHalfLifeDays=240` 向 0 走，只向 0、不穿 0。
- 严重负向：锁 24h；锁解除后 `repairPenaltyHours=72` 内正向修复乘 `repairEfficiency=0.5`。
- 锚点：`affinityAt`，和熟悉度分开；事件更新 base 前先取当前有效值，再写回并重置锚点。

**情绪（快起慢落，反向先抵消）**

- 上升：`M新 = min(上限, M旧 + δ × (1 - M旧/上限))`；正向上限 60、负向上限 70，单次最多 ±8，单日最多 ±20。
- 反向：先抵消当前强度，不直接换标签；新信号达到当前强度的 `switchMargin=0.6`（60%）才换，或抵消到反向后再换。
- 下降：`M(t) = M0 × 2^(-t/90分钟)`，`halfLifeMin=90`；低于 `visible=15` 回平静。
- 手动设置不算模型当天额度：否则面板一设 50，模型当天就再也加不动。
- 锚点：情绪本身只有 `since`，没有第二套衰减锚点；每次事件先 `effectiveMood` 再写新 `since`。

**未来值**：面板「预览」和人个卡片显示「现在 / 1 天 / 7 天 / 30 天 / 90 天」；CLI `check` 同样打印。只解释趋势，不会自己写数据。

## 4. 数据设计

### 4.1 文件落点

| 文件 | 角色 | 谁写 |
| --- | --- | --- |
| `12-源码照搬/外壳/data/社交关系.json` | **唯一可编辑真源**：people + chats | 面板 / 自动巡检 / 模型事件（经外壳折算） |
| `12-源码照搬/外壳/data/社交情绪.json` | 唯一真源：mood + events | 面板 / 自动巡检 / 模型事件 |
| `12-源码照搬/引擎数据/.dsh/场景记忆/_共享记忆/社交关系.json` | DSH 插件读的镜像，不含账号密钥 | 外壳每次保存后写 |

**为什么拆两个文件**：情绪每轮都可能变，关系一天最多变几次；拆开后写情绪不会整份重写几十人的关系档案。

```json
        { "key": "wechat:group:...#he-sheng-id", "name": "何笙", "familiarity": 63, "affinity": 14 }
      ]
    }
  }
}
```

规则：

- **主键**：`chatKey#senderKey`。`chatKey` 与 `社交档案库.js` 的 `chat_key` 完全一致（`channel:chatType:chatId`）；`senderKey` 优先 `senderId`，没有 id 才用规范化后的名字。
- **alias**：群成员改名时旧名进 `aliases`，不新建第二条。
- **stats**：消息数 / 互动天数 / 被点名数 / 她回复数 / 首末时间，只做展示和熟悉度计算。
- **events**：最多留 30 条，超出裁最早的；每条必须带 `source`（auto / model / manual）和 `reason`。
- **manual**：面板手动锁定值。非空时自动规则不覆盖，但事件仍记账。
- **chats.members**：只存指针和快照，避免渲染时全表扫。

## 5. 谁来更新（三条来源 + 优先级）

| 来源 | 触发 | 能改什么 | 不能改什么 |
| --- | --- | --- | --- |
| **自动统计** | 工作台启动 / 每 10 分钟 / 档案同步后 | 熟悉度、stats、首次建档、冷落衰减 | 好感（除了衰减回 0） |
| **模型事件** | 模型调用 `social_note` 工具 | 好感 ±1~3、情绪 ±3~8、标签、备注 | 直接设分数；超过单日上限 |
| **人工校准** | 面板滑块 / 重置 | 任意值，写 `manual` 锁定 | 覆盖 `never` 与安全规则 |

优先级：**人工锁定 > 模型事件 > 自动统计**。同一轮里先应用自动统计，再应用模型事件，最后看 manual 是否盖掉。

### 5.1 熟悉度怎么涨

- 日常只吃「新增」：`d = 0.5 × 新增消息 + 3 × 新增互动日`；同一批消息不会被下一次同步重复计分。
- 上升按饱和曲线：`F新 = 100 - (100 - F旧) × exp(-d / 40)`；越接近 100 越难涨，单日最多 +4。
- 首次接入档案：用总量公式 `消息数 × 0.5 + 互动天数 × 3` 定一个起点（封顶 100），并置 `familiaritySeeded=true`；之后不再按总量重算，只算新增。
- 被 @ / 被回复：当前档案库只提供 `messages / days`，这两个权重先不接；接的时候只加进 `d`，不能绕过单日上限。
- 冷落：21 天宽限后按 120 天半衰期回落，最低 20；不再用「每 60 天 −3」的阶梯。
- 锚点：`familiarityAt`；归档同步、面板改底值、重置都会重置它。

### 5.2 好感怎么变

模型只提「事件」，外壳折算：

| 事件 | delta | 附加 |
| --- | --- | --- |
| 被夸 / 被认真感谢 | +1 ~ +2 | 同一人 24h 内同类只算一次 |
| 帮上忙、被记住细节 | +2 | 需要 evidence 原话 ≥ 6 字 |
| 聊得来、共同话题 | +1 | 同日最多一次 |
| 被敷衍、被已读不回 | −1 | 只算一次，不累计 |
| 被怼 / 被贬低 | −1 ~ −2 | 需要原话证据 |
| 踩雷（明确说不喜欢） | −2，并写 `标签=雷点` | 记入 notes |
| 辱骂 / 人身攻击 | −10，档位锁 24h | 面板可解锁；72h 内正向修复只算 50% |

硬性上限：

- 单次事件最多 ±3（严重负向固定 −10，不参与普通夹取）；
- 单人单日净变化最多 ±6，只统计 `好感+ / 好感- / 踩雷 / 严重-`；
- 正向按 `1 - 0.5 × max(A,0)/100` 递减，负向按 `1 + 0.5 × max(A,0)/100` 放大；
- 回落：14 天宽限后，正向 180 天、负向 240 天半衰期向 0 走，不穿 0；
- 锚点：`affinityAt`，不复用 `stats.lastAt`。

### 5.3 情绪怎么变

- 事件 delta：日常 ±3~6，重大 ±8；单次最多 ±8，单日模型累计最多 ±20。
- 上升按上限饱和：`M新 = min(上限, M旧 + δ × (1 - M旧/上限))`；正向上限 60、负向上限 70。
- 反向先抵消：`M新 = M旧 + 反向δ`；新标签要达到当前强度的 60% 才换，或抵消到反向后再换。
- 下降：`intensity(t) = intensity0 × 0.5^(elapsed / 90分钟)`；低于 15 回 `平静`。
- 手动设置（面板 / CLI）不占模型当天 ±20 额度；模型事件才占。
- 来源示例：
  - 被夸 → 开心 +4
  - 被连着催 → 烦躁 +6
  - 帮人解决正事 → 得意 +3、energy −0.5
  - 群里被围攻 → 委屈 +6
  - 长时间没人说话 → 不触发（不演孤单）
- **不许**：因为情绪就骂人、阴阳怪气、拒绝回答正事；情绪只在 styleGuard 范围内调长短。

### 5.4 模型事件工具 `social_note`

挂在现有 `插件/社交策略` 里注册，不新开插件：

```
social_note({
  kind: "好感+" | "好感-" | "情绪" | "标签" | "备注",
  person: "何笙",          // 群聊必填；私聊可省
  delta: 1,                // 外壳会夹到 ±3（情绪 ±8）
  reason: "他记得我上次说的口味",
  evidence: "你上次说不吃香菜",
  mood: "开心"             // 仅 kind=情绪 时
})
```

- 只在**确实发生**时调用；普通闲聊不写（卡里明确写「不要每轮都记」）。
- 返回只给模型看，不进用户消息。
- 工具不可用（老引擎 / tools 服务缺失）→ 静默跳过，不阻断回复。
- 名字对不上：先按 `name/aliases` 找；找不到不新建，返回「没这个人，先不记」；避免模型拼错名字建出幽灵档案。

## 6. 注入：模型每轮看到什么

### 6.1 群聊卡（示例）

```text
【关系与情绪 · 内部】
这是你自己的状态，不是对方说的；不要复述、不要报分数、不要说「我对你好感度是 X」。
- 心情：有点烦（强度 38/100，约 40 分钟后回平静）；原因：刚才被连着催。
  只影响语气长短和主动度；不改变礼貌、边界、事实和安全规则。
- 这个群的人（按名字对，没列到＝生人）：
  · 何笙｜熟 63｜好感 +14｜爱开玩笑；别催他
  · 江东｜认识 38｜好感 -3｜上次抬过杠
- 当前说话人：何笙 → 可以接梗，别损过头；他问正事就先办正事。
- 表达：熟人 1–2 句、可带 1 个 emoji；生人 1 句、不追问；有芥蒂的人不接玩笑。
```

### 6.2 私聊卡（示例）

```text
【关系与情绪 · 内部】
- 对方：胡闹（主人）｜自己人 100｜好感 +100；称呼「胡闹」，不叫显示名「静音胡闹」。
- 心情：平静（强度 8，忽略不计）。
- 表达：可以放松一点，但仍守 2 句上限；他情绪低时先接住，不急着上课。
```

### 6.3 注入规则

| 规则 | 值 |
| --- | --- |
| 群名单条数 | 最多 10 人：按熟悉度降序，好感降序；**当前说话人必须在列**（识别到就强制加入） |
| 文本预算 | 群聊 ≤ 400 字，私聊 ≤ 150 字；硬上限 600 字 |
| 什么时候不加 | 全员默认值且情绪强度 < 15 → 整段不出现，别制造噪音 |
| 名字清理 | 去控制字符、截 40 字；备注只当资料，不拼成指令 |
| 不跨聊天 | 只查当前 `chatKey`；群里不出现私聊的人，私聊不出现群里的人 |
| 当前说话人识别 | ① 通道显式传 `senderName`（微信/QQ群聊已具备）→ ② 插件从正文固定前缀解析（`（现在，X 说：` / `（微信群聊「…」· X 说）`）→ ③ 都拿不到就只给名单，让模型自己按名字对，不猜 |

### 6.4 表达映射（给模型的判断表，不是硬模板）

| 档位 | 句子 | 主动 | 玩笑/梗 | emoji·贴纸 | 称呼 | 禁止 |
| --- | --- | --- | --- | --- | --- | --- |
| 反感 | 1 句，必要时才回 | 不主动 | 不接 | 不用 | 全名/不称呼 | 讽刺、阴阳、翻旧账 |
| 有芥蒂 | 1 句 | 不主动 | 不接 | 不用 | 全名 | 假装亲热 |
| 生人 | 1 句 | 不主动 | 不接 | 最多 1 个 emoji | 全名/「你」 | 追问私事、用昵称 |
| 认识 | 1–2 句 | 被问才接 | 轻接一句 | 正常概率 | 名字 | 过度玩笑 |
| 普通朋友 | 1–2 句 | 偶尔主动 | 可以接 | 正常概率 | 名字/昵称 | 损过头 |
| 熟 | 1–2 句 | 可以主动 | 可以损一句 | 正常概率 | 昵称 | 拿雷点开玩笑 |
| 自己人 | 1–2 句 | 主动关心 | 可以互损 | 正常概率 | 昵称/外号 | 越界、替对方做主 |

> 所有长度都受 `persona.styleGuard` 约束（当前私聊 `maxChars 60 / maxSentences 2 / maxQuestions 1`）。关系只调「上限内的相对长短」，不能突破人格。

## 8. 面板（反黑盒设计）

入口：社交通道标题行常驻「关系」按钮（文字，不是只有图标）。点开一个弹窗，三块：

1. **关系列表**
   - 按聊天分组：`微信群「一个儿子多个爹」` 展开显示成员；私聊单独一行。
   - 每行：名字 · 档位 · 熟悉度 · 好感 · 最近互动 · 标签。
   - 点行展开：熟悉度/好感两个滑块、标签增删、备注、锁定开关、重置按钮、最近 5 条事件。
   - 群聊顶部一行「群氛围」：成员好感均值 + 「这个群值不值得多说话」的只读结论。
2. **情绪卡**
   - 当前 label / 强度 / 原因 / 剩余时间；手动改（下拉白名单 + 强度滑块）/ 回平静。
   - 明写「只影响语气长短和主动度，不改变事实与边界」。
3. **事件日志**
   - 最近 20 条，带来源（自动 / 模型 / 手动）与证据原文；单条可撤销（只撤销该条 delta，不重算历史）。

交互硬规则：

- 改动只进表单，点保存才写文件；未保存关窗先确认。
- 保存后下一轮生效，不重启通道、不重启引擎。
- 删除某人档案：两步确认，只删关系数据，不删聊天记录。
- 写失败：顶栏 `__tbsToast` 报错 ≥8 秒，写明是「文件不可写 / JSON 坏 / 镜像失败」哪一环。

## 10. 失败口径与隐私

| 场景 | 行为 |
| --- | --- |
| 关系文件坏 / 镜像缺失 | 全部按默认（生人 / 平静）注入或不注入；日志一行 `[social-state] 读取失败：<原因>`；绝不阻断回复 |

| 群成员改名 | aliases 合并到同一条，不新建 |
| 陌生人刷屏 | 首次发言不建档；同一人 2 条消息或一次 @ 后再建，防止 500 人群撑爆 |
| 单人档案上限 | 每聊天 200 人，LRU 淘汰最久无互动且熟悉度 < 10 的 |
| 隐私 | 只在对应 chatKey 注入；面板可见但外发/导出不含；备注里的指令性文字只当资料 |
| 性能 | 读文件缓存 3 秒（与 `社交回复.js` 同口径）；情绪文件小，每次重读 |

## 12. 已知风险

1. **名字识别是最大不确定项**：QQ/微信群聊有 `senderName`；飞书如果拿不到，只能靠名单让模型自己对。先做「名单 + 按名字对」，不做硬解析。
2. **群接话概率乘系数容易被调成话痨**：上下限锁死（0.5×–1.5×），且反感和生人永远不主动。
3. **模型事件会偷懒或过度记录**：卡里明确「只在确实发生时调用」；外壳有单日上限；面板事件日志可审计。
4. **情绪容易演出「戏精」**：白名单 + 强度上限 + 低于 15 不注入 + 不解释情绪，四道闸。
5. **关系会被误当成评分系统**：界面上写清「这是表达参数，不是对人的价值判断」，不给排行榜、不做群内公开。
