# 社交好感度与情绪 · 设计（2026-11-20）

> **这篇是什么**：给「群聊里每个人都被同样对待」这个问题做的机制设计，不是施工记录。
> 现状核对：**没有好感度，也没有独立情绪状态**。下面第 1 节列证据。
> 落地位置：`08-`（改造清单）；P0 跑通、自检过了再考虑升进 `00-核心机制/七-关系与情绪.md`。

## 1. 现状：两样都没有

| 你以为有的 | 实际是什么 | 证据 |
| --- | --- | --- |
| 对每个人的好感度 | 没有。群成员只有名字出现在旁听记录/群成员名单里，模型对谁都是一个态度 | `外壳/社交.js:94-144`（消息流只带正文）；`微信通道.js:3305-3312`（只拼群成员名单）；`QQ群聊.js:421-457`（旁听记录只有「昵称：内容」） |
| 她自己的情绪 | 没有持久状态。只有静态人格文本里一句「先接住情绪」+ 表情包分类名 | `外壳/pet/设置.默认.json:2-24`（identity / personality / speech / reactions / care / never，全是常量）；`外壳/社交回复.js:97-138`（tone / emoji / sticker / group，全局一套） |
| 记忆里的关系 | 没有。人格记忆只有「记忆 / 对话 / 待办」三类，不记关系 | `工具/人格记忆.mjs:123-139` |
| 搜索到的「情绪」 | 全是表情包分类名和选股器的市场情绪，不是人格情绪 | `外壳/QQ能力.js:265-337`、`renderer/renderers.js:12400+` |

**结论**：现在所有聊天共用「一个静态人格 + 一套全局回复策略」。同一句话，张三说和李四说，回复只会在上下文上不同，不会在**态度**上不同。这不是模型不够聪明，是提示词里根本没有「张三和李四不一样」这个信息。

## 2. 目标与边界

### 2.1 目标

1. 群里每个人一条独立的关系档案：熟不熟、好感多少、有什么标签/雷点。
2. 她自己有一份会衰减的短期情绪，不再永远「平静且礼貌」。
3. 两者都只影响**表达**：句子长短、主动程度、玩笑尺度、称呼、emoji/贴纸、接话概率。
4. 每一条变化都能追溯到证据（哪句话、哪次互动），不凭感觉打分。
5. 默认保守：生人不会自来熟，熟人不会突然变冷，一句话不能跨档。

### 2.2 明确不做

| 不做 | 原因 |
| --- | --- |
| 用好感度决定「回不回」 | 会变成势利眼；被 @、被直接问仍然必须回 |
| 让模型直接写分数 | 一句「夸你」就能刷满级；模型只提事件，外壳限量折算 |
| 把好感度发给对方 / 写进群消息 | 这是内部状态，不是社交货币 |
| 跨聊天共享好感 | 私聊 A 的好感不能出现在群 B；群 C 的印象不能带进群 D |
| 用好感度覆盖人格底线 | `never`、外发闸门、安全规则优先级永远更高 |
| 上情感识别模型 | 成本高、误判多；先做事件级，够用 |

## 3. 双层模型：关系是慢变量，情绪是快变量

这是整套设计的地基，先分清两件事：

| | 关系（对某个人） | 情绪（她自己） |
| --- | --- | --- |
| 管什么 | 我对**这个人**的态度 | 我**此刻**的状态 |
| 变化速度 | 慢：按天/周累积，衰减以 30 天计 | 快：按分钟/小时，半衰期约 90 分钟 |
| 存哪 | `社交关系.json` 的 `people` | `社交情绪.json` 的 `mood` |
| 例子 | 何笙：熟 63 / 好感 +14 | 现在有点烦，强度 38，约 40 分钟后回平静 |
| 会不会互相影响 | 会，但只做小幅调制：心情差时对熟人也不会热情，但不会因此讨厌他 | 不会因为讨厌某个人就长期低落 |

**为什么必须分开**：合成一个「心情值」会出现「被张三怼了 → 对李四也冷」的串味；分开后，情绪是全局的，好感是按人的，互不污染。

### 3.1 关系的两个轴

不要只用一个「好感分」。人跟人之间至少有两个维度：

| 轴 | 范围 | 来源 | 决定什么 |
| --- | --- | --- | --- |
| **熟悉度** familiarity | 0–100 | 互动量、互动天数、被点名次数、她回复次数 | 多主动、能不能用昵称、能不能开玩笑、要不要解释背景 |
| **好感** affinity | -100–+100 | 事件：被夸、被感谢、被怼、被敷衍、踩雷、共同话题 | 多耐心、多热络、玩笑开多深、愿不愿意多聊一句 |

两个轴组合出档位（带 5 分滞回，防止一句话跨档）：

| 档位 | 判定 | 一句话态度 |
| --- | --- | --- |
| 反感 | 好感 ≤ -30 | 只回必要信息，不主动，不接梗 |
| 有芥蒂 | -29 ~ -1 | 礼貌但短，避免玩笑，不主动找话 |
| 生人 | 好感 ≥ 0 且 熟悉 < 20 | 客气、短、不追问、不用昵称 |
| 认识 | 熟悉 20–39 | 正常礼貌，可以接一句话题 |
| 普通朋友 | 熟悉 40–59 | 能接梗，偶尔主动，可带 1 个 emoji |
| 熟 | 熟悉 60–79 且 好感 ≥ 10 | 放松，可损一句，可用昵称，贴纸正常概率 |
| 自己人 | 熟悉 ≥ 80 且 好感 ≥ 30 | 护短、主动关心、记得细节 |

> 好感高但刚认识（例如一见如故）→ 最多到「普通朋友」，不能直接「自己人」：没有共同经历，自来熟会假。
> 熟悉高但好感负 → 降一档：熟人抬杠可以，但不能一边熟一边冷。

### 3.2 情绪的状态

情绪不是「开心/难过」二选一，而是一条带强度、原因、半衰期的状态：

| 字段 | 说明 |
| --- | --- |
| `label` | 白名单：平静 / 开心 / 兴奋 / 得意 / 低落 / 委屈 / 烦躁 / 疲惫 / 心虚 |
| `intensity` | 0–100；低于 15 不写进提示词，等于没有情绪 |
| `valence` | -1 ~ +1，正负倾向 |
| `energy` | 0–1，精神头；决定主动接话、句子长短 |
| `cause` | 一句人话原因：「刚才被连着催了两次」 |
| `halfLife` | 默认 90 分钟；重大事件最多 6 小时 |
| `until` | 衰减到 10 以下、回平静的时间 |

**基线由人格派生**：`personality` 是「慢热、话淡、不演」，所以默认 `平静`，正向强度上限 60、负向上限 70；不做大起大落，不演委屈，不拿情绪当借口。

**情绪只调旋钮，不改内容**：

| 旋钮 | 情绪怎么影响 |
| --- | --- |
| 句子数 | 烦躁/疲惫 → 压到 1 句；开心 → 允许到 2 句（仍受 `styleGuard` 上限约束） |
| emoji 概率 | 乘 `1 + valence × 0.5`，夹在 0–1 |
| 贴纸概率 | 低落 / 烦躁 / 疲惫 → 0；开心 / 得意 → 保持原概率 |
| 群接话概率 | energy 高 ×1.2，低 ×0.8，烦躁 ×0.7；反感和生人仍然不主动 |
| 称呼 | 情绪不改变称呼；称呼只由熟悉度决定 |

## 4. 数据设计

### 4.1 文件落点

| 文件 | 角色 | 谁写 |
| --- | --- | --- |
| `12-源码照搬/外壳/data/社交关系.json` | **唯一可编辑真源**：people + chats | 面板 / 自动巡检 / 模型事件（经外壳折算） |
| `12-源码照搬/外壳/data/社交情绪.json` | 唯一真源：mood + events | 面板 / 自动巡检 / 模型事件 |
| `12-源码照搬/引擎数据/.dsh/场景记忆/_共享记忆/社交关系.json` | DSH 插件读的镜像，不含账号密钥 | 外壳每次保存后写 |
| `12-源码照搬/引擎数据/.dsh/场景记忆/_共享记忆/社交情绪.json` | 同上 | 同上 |

**为什么拆两个文件**：情绪每轮都可能变，关系一天最多变几次；拆开后写情绪不会整份重写几十人的关系档案。

### 4.2 `社交关系.json` 结构

```json
{
  "version": 1,
  "updatedAt": 0,
  "defaults": {
    "privateAffinity": 5,
    "groupAffinity": 0,
    "privateFamiliarity": 15,
    "groupFamiliarity": 5,
    "affinityDecayDays": 30,
    "affinityDecayStep": 2,
    "familiarityDecayDays": 60,
    "familiarityDecayStep": 3,
    "familiarityFloor": 10
  },
  "people": {
    "wechat:group:43525978777@chatroom#he-sheng-id": {
      "channel": "wechat",
      "chatType": "group",
      "chatId": "43525978777@chatroom",
      "senderId": "he-sheng-id",
      "name": "何笙",
      "aliases": ["何笙", "笙哥"],
      "familiarity": 63,
      "affinity": 14,
      "manual": { "familiarity": null, "affinity": null },
      "tags": ["爱开玩笑", "夜猫子"],
      "notes": [
        { "at": 0, "kind": "雷点", "text": "别催他，越催越不回", "source": "manual" }
      ],
      "stats": {
        "messages": 41, "days": 6, "mentions": 3, "replies": 12,
        "firstAt": 0, "lastAt": 0
      },
      "events": [
        { "at": 0, "kind": "好感+", "delta": 2, "reason": "他记得我上次说的口味", "source": "model" }
      ]
    }
  },
  "chats": {
    "wechat:group:43525978777@chatroom": {
      "rosterUpdatedAt": 0,
      "members": [
        { "key": "wechat:group:...#he-sheng-id", "name": "何笙", "familiarity": 63, "affinity": 14 }
      ]
    }
  }
}
```

规则：

- **主键**：`chatKey#senderKey`。`chatKey` 与 `社交档案库.js` 的 `chat_key` 完全一致（`channel:chatType:chatId`）；`senderKey` 优先 `senderId`，没有 id 才用规范化后的名字。
- **alias**：群成员改名时旧名进 `aliases`，不新建第二条。
- **stats**：消息数 / 互动天数 / 被点名数 / 她回复数 / 首末时间，只做展示和熟悉度计算。
- **events**：最多留 30 条，超出裁最早的；每条必须带 `source`（auto / model / manual）和 `reason`。
- **manual**：面板手动锁定值。非空时自动规则不覆盖，但事件仍记账。
- **chats.members**：只存指针和快照，避免渲染时全表扫。

### 4.3 `社交情绪.json` 结构

```json
{
  "version": 1,
  "updatedAt": 0,
  "mood": {
    "label": "平静",
    "intensity": 0,
    "valence": 0,
    "energy": 0.35,
    "cause": "",
    "source": "",
    "since": 0,
    "until": 0,
    "halfLife": 90
  },
  "events": [
    { "at": 0, "label": "烦躁", "delta": 6, "cause": "被连着催了两次", "source": "model", "chatKey": "qq:group:123" }
  ],
  "perChat": {}
}
```

`perChat` 是 P2 可选：只记「在这个聊天里的余味」，最多 3 条，30 分钟衰减；不写就不启用。

## 5. 谁来更新（三条来源 + 优先级）

| 来源 | 触发 | 能改什么 | 不能改什么 |
| --- | --- | --- | --- |
| **自动统计** | 工作台启动 / 每 10 分钟 / 档案同步后 | 熟悉度、stats、首次建档、冷落衰减 | 好感（除了衰减回 0） |
| **模型事件** | 模型调用 `social_note` 工具 | 好感 ±1~3、情绪 ±3~8、标签、备注 | 直接设分数；超过单日上限 |
| **人工校准** | 面板滑块 / 重置 | 任意值，写 `manual` 锁定 | 覆盖 `never` 与安全规则 |

优先级：**人工锁定 > 模型事件 > 自动统计**。同一轮里先应用自动统计，再应用模型事件，最后看 manual 是否盖掉。

### 5.1 熟悉度怎么涨

- 每发一条消息：+0.5，单人单日最多 +3。
- 每有一个新的互动日：+2，单周最多 +10。
- 被点名 / @：+1，单日最多 +3。
- 她成功回了一句：+0.5，单日最多 +3。
- 首次建档：`min(40, 消息数 × 0.5 + 互动天数 × 3)`，所以老群友一上来就是「普通朋友/熟」，不用从零养。
- 冷落衰减：60 天无互动 −3，最低 10（认识过的人不会完全变陌生人）。

### 5.2 好感怎么变

模型只提「事件」，外壳折算：

| 事件 | delta | 附加 |
| --- | --- | --- |
| 被夸 / 被认真感谢 | +1 ~ +2 | 同一人 24h 内同类只算一次 |
| 帮上忙、被记住细节 | +2 | 需要 evidence 原话 ≥ 6 字 |
| 聊得来、共同话题 | +1 | 同日最多一次 |
| 被敷衍、被已读不回 | −1 | 只算一次，不累计 |
| 被怼 / 被贬低 | −1 ~ −2 | 需要原话证据 |
| 踩雷（明确说不喜欢） | −2，并写 `标签=雷点` | 记入 notes |
| 辱骂 / 人身攻击 | −10，档位锁 24h | 面板可解锁；道歉不能立刻回满 |

硬性上限：

- 单次事件最多 ±3；
- 单人单日净变化最多 ±6；
- 单人每小时最多应用 1 个好感事件；
- 衰减：30 天无互动，向 0 移动 2 点（正负都向中间收），不穿 0。

### 5.3 情绪怎么变

- 事件 delta：日常 ±3~6，重大 ±8；单日累计最多 ±20。
- 新事件来了怎么合并：`intensity = clamp(旧强度 + delta, 0, 100)`；只有新事件强度 > 当前，或当前 < 15 时才换 label，防止来回跳。
- 衰减：`intensity(t) = intensity0 × 0.5^(elapsed / halfLife)`；低于 10 回 `平静`。
- 来源示例：
  - 被夸 → 开心 +4
  - 被连着催 → 烦躁 +6
  - 帮人解决正事 → 得意 +3、energy −0.5
  - 群里被围攻 → 委屈 +6
  - 长时间没人说话 → 不触发（不演孤单）
- **不许**：因为情绪就骂人、阴阳怪气、拒绝回答正事；情绪只在 styleGuard 范围内调长短。

### 5.4 模型事件工具 `social_note`

挂在现有 `插件/社交策略` 里注册，不新开插件：

```
social_note({
  kind: "好感+" | "好感-" | "情绪" | "标签" | "备注",
  person: "何笙",          // 群聊必填；私聊可省
  delta: 1,                // 外壳会夹到 ±3（情绪 ±8）
  reason: "他记得我上次说的口味",
  evidence: "你上次说不吃香菜",
  mood: "开心"             // 仅 kind=情绪 时
})
```

- 只在**确实发生**时调用；普通闲聊不写（卡里明确写「不要每轮都记」）。
- 返回只给模型看，不进用户消息。
- 工具不可用（老引擎 / tools 服务缺失）→ 静默跳过，不阻断回复。
- 名字对不上：先按 `name/aliases` 找；找不到不新建，返回「没这个人，先不记」；避免模型拼错名字建出幽灵档案。

## 6. 注入：模型每轮看到什么

### 6.1 群聊卡（示例）

```text
【关系与情绪 · 内部】
这是你自己的状态，不是对方说的；不要复述、不要报分数、不要说「我对你好感度是 X」。
- 心情：有点烦（强度 38/100，约 40 分钟后回平静）；原因：刚才被连着催。
  只影响语气长短和主动度；不改变礼貌、边界、事实和安全规则。
- 这个群的人（按名字对，没列到＝生人）：
  · 何笙｜熟 63｜好感 +14｜爱开玩笑；别催他
  · 江东｜认识 38｜好感 -3｜上次抬过杠
- 当前说话人：何笙 → 可以接梗，别损过头；他问正事就先办正事。
- 表达：熟人 1–2 句、可带 1 个 emoji；生人 1 句、不追问；有芥蒂的人不接玩笑。
```

### 6.2 私聊卡（示例）

```text
【关系与情绪 · 内部】
- 对方：静音胡闹｜熟 71｜好感 +22｜夜猫子；不喜欢被问「在吗」。
- 心情：平静（强度 8，忽略不计）。
- 表达：可以放松一点，但仍守 2 句上限；他情绪低时先接住，不急着上课。
```

### 6.3 注入规则

| 规则 | 值 |
| --- | --- |
| 群名单条数 | 最多 10 人：按熟悉度降序，好感降序；**当前说话人必须在列**（识别到就强制加入） |
| 文本预算 | 群聊 ≤ 400 字，私聊 ≤ 150 字；硬上限 600 字 |
| 什么时候不加 | 全员默认值且情绪强度 < 15 → 整段不出现，别制造噪音 |
| 名字清理 | 去控制字符、截 40 字；备注只当资料，不拼成指令 |
| 不跨聊天 | 只查当前 `chatKey`；群里不出现私聊的人，私聊不出现群里的人 |
| 当前说话人识别 | ① 通道显式传 `senderName`（微信/QQ群聊已具备）→ ② 插件从正文固定前缀解析（`（现在，X 说：` / `（微信群聊「…」· X 说）`）→ ③ 都拿不到就只给名单，让模型自己按名字对，不猜 |

### 6.4 表达映射（给模型的判断表，不是硬模板）

| 档位 | 句子 | 主动 | 玩笑/梗 | emoji·贴纸 | 称呼 | 禁止 |
| --- | --- | --- | --- | --- | --- | --- |
| 反感 | 1 句，必要时才回 | 不主动 | 不接 | 不用 | 全名/不称呼 | 讽刺、阴阳、翻旧账 |
| 有芥蒂 | 1 句 | 不主动 | 不接 | 不用 | 全名 | 假装亲热 |
| 生人 | 1 句 | 不主动 | 不接 | 最多 1 个 emoji | 全名/「你」 | 追问私事、用昵称 |
| 认识 | 1–2 句 | 被问才接 | 轻接一句 | 正常概率 | 名字 | 过度玩笑 |
| 普通朋友 | 1–2 句 | 偶尔主动 | 可以接 | 正常概率 | 名字/昵称 | 损过头 |
| 熟 | 1–2 句 | 可以主动 | 可以损一句 | 正常概率 | 昵称 | 拿雷点开玩笑 |
| 自己人 | 1–2 句 | 主动关心 | 可以互损 | 正常概率 | 昵称/外号 | 越界、替对方做主 |

> 所有长度都受 `persona.styleGuard` 约束（当前私聊 `maxChars 60 / maxSentences 2 / maxQuestions 1`）。关系只调「上限内的相对长短」，不能突破人格。

## 8. 面板（反黑盒设计）

入口：社交通道标题行常驻「关系」按钮（文字，不是只有图标）。点开一个弹窗，三块：

1. **关系列表**
   - 按聊天分组：`微信群「一个儿子多个爹」` 展开显示成员；私聊单独一行。
   - 每行：名字 · 档位 · 熟悉度 · 好感 · 最近互动 · 标签。
   - 点行展开：熟悉度/好感两个滑块、标签增删、备注、锁定开关、重置按钮、最近 5 条事件。
   - 群聊顶部一行「群氛围」：成员好感均值 + 「这个群值不值得多说话」的只读结论。
2. **情绪卡**
   - 当前 label / 强度 / 原因 / 剩余时间；手动改（下拉白名单 + 强度滑块）/ 回平静。
   - 明写「只影响语气长短和主动度，不改变事实与边界」。
3. **事件日志**
   - 最近 20 条，带来源（自动 / 模型 / 手动）与证据原文；单条可撤销（只撤销该条 delta，不重算历史）。

交互硬规则：

- 改动只进表单，点保存才写文件；未保存关窗先确认。
- 保存后下一轮生效，不重启通道、不重启引擎。
- 删除某人档案：两步确认，只删关系数据，不删聊天记录。
- 写失败：顶栏 `__tbsToast` 报错 ≥8 秒，写明是「文件不可写 / JSON 坏 / 镜像失败」哪一环。

## 9. 分期落地

| 期 | 内容 | 完成判据 | 依赖 |
| --- | --- | --- | --- |
| **P0** 静态差异 | 数据结构 + `relationFragment` + 面板手改 + 从档案建档 + 注入三通道 | 同群两个成员手动设不同档位，回复长度/称呼/主动度明显不同 | 无 |
| **P1** 自动熟悉度 | 统计增量、首次建档、冷落衰减、群接话权重 | 老群友建档后直接是「普通朋友/熟」；连续 3 天互动涨档；60 天不动降档 | P0 |
| **P2** 情绪 | 情绪状态 + 衰减 + 卡里一行 + 面板情绪卡 + `social_note` | 被连续催后回复变短；40 分钟后自动回平静；面板能看到原因 | P1 |
| **P3** 细化 | 每聊天余味、主动话题（只对熟人）、关系标签自动学习、群氛围对「接不接」的影响 | 不出现「对所有人都一样」的抽样对比 | P2 |

建议先做 **P0 + P1**：这两期就能解决「群里所有人一个态度」的主诉，且不依赖模型工具，风险最低。P2 再上情绪，避免一次改太多、坏了分不清是哪层。

## 10. 失败口径与隐私

| 场景 | 行为 |
| --- | --- |
| 关系文件坏 / 镜像缺失 | 全部按默认（生人 / 平静）注入或不注入；日志一行 `[social-state] 读取失败：<原因>`；绝不阻断回复 |
| 插件读不到外壳模块 | 只读镜像；镜像也没有 → 不加关系段，不猜 |
| 同一群两个同名 | `senderId` 优先；没有 id 时按名字分开存，卡里标「（同名，按最近发言）」 |
| 群成员改名 | aliases 合并到同一条，不新建 |
| 陌生人刷屏 | 首次发言不建档；同一人 2 条消息或一次 @ 后再建，防止 500 人群撑爆 |
| 单人档案上限 | 每聊天 200 人，LRU 淘汰最久无互动且熟悉度 < 10 的 |
| 隐私 | 只在对应 chatKey 注入；面板可见但外发/导出不含；备注里的指令性文字只当资料 |
| 性能 | 读文件缓存 5 秒（与 `社交回复.js` 同口径）；情绪文件小，每次重读 |

## 11. 验收（每条都要能跑）

`node 12-源码照搬\工具\社交状态.mjs 自检` 至少 12 条：

1. 空文件 → 默认值，不报错。
2. 首次建档：41 条 / 6 天 → 熟悉度 ≈ 38–40。
3. 单次好感 +5 被夹到 +3。
4. 单日好感 +10 被夹到 +6。
5. 30 天无互动 → 好感向 0 移动 2。
6. 60 天无互动 → 熟悉度 −3，不低于 10。
7. 档位滞回：58 ↔ 62 不会来回跳。
8. 群名单只出现本 chatKey 的人。
9. 当前说话人不在前 10 也强制入列。
10. 情绪 38 → 90 分钟后 ≈ 19 → 再 90 分钟 < 10 回平静。
11. 情绪强度 8 → 卡里不出现情绪行。
12. 手动锁定好感 20 后，自动事件不改值，只记账。

面板三个用例：

- 正常：改何笙好感 14→30，保存，下一轮群里对他明显更热络。
- 边界：把好感拉到 -100，回复仍不骂人、正事仍回答。
- 异常：关系文件写坏，面板报错并显示「已按默认运行」，聊天不中断。

## 12. 已知风险

1. **名字识别是最大不确定项**：QQ/微信群聊有 `senderName`；飞书如果拿不到，只能靠名单让模型自己对。先做「名单 + 按名字对」，不做硬解析。
2. **群接话概率乘系数容易被调成话痨**：上下限锁死（0.5×–1.5×），且反感和生人永远不主动。
3. **模型事件会偷懒或过度记录**：卡里明确「只在确实发生时调用」；外壳有单日上限；面板事件日志可审计。
4. **情绪容易演出「戏精」**：白名单 + 强度上限 + 低于 15 不注入 + 不解释情绪，四道闸。
5. **关系会被误当成评分系统**：界面上写清「这是表达参数，不是对人的价值判断」，不给排行榜、不做群内公开。
