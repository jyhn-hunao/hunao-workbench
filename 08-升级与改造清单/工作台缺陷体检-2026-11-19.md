### P1-1 顶栏「快照 / 回滚」接的是已删除脚本，备份安全网整体失效

- **现象**：顶栏点「快照」或「回滚」必失败；`data\backups` 目录根本不存在，源码快照 0 个。
- **证据（已验证）**

  - 两个文件 `Test-Path` 均为 False，全仓递归也找不到；

- **影响**：用户以为有「改坏了可回滚」的安全网，实际一次快照都打不出来；目录契约里的「回滚会漏文件」检查也一起失效。

- **不算故障**：群聊 5 条 `not_addressed` / `addressed_to_other` 是 @ 判定，不是漏发；`engine-update-check` 退出 1 = 有新版本，是既定语义；`pet-runtime.proactive` 退出 1 = 当前不能主动，也是既定语义。

1. **正常**：双击 `启动.vbs` → 窗口可见、引擎 24.22.2 就绪、3083/31238 在跑；`测试` / `自检` / `sessions` / `发布前检查` 全过；微信私聊 3 轮收到并回复成功。

## 六、最易误用点

1. **把「自检全绿」当「守卫已生效」**：自检只查副本落位，不查 `bundles`。
2. **把「状态卡 0 条」当「通道没干活」**：计数重启即清零，真实收发在 `通道.log`。
3. **把「通道记忆显示未回」当「她没回」**：重复消息打断了配对，转录里其实有回复。
4. **以为顶栏快照能用**：脚本已被删，`data\backups` 不存在。
5. **在本会话 PowerShell 里直接 `node` 跑脚本**：PATH 是 22.23.2，机器配置才是 24.22.2。
6. **以为重启整壳就能升级引擎**：实际要点「立即更新」；且升完必须重跑建会话验证。
