## 二、缺陷清单

### P1-1 省 token 守卫静默失效，自检却报"已落位"

- **现象**：每次启动引擎打一条 `dsh: skipping profile bundle "dsh-token-guard": cannot resolve profile bundle`，守卫插件不加载；但 `自检` 说"私有插件落位 全部已落位"、`check-gui` 只说"当前是关的"。
- **证据（已验证）**
  - `12-源码照搬/引擎数据/.dsh/profiles/web/package.json` 的 `dsh.profile.bundles` 只有 base / web-app / dsh-im / onebot，**没有** `dsh-token-guard`；
  - `node_modules/dsh-token-guard` 仍是指向 `插件\省token守卫` 的 Junction（`--off` 本应删副本，`--on` 本应写 bundles，现在是第三种"半摘"状态）；
  - `server.log` 中该 skip 行 3 条；`storages/token-guard.jsonl` 最后一条是 **2026-11-12 16:44:29**，之后再无记录；
  - `自检.mjs` 的"私有插件落位"只判断 profile node_modules 里有没有副本，不判断 `bundles` 里有没有登记 → 假绿。
- **影响**：省 token（重复读 / 整读大文件拦截）能力实际不生效；每次启动多一条错误日志；换机器后同样误判。
- **修复（二选一，需重启整壳）**
  - 启用：`node 12-源码照搬\工具\守卫开关.mjs --on`（默认 shadow，只记不拦；要真拦加 `--mode enforce`）
  - 停用：`node 12-源码照搬\工具\守卫开关.mjs --off`（删副本，启动报错消失）
- **建议同时加固**：`自检` 的私有插件项加一条"是否在 `bundles` 里"，与 `check-gui` 口径一致。

### P2-1 面板注入的诊断链路失效（每次注入一条错误日志）

- **现象**：`renderers.js` 的 `injectFix` 每次执行都抛 `"undefined" is not valid JSON`，面板标题行的「精简 ✓ / 铺满 x列」不再刷新。
- **证据（已验证）**：`HARNESS_FIX_JS` 模板在 `renderers.js:15570` 开始、`:15666` 以 `return JSON.stringify(...)` 结束，但 `:15668` 又拼了 `${HARNESS_PIN_JS}`；`executeJavaScript` 返回最后一条语句的值，而 PIN_JS 是 `(() => {…})()`（`:15569`，无 return）→ 整体返回 `undefined` → `renderers.js:15680` 的 `JSON.parse(r)` 必抛。日志中该错误 **38 条**；另有 3 条 `GUEST_VIEW_MANAGER_CALL`。
- **影响**：诊断文字永远停在旧值/「等界面…」，引擎改版导致铺满失效时看不到提示；日志被错误刷屏。
- **修复**：把 `${HARNESS_PIN_JS}` 移到 IIFE 之前，或在 IIFE 末尾 `return window.__fixDiag || JSON.stringify({...})`，并让渲染层优先读 `window.__fixDiag`。

### P2-2 注入风暴：每个面板前 30 秒每 1.5 秒全量注入 + 全幅截图落盘

- **现象**：每次注入都 `capturePage()` 截整页并同步写 115 KB 的 `panel-latest.png`（主进程 `writeFileSync`），同时执行 CSS + 两段 JS + 900 字符诊断日志。
- **证据（已验证计数）**
  - `renderers.js:15781` 起 30 秒内每 1.5 秒 `mainInject() + injectFix()`（≈20 轮/面板），`:15788` 才清定时器；
  - `main.js:1427-1438` 每次注入截图并 `fs.writeFileSync`；多面板并发写**同一个** `panel-latest.png`（无锁，后写覆盖）；
  - 本份 `server.log`：11,883 行中 **10,244 行（86.2%）** 是 `[wv:inject] js 结果 / diag / 截图已保存`；累计注入 3,496 次、截图 3,192 次（56 次启动）。
- **影响**：切场景、开面板时主进程同步 I/O + IPC 图像传输造成卡顿；日志 3.3 MB/轮，诊断价值被淹没。
- **修复（建议）**：
  1. 截图改为调试开关（默认关）或只在首次注入拍一张；
  2. `[wv:inject] js 结果/diag` 只在失败或 `found=false` 时打；
  3. 1.5 秒轮询降为 `dom-ready` / `did-finish-load` + 2 次延时补投（现有 1.5s/4s 已能覆盖冷启动）；
  4. 截图文件名带 webContentsId，避免并发覆盖。

## 五、最易误用点

1. **把"自检全绿"当成"插件已生效"**——自检只查副本落位，不查 bundles（P1-1）。
2. **只删/只留 node_modules 副本**：留下副本但不在 bundles → 引擎每次报错且不加载；正确做法是 `守卫开关 --on/--off` 二选一。
3. **以为重启整壳就能升级引擎**——实际必须点「立即更新」（P2-7 的旧文案还在误导）。
4. **手改 `索引.json` / `记忆地图.json`**：下次 `索引 --all` 会覆盖；新增场景要跑工具并补 `areas\<场景>.md`。
5. **在本会话 PowerShell 里直接 `node` 跑脚本**：这里 PATH 的 node 是豆包沙箱 **22.23.2**，而机器配置 `nodeExe` 是 **24.22.2**（引擎要求 ≥24.9）。手工跑前先 `where node`，否则可能用 22 跑出假结果。
6. **把"决策 31 篇"当可修告警**：整理只搬 >180 天条目，而当前 0 篇超期，永远搬不动。
